## B33 · 手机端地图只能上下滑，不能左右/随意方向滑

### 根因（CSS 层，两半缺一不可）

`ui.js` 的 `mapHtml()` 把画布宽度**内联写死**成内容真实宽度：

```js
const W = b.w * MAP_CELL + MAP_PAD * 2;      // 窄屏一个 16 格区域 = 892px
h += '<div class="map-canvas" style="width:' + W + 'px;height:' + H + 'px">';
```

而 CSS 里 `.map-canvas` 原来只有：

```css
.map-canvas { … overflow: auto; max-height: 54vh; … touch-action: none; }
```

- **纵向**：画布高 892px 被 `max-height:54vh` 压到 ~430px，内容溢出，`scrollTop` 生效 → 滑得动 ✔
- **横向**：画布**自己**不溢出（宽 892px 就是 892px），横向那截溢出被**外层 `.map-wrap`
  （`max-height:60vh; overflow:auto`）**兜走了。于是：
  1. `bindMapPan` 只操作 `.map-canvas` 的 `scrollLeft`，而那个值被浏览器夹成 **0**（无溢出）→ 左/右/斜向都划不动；
  2. 手指落在画布上时 `touch-action:none` 把这一片手势整个禁掉，**外层 `.map-wrap` 也没法靠原生滚动横向走**。

⇒ 症状就是主人说的「只能上下滑动」。

### 修法

```css
/* max-width 与 max-height 必须成对出现 */
.map-canvas { … overflow: auto; max-width: 100%; max-height: 54vh; … }
```

画布被压到容器宽（手机约 343px），892px 的内容溢出**在画布内部**，`scrollLeft` 才有可动范围。
`bindMapPan` 本来就是**同时**改 `scrollLeft` 与 `scrollTop`（斜向平移），两端一通，上下/左右/斜着全通。

### 为什么以前测不出来

`smoke-mapui` 的假画布给了固定 `scrollWidth=2000 / clientWidth=375`，**横向永远"可滚"** ——
它验的是 JS 平移逻辑，验不到「真实 DOM 里到底有没有横向溢出」（那要排版引擎）。所以：
- 平移逻辑仍由 `smoke-mapui` 真点真拖验（B-4/B-5 改成**相对位移**断言）；
- 「有没有横向溢出」只能断 **CSS 契约**：`.map-canvas` 必须同时声明 `max-width` 与 `max-height`（`smoke-uiux` ⑩-2）。

### 断言 & 变异自证

| 断言 | 变异 | 结果 |
|---|---|---|
| `smoke-uiux` ⑩-2 `.map-canvas` 同时有 max-width/max-height | 摘掉 `max-width: 100%` | **红**（⑩-2） |
| `smoke-mapui` B-3b/B-4/B-5 开图即居中 + 拖动双轴相对位移 | — | 绿 |

## B34 · 地图上显示的附近位置与人物实际所在位置不符

三个独立成因，一起修。

### ① 斜向走廊**画不出连线**（也印英文方向名）

数据里 `exits` 用 `n/s/e/w/ne/nw/se/sw` —— 全图 **650 条出口里有 124 条是斜向**（19%）。
而 `ui.js` 的方向表只写了 6 个：

```js
const DIR_CN  = { n:'北', s:'南', e:'东', w:'西', u:'上', d:'下' };
const DIR_OFF = { n:[0,-1], s:[0,1], e:[1,0], w:[-1,0], u:[0,-1], d:[0,1] };
```

连线那一步是 `const d = DIR_OFF[dir]; if (!d) return;` → **斜着相连的两个房间画出来互不相连**，
看着像隔了老远；地图抬头还会印出「出口：北 / 南 / 西 / 东 / **ne**」这种半中半英。

修法：补上四个斜向（`ne:东北 / nw:西北 / se:东南 / sw:西南`，偏移 `[1,-1]/[-1,-1]/[1,1]/[-1,1]`）；
`u/d` 仍**不画线**（不同楼层画条直线等于骗人），只在出口名里显示。

> 布局引擎 `core/maplayout.js` 的 `DIR_DELTA` 本来就有斜向 —— 缺的只是前端这一层。

### ② 开图不居中

画布是**整块区域**大小（窄屏 16×16 格 = 892×892px），手机可视区只有 ~343×400。
原来打开就停在**左上角** —— 玩家自己的格子大概率在视野外，眼前全是「别处」；
再加当时横向还划不动（B33），等于**永远找不到自己**。这就是「附近位置与实际不符」的直观来源。

修法：新增 `centerMapOnHere()`，开图时把「你在这里」那格滚到视野正中。
坐标**从 DOM 反读**（房间格子的 `left/top` 写在内联 style 里），不再把几何算法抄第二遍。

### ③ 点「一步可达」的格子，走的是**房间名**不是方向

```js
/* 注释写着「优先用方向走（引擎的方向指令最可靠），否则用房间名」—— */
doCmd('go ' + room.name, { fromButton: true });     // ← 代码只做了后半句
```

`go <名字>` 是**按名字找**。江湖上「客栈」「山道」「小巷」满地都是同名/近名，
点的是地图上紧挨着自己的那一格，人却被带去了**另一个同名房间** —— 位置自然「对不上」。

修法：先查 `view.exits` 里有没有 `to === 目标房间`，有就发**方向**（当前房间自己的出口，一对一，不可能走错），
查不到才退回名字。

### 断言 & 变异自证

`tools/smoke-round2-map.js`（新，7 项）——**断几何，不 grep 源码**：
按真实地图数据算出「该画几条走廊」（正交 44 + 斜向 12 = 56），再数**真渲染出来的** `<path d>` 里有几段 `M…L…`，两边必须相等。

| 断言 | 变异 | 结果 |
|---|---|---|
| R2-1-2/R2-1-3 走廊段数 = 正交+斜向，且 > 正交-only | 摘掉 `DIR_OFF` 的斜向偏移 | **红** |
| R2-1-4 出口行不出现英文 ne/nw/se/sw | 摘掉 `DIR_CN` 的斜向中文名 | **红**（`smoke-uiux` ⑩-2c） |
| R2-2-2 同区域内一步可达房间的格子差 = 出口方向偏移（无错位/重合） | — | 绿 |
| `smoke-mapui` B-3b 开图自动居中 | — | 绿 |
| `smoke-mapui` C-1b 直连出口发**方向** | 改回只按房间名 | **红** |

> ⚠️ **⑩-2c 踩过一次「grep 源码当断言」的坑**：第一版写的是
> `/ne:\s*'东北'/.test(源码)`，而 `ui.js` 里**另有两处**局部 `const CN = {…ne:'东北'…}`（出口九宫格用），
> 把 `DIR_CN` 那行删掉、grep 依然命中 → 变异测下来**恒绿**。改成走**真渲染**读 `.map-now` 文本才守得住。

## B35 · 饱食 / 饮水小数位不要超过一位

主人的标准是「**不超过一位**小数」（不是「必须整数」）。

生存系统按小数扣（`p.food -= 0.5`、每分钟按比例回复），原值常是 `99.9187` 这种四位。
顶栏已经用 `Math.floor` 修过，但 `showPanel`（「状态一览」）那两行还是 `p.water + ' / ' + p.maxWater` ——
**修一处漏一处**。

修法：加**单一入口** `fmt1(n) = Math.floor(n*10)/10`：

- 满足「不超过一位小数」（`99.9187 → 99.9`）；
- **下取整**而不是四舍五入 —— 否则 `99.96` 会显示成满值 `100.0`，没满却写满 = 谎报；
- 整数原样（`100 → 100`，不补 `.0`）。

顶栏与「状态一览」都改成走 `fmt1`。

> 顺带修正了我自己上一批定的**过严**标准：`smoke-uiux` ⑨-1/2 原来断「必须整数」，
> 比主人要求更严；已改成「小数位 ≤1」，并保留「值本身是下取整到一位」的防假绿断言（⑨-2b）。

## B36 · 主动攻击 NPC 时，旁边 NPC 帮错了人

### 根因（两处，缺一不可）

`world.js` 的 `combatStartWitnessReaction(battle)`：

```js
const attacker = battle.target;                  // ⚠️ target = **被打的那个 NPC**
const witnesses = ….filter(n => n.id !== attackerId …);
const r = this.witnessTree(w, personalityMod, attacker.name, /* playerIsVictim */ true); // ⚠️ 写死 true
…
else if (per.id === 'xiayi' …) battle.attackers.push(w);   // ⚠️ 一律倒进「玩家一侧」
```

`startCombat(ch, npc)` 里 `attackers=[ch]`、`defenders=[npc]`、`target=npc`。所以：

- **玩家打小叫花** → 树以为「小叫花在行凶、玩家在挨打」→ 侠义 NPC
  「挺身加入战团，与你并肩迎敌」= **帮着凶手打受害者**。这正是主人看到的那一幕。

### 修法

1. **谁先动的手**用显式标记判，不看 `target`：
   `startCombat(ch, npc, {ambush:true})` → `battle.ambush`。
   遭遇战（`onRoomEnter` 里被山贼/毒蛇拦住去路）走 `{ambush:true}`；
   `kill` / `fight` / 掳人 / modapi 都是玩家发起，不带此标记。
   → `playerIsVictim = !!battle.ambush`。
2. **被打的是不是「该打的人」**：新增 `world.isVillainNpc(n)`
   （`def.hostile` 模板常驻标记 / 恶徒 tag / 恶名 ≤ −30）。侠义之士对山贼没道理替他出头。
3. **站队**三档：
   - 玩家**被伏击** → 进 `attackers`（与你并肩，B7 原场景，行为不变）；
   - 玩家打**弱者** → 进 `defenders`（挡在小叫花身前，跟你动手）；
   - 玩家打**该打的人** → **谁也不帮**，抱臂退到一旁。
4. **目击者名单**：由「排除 `target`」改成**排除本次参战双方**（按 id 全排）；
   `def.hostile` 仍排除（山贼/毒蛇不做「旁观市民」的惊呼/逃跑反应）。
5. **顺手补一个「谎报」**：官差台词写着「（你被官府通缉，通缉度 +1）」，但那个 `+1` **从来没实现过**
   （老代码走不到这一支）。现在真加；并且**打山贼（除害）时官差睁只眼闭只眼**，不加通缉、
   台词也改成「扫了一眼地上那人，别过头去：「……我没看见。」」
   （否则「打山贼反被通缉」说不通，玩家一定会骂）。

### 断言 & 变异自证

`tools/smoke-owner-bugs.js` 新增 §B30（12 项）+ 改写 §B7：

| 断言 | 变异 | 结果 |
|---|---|---|
| B30-3 ★ 侠义 NPC 站到**被打的小叫花**那边（`defenders`） | `playerIsVictim` 退回写死 `true` | **红（7 项）** |
| B30-4 ★ 没有站到玩家（动手的）那边 | 同上 | 红 |
| B30-5 ★ 台词点明「挡在谁身前」且不再有「并肩迎敌」 | 同上 | 红 |
| B30-7 对照：打山贼时谁也不帮 | 同上 | 红 |
| B30-8 对照：真被伏击时回到玩家一侧（B7 原场景没坏） | — | 绿 |
| B30-9 ★ 当街打平民，官差那行「通缉 +1」真加了 | 退回写死 true | **红** |
| B30-10 对照：打山贼通缉不涨 | — | 绿 |
| B7-4 ★ 打「该打的人」时不站任何一边 | 退回写死 true | 红 |

> **连带修掉一个「靠缺陷成立」的旧断言**：`smoke-owner-bugs` 的 BLK-2（蓝凤凰出招采样）原来是
> **借**「侠义者无条件倒进 attackers」这个 bug 才把蓝凤凰拉进战团的。修对之后她不再参战、采不到招 →
> 已改成**直接以蓝凤凰为对手**（她是防御方，照常还手），断言才立在正常机制上。

## B37 · 点「任务」快捷键弹出来的还是旧主线

三个成因，逐条修。

### ① 开局自动把**第二幕**也接了

```js
// world.createPlayer()
for (const qid of Object.keys(this.data.quests || {})) {
  if (this.data.quests[qid].type === '主线') p.setQuestStage(qid, 0);   // ⚠️ 一律接
}
```

加进第二幕后这就坏了：`q_main_sect`（门派之疑，level 30，委托人冲虚道长）也开局被塞进任务簿 ——
新角色一进游戏就看见「**把半块东厂铜牌带回武当，交给冲虚道长过目**」：
① 剧透二幕；② 玩家压根没那块铜牌（**第一幕幕末才发**）；③ 新手引导第 5 步「寻个营生」的
「非主线」判定（`tutorial.js` 的 `some(k => k !== 'q_main_jianghu')`）**一开局就被点亮**。

> 这条隐患 `design/17-intro-rewrite.md §5` 早就记了「建议重做主线时一并处理」，
> 主人这回以「点任务快捷键弹出来的还是旧主线」把症状报到台面上。

修法：**有委托人（`giver`）的主线必须由那个人当面交给你**，只有无委托人的「起手式」才自动接
（另支持数据侧显式 `auto:false`）。将来加三~五幕也**不会复发**（判据是数据字段，不是幕号）。

### ② 第三阶段文案点名了**四个打不动的人**

数据里：

```
desc : 击败一位绝世高手（东方不败 / 血刀老祖 / 丁春秋 / 方证大师）
cond : { fn: 'defeatLegend' }
```

而引擎的名单是 `LEGEND_IDS = ['emei_miejue','taixu_hermit','shenni']`（灭绝师太 / 太虚居士 / 神秘老僧）——
**desc 里那四位一个都不在名单里**（东方不败=第四幕 Boss，血刀老祖/丁春秋=第三幕 Boss，方证大师=第三幕委托人）。
玩家照着面板把这四位挨个打一遍，**任务永远不推进、也不报错** ——
这就是「弹出来的还是旧主线」最实在的一层：面板给的还是**旧主线的攻略**。

修法：desc 改为 `胜过一位成名高手（灭绝师太 / 太虚居士 / 神秘老僧）`（**与名单逐字对齐**）。
数据用 `JSON.parse → JSON.stringify(doc,null,2)+'\n'` 改写，改前先验**往返逐字节一致**，
改后重新读回比对（2 空格 + 尾换行格式未变；343851 → 343845 字节，只动了这一处）。

并加**护栏**（`smoke-mainline`）：把 `desc` 括号里点名的人**现取**出来，逐个反查 id，
要求每一个人都落在 `legendIds` 里 —— 名字从文案里取，不在测试里再抄一份名单。
**先红后绿**：加断言时当场红（「点了却打不动：东方不败、血刀老祖、丁春秋、方证大师」），改完数据转绿。

### ③ 面板一把梭平铺，主线把支线挤没

`questsHtml()` 原来把 `active` 平铺，只要挂着主线，第一屏全是主线。
改成**按类型分组**（主线 / 支线 / 门派 / 委托 / 其他，主线在最上，带条数），
身上没有支线时给一句江湖话的提示（不写「请前往XX领取」那种说明书腔）。

### 「快捷键实际点了的效果」

主人点名要验。逐个**真点**默认快捷条的 10 个按钮（走真 `onclick → doCmd → api`），读真记录：

| 指令 | 性质 | 实测 |
|---|---|---|
| look / meditate / heal | 真指令 | 真过后端 ✔ |
| i / skills / sc / map / quests / help / guide | 面板类 | **本地开面板，一条后端调用都没有** ✔ |

⇒ 10 项**全部有真实效果**，没有「点了没反应」的。`guide` 也确实在 `PANEL_CMDS` 里被前端拦截
（不是发给后端换来一句「「guide」是什么指令？」）。

### 断言 & 变异自证

| 断言 | 变异 | 结果 |
|---|---|---|
| `smoke-quest-data` ★ 开局任务簿只有第一幕，带 giver 的主线一条都不在 | `if (q.giver) continue` 改 `if (false)` | **红（4 项）** |
| `smoke-quest-data` ★ `view.quests.active` 里不再出现「门派之疑」 | 同上 | 红 |
| `smoke-quest-data` ★ 引导「寻个营生」未被提前点亮 | 同上 | 红 |
