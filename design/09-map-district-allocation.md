# 《地图分区与 NPC 安置规格》

> 上位文档：`08-studio-master-plan.md` SPRINT-A 的执行细则。
> **执行顺序：先定地 → 再分人 → 最后写画像。** 画像写到哪儿的人身上，那儿就得先有地方。
>
> 最后更新：2026-10-09

## 零、为什么要重做（实测数据，不猜）

### 0.1 真病灶

```
620 间房 → 真实房间只有 266 间，填充物 354 间（57%）
```

填充物两种前缀：

| 前缀 | 数量 | 现在长什么样 | 问题 |
|---|---|---|---|
| `fang_*` | 156 | 「巷陌」「巷陌·第二弄」…「第三十弄」 | 三十条一模一样的巷子，纯凑数 |
| `hm_*` | 198 | 「岳不群的家」「伍修的家」… | **全部挂在公共建筑旁边** |

**最离谱的一例**：

```
fang_jiangnan_1 的出口 = { s: 悦来客栈, n: 岳不群的家, nw: 令狐冲的家,
                           sw: 冲虚道长的家, e: 灭绝师太的家 }
```

华山派掌门的家、中原第一剑客的家、武当掌门的家、峨眉掌门的家，
**四个门派的掌门全部住在江南城一家客栈的巷子里**。这是地图看起来乱的唯一根因。

### 0.2 区域名一半是英文

房间实际用 **31 个 region tag**，但 `50_map.json.regions` 只定义了 **12 个**。
剩下 19 个（jiangnan / huashan / shaolin / wudang / emei / gusu / wild / beijiang…）
在 `packRegions()` 第 267 行 `name: regions[regId] && regions[regId].name || regId`
走到 fallback —— **玩家在地图上看到的是 "huashan"，不是「华山」**。

### 0.3 「重要」和「次要」现在是混的

313 个 NPC 挂着 313 条支线（`sq_npcv_001` ~ `sq_npcv_288` + 25 条门派主线），
且**支线 desc 是模板套的**（313 条去重后 310 条，句式就那几种）：

```
「傅君让你帮忙找一位久未联系的旧识夏青。」
「水拂让你帮忙找一位久未联系的旧识范秋声。」
```

所以现在**没法靠「有没有支线」区分主次**——人人有支线，等于人人没支线。
必须先在**地理上**把 NPC 分层，画像和支线才有挂靠的地方。

## 一、分区体系：三层

```
第一层  天下九州（world map，只看轮廓和名字，看不清房）
   │
   ├─ 第二层  州府/区域图（区域舆图，默认打开，能看到格、房间名、NPC）
   │     ├─ 城镇区（可自由行走）
   │     ├─ 门派/官府区（需身份或通报）
   │     └─ 野外区（自由）
   │
   └─ 第三层  私域（private，不在地图上，靠「与该 NPC 互动」才进）
         └─ 每户一个小院，只有本户 NPC + 常客
```

**关键设计：第三层「私域」不上地图。**
玩家在区域图上只会看到「张家宅」这样一个小点，
背景里知道「张家在柳巷，隔壁是老张家」，
**要走到那儿，得先跟张本人有交情（好感 ≥30 或接了他的支线）**，
然后「拜访」才开一条通往他小院的路。

这解决了两个问题：
1. 地图不再被 198 个「某某的家」撑爆
2. 每户人家成了一个**可解锁的小副本**，天然有探索感

## 三、NPC 安置：三层分级

### 3.1 分层标准

| 层 | 判定条件 | 数量 | 地图上 | 画像规格 | 家 |
|---|---|---|---|---|---|
| **A · 主角级** | 门派掌门 / 五岳剑派人物 / 主线 Boss / 有画像且 tier=A | **40** | 标名字 + 立绘格 | 完整 13 字段 + 弧光 | **独立小院，区域图可见** |
| **B · 常驻级** | 有固定店铺/岗位（掌柜、店主、捕快、郎中、镖师…） | **120** | 标名字 + 小图标 | 完整 13 字段 | **区域图可见的家或铺子** |

**C 层的 5 字段**（对齐 `03-portrait-samples.md` 的 B 层示范粒度）：
`姓名 / 身份 / 一句话模样 / 与谁是邻居 / 一个能记住的小癖好`

主人钦定：**C 层只写这 5 项**，不写 `secret` / `obsession` / `feuds` / `arc` / `hooks`。
——背景人不需要有内心戏，只需要「你去找他时，他像个人」。

### 3.3 私域设计（主人的核心要求）

**现状问题**：198 个 `hm_*` 房间全挂在公共建筑旁边，随机分布。

**新设计**：

```
C 层 NPC 的家 → 从地图上彻底消失
             ↓
玩家在区域图上只看到「柳巷·民宅」这样一片聚合标记（3~5 户共用一格）
             ↓
想进去？先满足条件：
   ① 该 NPC 好感 ≥ 30
   ② 或接过他的支线
   ③ 或你是他的债主 / 仇家 / 青楼东家（掳人系统联动）
             ↓
条件满足 → 该户小院「点亮」，区域图上从聚合标记里单独浮出
         → 指令「拜访 张三」才建路
             ↓
进院 → 3~5 间房（堂屋/卧房/厨房/院子/柴房），
       院内可触发：聊天、买卖、投宿、蹭饭、翻箱倒柜（有后果）、送重礼
```

**每户小院 3~5 间房**，198 户 × 4 = 792 间房**不写进数据**，
只在玩家拜访时**动态生成 1 间**（其余留白，随访问进度逐间解锁）。
数据里只存 `house:<npcId>` 一条 + 布局模板。

**这就是地图从 620 → 约 330 房间的瘦身法**，同时把 198 个家从地图噪音变成内容。

### 3.4 邻里关系（背景里提一下）

每个 C 层 NPC 有一组 `neighbors` 字段，**只在他自己的画像或拜访场景里出现**：

```json
"npcv_050": {
  "neighbors": ["傅家隔壁是老李家", "巷口是卖炊饼的王二", "对门在闹分家"]
}
```

**作用**：
- 玩家进巷子时，邻居的一句话就交代了地理关系，不用地图画几十个小院
- 「谁和谁是邻居」会成为传闻系统的种子（隔壁王二昨天被人抬走了）
- 玩家可以去找邻居打听（`打听` 指令的新目标来源）

## 五、测试要求（`tools/map-check.js`）

落地后必须全绿的断言：

1. **房间 id 唯一**、所有出口指向真实存在的房间（双向都要有反向边）
2. **31 个 region 全部有 `name`**，且 `name` 不等于 `regId`（防英文 fallback 复发）
3. **NPC 归属断言**：每个 NPC 的 `district` 对应的 region 真实存在
4. **住宅解锁断言**：每个 `house:<npcId>` 的 owner 必须是真实 NPC，且该 NPC 有 `house` 字段
5. **terrain 不越界**：所有 terrain 格的坐标在所属 region box 内
6. **地图格数达标**：每个 `tier=town/sect` 的区域 `box.w*box.h ≥ minW*minH`（terrain 计入）
7. **住宅不连片**：区域图上「已解锁住宅格」之间至少隔 1 格（主人要求）
8. **拜访门槛断言**：好感 <30 且无支线的 NPC，`visitHouse` 返回明确拒绝理由
