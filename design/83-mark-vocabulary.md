## 〇、三条前置

### 0.1 一条总纲（贯穿全表）

> **连续量用可递增通道，离散量用可枚举通道。**
> （主理人 2026-10-13 从 `design/79` 提升为通用判据）

- **程度**（伤得多重、血有多深）→ 要能**递增**：杠宽 / 杠长 / 色阶。
- **类别**（这是固定描写还是动态句、这个词能不能点、这是出口还是可交互物）→ 要能**枚举**：
  位置 / 形状 / 线型。

判据用错的样子：拿"可递增的尺子"去量"是什么"，玩家会读成"这句比那句轻"。

### 0.2 两条硬约束（从各文档提升上来的）

1. **颜色不得是唯一信息载体。** 去色截图上必须还能认出。
2. **判定"落地了没有"不能只靠字面 grep。** 类名/变量是拼出来的、走数组的、走映射表的。
   ⇒ 同样地：**判定"撞没撞"不能只看选择器名字**，要看**它实际占了哪个通道**。
   （本文 §4 那两处，就是只看名字看不出来的。）

### 0.3 作用域分三层

通道独占是**按作用域**判的，不是全库一刀切：

| 作用域 | 范围 |
|---|---|
| **A · 日志流** | `.log` 内的文本行 |
| **B · 地图容器** | `.map-*` |
| **C · 面板 / 徽标 / 按钮** | 弹窗、卡片、标签、快捷键 |

跨作用域**不算撞**（地图的圈和日志的点不会同时进玩家眼睛）；
**同一作用域内，一个通道只归一家。**

> ⚠️ **2026-10-13 走查后补**：跨层免检**只对"确定不同屏"的两层成立。**
> 免检的真正前提是"不会同时进眼睛"，不是"不在同一作用域"。
> 例：地图面板与日志流**可能同屏**（右栏 / 弹窗）⇒ 即使跨层，也要对一次表（见 §4.3.5）。

### 2.1 判别：什么叫"记号"，什么不算

登记前先过这一刀，否则下一盘点的人会把分隔线全算成记号：

| 是记号 | **不是**记号 |
|---|---|
| 携带语义（可枚举 / 可递增） | 只分区，不携带语义 |
| **行级 / 项级** | **容器级** |
| 例：战斗杠（多重）、字下点（能点） | 例：`#scene` 的 `border-left`、` .seg-btn + .seg-btn`、` .data-table td` 的虚线、` .kv` 的分隔线 |

> **一句话：记号回答问题（"这句是什么"／"这下有多重"），分隔线只画格子。**
> 分隔线**不进本表**，也不受 §三 管。但改动它们之前仍要扫一眼有没有连带的布局影响。

### 4.1b 那四根杠的修法（主理人 2026-10-13：并进本文，不新开文档）

#### 先判：这四根杠值不值得继续当"杠"

**判：不值得。四根都拆。** 四条理由，任一条单独就够：

1. **§0.1 判据用错了。** 这四根杠量的全是**类别**（这是剧情 / 任务 / 画像动作 / 路遇钩子），
   用的却是"行左竖线"——一个天然的**可递增**通道（宽 / 长 / 色）。
   这正是 §0.1 里写明的"判据用错的样子"：**拿可递增的尺子去量"是什么"。**
   玩家看见竖线会本能地去读"这根有多重"，而答案是"没有重，它只是个标签"。
2. **它们在稀释唯一有量的那根。** `design/76` 的战斗竖杠是日志流里**唯一**真正携带连续量的杠
   （宽 / 长 / 色三维递增）。现在它有四个同伴，五根竖线里只有一根有含义 ——
   玩家每次都得先猜"这根要不要读"。
3. **它们连彼此都分不开。** `story` 与 `npcsact` 同色同缩进只差 1px（§4.1）。
   一根连"我是哪一种行"都没传达到的杠，说明它**已经退化为纯装饰**。
   ⇒ 装饰件的正确处置是**删**，不是换个形状继续留着。**不为保留形状而保留形状。**
4. **语义早就有别的载体了，杠是第三重重复。**
   - 任务行：全仓 quest 行的 `text` **一律以「【】」方括号开头**（`【任务】`/`【任务完成】`/`【任务进展】`/`【接取任务】`，
     见 commands.js:4575/4603/5804/5812/5846、engine.js:2133、storybeat.js:118/182/187、patrol.js:238、escort.js:93）。
     **它自己就写着"我是任务"。**
   - 剧情行：**本来就该有「剧情」标签**（主人 2026-10-08 原话），只是那条路现在是断的（见下）。

#### 修法：拆，不补形状

## 五、新增记号的七条自测（将来要加第六套，先照这个填）

新增前先回答这七条，答不上来就别加：

1. **我量的是连续还是离散？**
   连续 → 只能用可递增通道（宽/长/色阶）；离散 → 只能用可枚举通道（位置/形状/线型）。
2. **我要占哪个通道？那个通道现在归谁？**
   查 §二。已被占 → 要么换通道，要么先跟那家谈（并满足 §3.6 的第二维度）。
3. **我的作用域是 A / B / C 哪一层？**
   跨层不算撞；同层才受 §三 管。
4. **去掉颜色之后还剩什么？**
   答不上来 = 违反 §0.2-1，回去重做。
5. **我跟同层里最像的那套记号，靠什么分？**
   必须答出**至少两个维度**（形状 / 位置 / 线型 / 宽窄），只答颜色 = 不合格。
6. **我的记号会不会跟别人的"退路"打架？**
   ⚠️ 这条最容易漏。例：81 那条 `@supports` 兜底的实线下划，
   在墨阶甲落地后不能再退——因为那时 79 的②③ 亮度差只剩 1.126，
   那颗点已经是唯一判据，一退化成线就撞上出口的虚线（`design/81` §4.2）。
   ⇒ **新增时要检查：我的兜底路径会不会踩掉别人的主判据。**
7. 🔴 **我说"这条通道上住了谁"，是全量盘出来的，还是我记得的？**
   ⚠️ 这条是我 2026-10-13 第二轮走查**用自己两处漏换来的**。
   上一版我在这张表里写下"两根杠""三家缩进"时，两个数字都是**凭印象**，
   实际是**四根**和**六家**（§4.3.1）。
   ⇒ **写进表之前：把这条通道全仓 grep 一遍，把每一家列出来，别写"等我记得"。**
   这张表的全部价值就在于**不靠任何人的脑子**——连写它的人的脑子也不靠。

### 附注：`.log-tag` 为什么不算违反 §3.4

`.log-tag`（剧情行上方那颗「剧情」小标签）是**文字标签**，不是记号——
它说的是"这句是剧情"这个**事实**，靠**读字**得知，不靠识形。
⇒ 它可以用底 + 边框（跟徽标同族），因为玩家不需要"认出"它，只需要"看见"它。
**记号与标签的区别：记号靠形状被认出，标签靠文字被读懂。**

> ⚠️ **2026-10-13 走查补记**：这条豁免**本身成立**，但我写它的时候**没有追数据路径** ——
> `.log-tag` 当前是一条都不渲染的死代码（§4.1b / §4.3.6）。
> 豁免一个不存在的东西，跟漏记两根杠是**同一种错**：**只看 CSS，没看它会不会真的出来。**
