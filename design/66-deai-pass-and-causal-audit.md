## 一、去 AI 味：从「一条规则」到「一类句式」

### 1.1 主人点的那句，问题不在词，在**壳**

> 原句：老汉看了半晌，从怀里摸出个东西。**不是钱，是一封旧信**，封皮上**只**按了个指印。

- `不是 A，是 B` —— AI 写中文最典型的一层壳：**先立一个靶子，再抛出答案**。
  读者并没有以为那是钱，这个否定是在替读者做注解。`deai-promax` 把它列为「三毒」之首。
  **处理：删掉靶子那一半。** 改动只有六个字：
  `不是钱，是一封旧信，封皮上只按了个指印` → `是封旧信，封皮上按着个指印`
- `只按了个指印` —— 「不 X 只 Y」的兄弟。单看没事，**成批出现**就是机器腔。
  这里「只」承担的是「有指印、没写字」这层对比，位置没错，但同段里两个 AI 壳叠着，
  留一个就够 ——「只」删掉，对比交给下一句（「封皮上没写字」）。

同一章里还有一句同族的：`你记得的不是路，是一只手掌。` → `那条路你早忘了。记住的是那只手掌。`

### 1.2 扫全库：新规则 + 两台口径

把规则加进**回归守卫** `tools/ai-flavor-check.js`（而不是只改一次就完事），并定两条豁免：

| 规则 | 判据 | 豁免 |
|---|---|---|
| 对偶定义（不是 A 是 B） | 逗号紧接的 `不是X，是Y` / `不是X，而是Y` | **人物台词豁免**（`talk`/`answer`/`say` 字段，或整句在「」里）——「这不是狠话，是账」是人的强调语气，是好句子 |

同时修了两个**扫描口径**的老毛病（不然命中的全是噪声）：

- **注释里有引号**：`combat.js`/`commands.js` 的工程注释连续命中「不是A是B」——
  那不是给玩家看的字。改成跳过整行注释与块注释。
- **问答表没算玩家可见**：`ask` / `askDefault` 这两个字段是「问一句他答一句」的台词，
  第一版没列进可见字段，于是当铺伙计的台词被当成旁白判红。

### 1.3 全库命中与处理（26 处）

| 类别 | 处理 |
|---|---|
| **旁白里的对偶壳**（画像 `hooks.seed` ×6、房间/事件/主线旁白 ×10、武学与物品描述 ×5） | **全改**。改法统一：**删掉靶子那一半，直接写是什么**；或把抽象换成具体动作（「他搓的不是米，是心」→「搓完把碎米挑出来，说这批不能卖」） |
| **人物台词里的对偶**（洪七公「降龙十八掌最难的不是招式，是那股子刚正之气」、蓝凤凰「蛊不是术，是命」、当铺「不是我狠，是东西押在手里也要担风险」、柳含烟「不是我拿大，是弹它伤人」…） | **保留**，并写进守卫的豁免里 —— 人就是这么说话的 |
| 网文套词 | `不由得` / `气血翻涌` ×2 → 改 |
| 破折号密度 | 实测 **0.95 / 千字**（阈值 2.38），**不需要动** |

### 1.4 扫完之后顺手做的量化体检（26 万字玩家文本）

| 项 | 实测 | 判断 |
|---|---|---|
| 玩家可见中文串 | **12,078 条 / 262,860 字** | — |
| `仿佛`（AI 高频） | 0 | 健康 |
| `眼神` / `目光` / `淡淡` / `轻轻` | 各 12~14 次（≈0.005%） | 健康 |
| 破折号 | 0.95 / 千字 | 健康 |

**结论：全库的用词是干净的，问题集中在**句式层**（对偶壳），不是词汇层。**

### 1.5 画像模板的「机械重复」——本题最刺眼的一处 AI 味

量化发现 C 层（门派小人物）**同一句话在全库重复 16 次**：

> 「天天扫地挑水，师父教的那一招还没练顺。」×16 · 「让师父记住自己的名字」×16 · 「师弟（师兄）好。」×16

根因：21 组门派人物共用 2 条 `now` / 2 条 `want` / 2 组口头禅。
玩家连着碰上两个门派弟子，看到一模一样的句子 —— 那不是文笔问题，是**模板露馅**。

两处整改：

1. **扩变体池**：弟子 7 条 `now` / 6 条 `want` / 8 组口头禅；看门人 6/5/5；掌门 5/5/4；武馆教头一人一句 `origin`。
2. 🔴 **选句从「哈希取模」改成「组内轮转」**：
   哈希在样本小时会**撞堆**（实测 21 个看门人里 9 个抽到同一句口头禅，而池子里明明有 5 句）。
   轮转保证同组相邻两人必不重样，且完全确定（只跟排序后的序号有关，重跑结果一致）。

| 字段 | 改前最高重复 | 改后 |
|---|---|---|
| `role` | ×16 | **×2** |
| `origin` | ×6 | **×2** |
| `now` | ×16 | **×5** |
| `want` | ×16 | **×5** |
| `catchphrase` | ×16 | **×4** |

## 二、主线因果审查：骨架可用，补了四处接榫

完整诊断见 **`design/65-mainline-causal-audit.md`**（六项问题 + 证据行号 + 后续大纲）。

一句话结论：**五幕主干干净，不需要重写**；缺口在榫头 ——
几处衔接靠玩家的**偶然发现**，而不是剧情的**必然推动**。

本轮已落地的四处：

1. **堵住「先接后拿 + 剧透」**：`q_main_sect` 加 `require: {flag:know_east_depot}`，
   并补一句人话门槛（顺带给 `accept` 指令加了 `requireMsg` 支持 ——
   原来只会说「你还不满足接取条件」，只告诉玩家「不行」、不告诉他差什么）。
2. **让铜牌那场夜戏看得见**：华山道房间描述补一句「天擦黑时这道上常有官车过；
   路边有块背风的石头，赶路的人多半在这儿歇脚」——**不剧透**，但告诉玩家这儿有戏。
3. **修好不可达分支**：`mojiao_shanmen` 加 action「探后山」，`moye_backroad` 不再只读不设。
4. **半交结局有物可交**：陈语冰抄纸那段同时 `+item:wulin_zhenyi_chaoben:1`。

外加：**认知边界收口**（东方那句改成耳目众多 + 追问）、
**补两名一线 Boss 的画像**（血刀老祖 / 丁春秋，各 13 字段 + 两条 `hooks`）。

## 三、Mod 制作器

`gamedata` 的 ID 列表原本只有 7 类（人物/物品/武学/房间/区域/剧情/门派），
而库里早就多了 **世界事件（68 条）**、**结局**、**天赋**：

- `endings` / `traits` —— 再新增两类**可按 id 载入编辑**（并在 `blankSpec` 里登记：
  不登记的话，作者载入的东西一保存就被 `jsonToSpec` 丢掉 —— 上一轮隐藏 ID 就栽在这）。
- `worldEvents` —— 世界事件挂在 `worldEvents.onDayTick` 这个**数组**上，
  而引擎对数组是「整段替换」：载入单条再上传会把其余 67 条一起顶掉。
  所以这一类做成**只读**：能搜、能看内容、能抄 id 进 mod 的 `cond`，但**不给载入编辑**。
