## 〇、三条总纲（先立规矩，再上清单）

### 0.1 行为点 = 「能下手的地方」的回声

与 `81` 咬合的硬判定：

> **一个房间没有可交互名词（字下朱点的词），它就不产生行为点。**
> 痕迹句是「你上次在这儿干过什么」的回述，而「干过」的前提是「当时能下手」。

⇒ 本清单的每个行为点，候选位都限定为**已有 `action` 或可交互名词的房间**。给空房间硬造「坐歇」，等于在没点的地方凭空出现历史——`81/N-V-25`（`.log-line.trace` 内 `.hl` 数量 === 0）同时保证痕迹句**本身**永远不可点，回述里没有当下能下手的东西。

### 0.2 覆盖语义（照抄 77 §2.0.2，一条不改）

- 写 `p.roomNotes[roomId]`，**单值**，新行为**静默覆盖**旧痕迹，不提示（77 §6.1 · V3 的裁决：先不加宽限）。
- **动作成功才写，失败不写。** 半途被打断、条件不满足、被守卫拦下——都不留痕。没干成的事不配被记住。
- 序列化进存档；渲染永远在固定描写、动态句之后。

### 0.3 触发条件的写法与字段边界

`evalCond`（`game/src/core/modapi.js`）已支持的形态，本清单只用这些：

| 形态 | 例 |
|---|---|
| 字符串简写 | `"hp<30"`、`"money>=100"`、`"flag:drunk"`、`"!combat"` |
| 数字比较对象 | `{ attr: "hp", "<": 30 }` |
| 组合 | `{ and: [...] }` / `{ or: [...] }` / `{ not: ... }` |
| 房间归一字段 | `"roomItems>0"`、`"roomNpcs>0"`（modapi 已做 `room.items` → `roomItems` 归一） |

🔴 **两个字段我没在 modapi 里查到现成写法，标注待寇豆码确认**：天气（`weather=='雪'`）与时辰（`isNight`）。条件先用 `{ and: ["!combat", ...] }` 兜底给出，字段名他落地时对齐即可——**判据是"什么情况下这个动作会出现"，字段名不是判据的一部分**。

## 二、与 81 / 79 / 83 的接口核对（三条，全是我这边能拍板的）

1. **痕迹句内 `.hl` 数量 === 0**（`81/N-V-25`）。上面 18 条的句子里没有任何词需要高亮——回述是过去时，过去时没有可下手的东西。写成规格：痕迹句字符串**不过 `.hl` 渲染管线**，整句按 79 的 trace 层样式（独立一行、左侧竖线、弱色一档）输出。
2. **痕迹句不与动态句抢通道**（`83` §四已盘）：trace 层走 79 已定的行级样式，本清单不新增任何视觉记号、不新增颜色。**这份文档是纯文案与条件清单，不产生新的美术资产。**
3. **写入时机**挂在动作成功回调处，与 `81` §3.1 的 `.hl-tip-cmd` 执行点是同一条路：玩家点词 → 提示行 → 指令执行成功 → 此处写 `p.roomNotes[roomId]`。行为点不需要独立的触发入口，**复用现成的 action 通道**，一行不新增按钮。

## 三、给寇豆码的落地口径（4 行）

1. 表格逐行落：候选位 = 匹配 `room.action` 里对应的 cmd（cmd 名以数据为准，我给的是语义，他按 cmd 对号）。
2. ⚠️ 标注的 4 类字段（weather / isNight / drunk / 击杀定位 / 抄书·持信 flag）落地时对齐实际字段名；**对不上就先落条件最简的那一档**（`"!combat"` 常驻位 6 条：#3/4/11/14/15/18），不要为等字段停整批。
3. 写入只在动作成功回调之后；覆盖静默；序列化进存档（`77` §5 · R4 已定，不重述）。
4. 验收：同一间房先后干两件事 → 后者盖前者、无提示、`look` 第三段只见后一句。

## 四、可砍项

砍法与 77 §6.2 同一逻辑，按组砍整组：E 组城镇 4 条 → C 组门派 3 条 → B 组 2 条。**A 组 6 条与 D 组 12/13 两条不能砍**——野外行为点是「江湖感」的底，杀与被杀的痕迹是这批东西存在的理由。
