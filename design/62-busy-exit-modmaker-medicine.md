## 1 吐纳 / 双修：点屏幕上任何别的按钮就退出

### 主人原话
> 「『吐纳』的动不了，改成点击页面任意其他按钮自动退出『吐纳』状态」（双修采补同理）；
> 「屏幕上要有退出吐纳状态的文本显示」；「中途退出双修状态的显示以及伴侣对你这种行为的幽怨态度语言神态动作等描写」；
> 「不用搞『收功』按钮」；「双修整个过程中到事后结束，玩家是否还会继续卡在那动不了也点不了」

### 改之前是什么样
- **双修中**：`engine.exec` 里有一张**白名单**，不在名单上的指令一律被**拒绝**，
  回一句「这会儿脱不开身 —— 要收手，敲『收功』」。
- **吐纳中**：只有 `movePlayerTo` 拦移动；点「背包」这类**本地面板指令**压根不走服务端，
  所以人还坐在那儿吐纳，面板却开了 —— 状态与画面是两回事。
- 引导文案到处在教玩家**敲「收功」**（等于把「收功」当按钮用，而主人明确不要这个按钮）。

### 改成了什么
**服务端 `engine.exec`：从「拒绝执行」改成「先退出这个状态，再照常执行」。**

```
吐纳中点「背包」
  → [story] 你缓缓睁开眼，把散在外头的那口气一点点收回来……
  → [sys]   已退出吐纳状态（坐满 1 轮） —— 这一坐没熬到最后，白坐了。
  → [title] 【 行囊 】（6 件）……      ← 背包照常开
```

- 判据只认 `p.vars.tuning` / `p.vars.dual` —— 起手之前一切照旧。
- `KEEP` 白名单只留两类：**继续类**（吐纳/行功/调息 · 双修/合修 · 采补/采战）
  与**显式退出类**（收功/散功/起身），其余一律走「退出 + 照常执行」。
  ⚠️ 少留了「继续类」，玩家再敲一次就会把自己打断；少留了「退出类」，
  敲「收功」会**先退一次、再报一次「你并没有在吐纳」**。
- 退出的那几句 **unshift 到该指令输出之前** —— 先看到「醒过来了」，再看「背包里有什么」。

**前端 `ui.js`：本地面板指令补一趟退出。**
`panelForCmd` 命中的指令在前端就地开面板、不打扰后端，所以那里要显式补：
`if (busyState()) await exitBusyState()`（发一次「收功」）。否则点「背包」面板开了、人还坐着。

**新增视图字段 `player.busy`**（`{kind, name, round, rounds}`）—— 前端靠它判断要不要补那一趟。

### 退出时的文本
- **吐纳**：睁眼收气 + 「已退出吐纳状态（坐满 N 轮）」+ 「内力与气血一起耗到见底那一刻，上限才涨」。
- **双修**：**被撂下那个人的反应**，按关系分两池（`QUIT_LOVER` / `QUIT_STRANGER`），
  同池 8 次内不重样。例：「你刚一起身，{a}扣衣裳的手就停住了。『这就走？』她声音平平的，听着比骂你还难受。」
- **采补**：另写一套（对方全程不知情），例：「你停了手。{a}翻了个身，睡得正沉，什么都不知道。」
- 双修半道抽身，**对方好感 −4**（采补不记 —— 人家不知道）。

### 「会不会继续卡着」的答复
**不会。** 四轮走完 `delete p.vars.dual`，`view().player.busy` 转 `null`，人当场能动。
测试里是**真的走了一步**来验的（`road_jiangnan_1 → jiangnan_gate`）。

### 测试
`tools/smoke-busy-exit.js`（**31 项**，真引擎真指令）+ `ui-bind-check.js` 新增 ⑦ 组（**7 项**，真跑 `doCmd`）。
另修 `smoke-neigong`（34/0）与 `smoke-dualcultivate`（53/0）——它们的旧断言是「走不动」，
现在这条口径变了，且**必须把出口验证挪到组末**（它会把状态清掉，插在前面会让后面全断）。

## 2 Mod 制作器：上传要登录 · 我制作的 Mod · 游戏内 ID

### 2.1 上传必须登录
**改之前**：站点上传是**全匿名**的 —— 前端填个昵称就当署名，谁都能顶着别人的名号发。
「我制作的 Mod」这种要认人的功能根本无从谈起（所以这两件是同一件事）。

**服务端**（`server/mod-site.js`）新增本站账号：
- 存储 `server/site-data/accounts.json`（salt + `scryptSync` 哈希，**不存明文**）、`sessions.json`（token 表，落盘，重启不掉线）
- 接口 `POST /api/account/register | login | logout`、`GET /api/account/me | mods`
- `apiUpload` 开头校验 token：**没登录 / token 伪造 → `{ok:false, needLogin:true}`**
- 署名**写死成账号名**（前端传 `author` 不作数）；Mod 记录新增 `owner`
- 别人的作品**顶不掉**：同 id 且 `owner !== me` → 「这是 X 的作品，你改不了」

**游戏服**（`server/game-server.js`）加 `site/account` 转发。
⚠️ 站点把「没登录」做成 **200 + `ok:false`**（不是 401），转发时**不能把 `ok:false` 当传输失败**，
否则前端拿不到 `needLogin`，只会显示一句「网络错误」。

**网页版上传页**（`server/public/upload.html`）也补了登录条 —— 不然服务端门禁会让它「莫名失败」。

### 2.2 我制作的 Mod（左侧新标签）
列出账号名下已发布的 Mod：名字 / 版本 / 分类 / 简介 / ID / 时间 / 下载数，
带「**载入编辑**」（取回发布时的 `mod.json` → `jsonToSpec` 归一化 → 读回表单，改完上传就是更新）
与「看网页」。
⚠️ 必须走 `jsonToSpec`：直接把站点记录塞进表单会把 `owner / timeText / downloads` 这些
**站点侧字段**当成 mod 内容再发出去。

### 2.3 游戏内 ID + 按 ID 改
- 后端 `GET /api/gamedata?kind=…&q=…&id=…`
  - 列表只发 **id / 名字 / 一条摘要**（全库 npcs 469 · items 196 · skills 745 · rooms 454 · regions 35 · quests 374 · sects 43）
  - 带 `id` → 返回那一件的**完整内容**
- 前端左侧新增 **「🎭 游戏内 ID」**：分类切换（人物/物品/武学/房间/区域/剧情/门派）+ 搜索 + 「改这个」
- 「改这个」把那件东西的当前内容整件载进 `spec` 的对应数组 → 保存/上传即**同 ID 覆盖**
- ⚠️ **同 id 只留一份**（数组在引擎里是后写覆盖先写，留两份等于埋雷）

### 2.4 Mod 站同步
- `tutorial.html` 补：上传要登录、「我制作的 Mod」怎么用、「游戏内 ID」按 ID 改
- `upload.html` 加登录条；`site.css` 加样式
- 站点页面**没有**硬编码的过时数字（首页/教程里的功能描述仍然准确）

## 3 医术闭环（「剩下的内容」）

### 缺口
`基本医术`（`basic_medicine`）在 `character.js` 的槽位表里占着一格，
玩家学了却发现**任何地方都用不上** —— 待办里挂着一条「医术类武学无战斗外消费点」。

### 做法（`game/src/core/medicine.js`）
三条出口：
- **`诊脉 [人]`** —— 气血/内力、身上有没有毒/迷/暗伤，外加一句**人话判断**（不报数字）
- **`医治 [人]`** —— 耗内力 + 走时间，按医术功力补气血（**一次最多补目标上限的 35%**）
- **`解毒 [人]`** —— 一次揭一层（医术浅的拔不干净）

另外：替人治伤 → 好感 +；对方是富户还会**给诊金**（钱从他口袋出，不是凭空印的）。

### 效果不跟等级走
本项目已去等级化。医术功力 = `基本医术熟练度 + 内功火候 / 3` ——
内力是医者的底气，**光背汤头歌治不了内伤**。

### ⚠️ 指令重名的坑（第一版踩了）
我原本注册 `疗伤`，但它在 `commands.js:4252` **早就有了**（耗内力硬撑、掏空会积暗伤的那套）。
`reg([...])` 是**后者覆盖前者** ⇒ 我这边整块**静默失效**：敲「疗伤」跑的是老实现，
测试看到的是「数值不对」，而不是「指令没接上」。
**改名为 `医治 / 看伤 / 救治 / 施救`** 之后一切正常（老 `疗伤` 一字未动）。
