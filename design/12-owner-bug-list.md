## B1 · 读取存档里出现「测试侠客」

**现象**：游戏主界面「读取存档」列表里能看到一个叫「测试侠客」的存档。

**根因（两层，缺一不可）**：`tools/smoke-test.js:65` 用 `GameEngine` 的**默认 `saveDir`**（= 玩家自己的
`saves/`）写测试档，每跑一次 smoke 就往玩家目录裸写一个「测试侠客」；叠加 `engine.js` 的 `listSaves()`
对盘上每个 `.json` **无任何过滤**。

**修法**：① 源头隔离 —— 新建 `tools/_test-save-dir.js`（`os.tmpdir()` 沙盒），
三个 smoke 脚本的 `new GameEngine` 全改指沙盒、写档改用 `save(id, {_test:true})`；
② 列表过滤 —— `engine.js` 新增 `_isTestSave()`（名单 id 直接挡；前缀须同时带 `_testMark`，防误杀玩家手打档名），
`listSaves()` 逐条过滤。

**测试**：`B1-1` 无测试档 / 无「测试侠客」/ `B1-2` 带 `_test` 的档不列出且未标记的正常档仍能列出（防误杀）/
`B1-3` **首行仍是磁盘上 savedAt 最大的真档**且不是测试档。
**变异自证**：关掉 `listSaves()` 过滤 → 190 通过 / 5 失败。

> 遗留：`saves/test_slot.json` 文件仍在盘上（只是不再被列出）。删除属破坏性操作，等主人拍板。

## B2 · 「继续游戏」不直接进最近存档

**现象**：点「继续游戏」没有直接进入最近一次存档，而是打开「读取存档」界面要手动点。

**根因**：`game/src/renderer/js/start.js:206` 的 `continueGame()` 原实现只做三件事 ——
拉 `api.saves()` → 判空 → `U.openSaves('load')`，**函数体内没有任何一处自动载入调用**（没有 `api.load`）。
不是排序问题，是根本没载入。

**修法**：`continueGame()` 改为真载入 `local[0]`（`listSaves()` 已按 savedAt 降序，首项即最新）→
`api.load` → `U.show('game')` → `bus.emit('gamestart')`；无档只 toast 不跳转；载入失败 toast + 退回列表兜底。

**测试**：**vm 行为测试** —— 把真 `start.js` 载进 `vm` sandbox，用桩替掉 `api`/`WXUI`/`document`，
真调一次 `WXSTART.continueGame()`，断言它到底调了哪些 API：`B2-3` 直接进游戏不先开列表 /
`B2-4` 载入的是最新档且不是测试侠客 / `B2-5` 无档只 toast / `B2 容错` 失败退回列表。
**变异自证**：退回「只开列表」→ 191 通过 / 5 失败。

> 教训：第一版断言是静态 grep `api.load`，变异体插入一行早退后**仍然全绿 195/0** ——
> 静态 grep 不能当行为断言，已重写为 vm 行为测试。

## B3 · 毒蛇的攻击方式是「基本拳脚」

**现象**：毒蛇战斗时攻击方式是「基本拳脚」，不合理——蛇类该有毒牙、缠绕、扑咬。

**根因**：`game/data/` 里蛇类 NPC（`mob_snake`）的技能是 `skills: { 拳: "basic_fist" }`；
而 `combat.js` 的 `pickSkill(u, t)` 只认 `equippedSkills` 的六个槽位，且**蛇类专属招式在整个数据里根本不存在**
——既没有招式定义，也没有 NPC 引用，所以每回合必然落到「拳」槽的 `basic_fist`。

**修法（代码侧注入，`game/data/*.json` 零改动；本条同时是 B8 的实现模板）**：
新建 `game/src/core/bestiary.js` 定义 `SPECIES_MOVES`（毒牙噬咬 / 缠身绞杀 / 信子吐信）+ `speciesOf()` 三级识别；
`world.js:2347` 新增 `applySpeciesMoves()` 注入 `data.skills` 与 NPC 模板的 `speciesMoves`，
挂在 `loadMods()` 末尾 `buildIndexes()` 之后（`boot()`/`reload()`/`deserialize()` 三条加载路径的必经点）
及 `deserialize()` 末尾；`spawnNpc`（`world.js:773`）`slice()` 复制到实例；
`combat.js:322` `pickSkill` 优先在 `speciesMoves` 里**随机**取招（固定取一招等于「只有一招」，观感与原 bug 无异）。

**测试**：`B3-1` 实例带 speciesMoves 且三招都注入且都学会 / `B3-2` 招式 type 是「拳」（不带兵刃惩罚）
且 `basic_fist` 仍保留（共存非替换）/ `B3-3` **真打一场**统计 24 回合，实测
`{毒牙噬咬:25, 缠身绞杀:19, 信子吐信:20}`，无兵刃惩罚 / `B3-4` `speciesOf` 三级识别 + 幂等。
**变异自证**：`pickSkill` 不读 `speciesMoves` → 193 通过 / 3 失败（退回 `{"基本拳脚":65}`）。

> ⚠️ 所有动物招式 `type` 必须为「拳」：设成「暗器」会被 `weaponPenalty` 给没手的蛇打出
> 「手中无暗器类兵刃，威力大减」（mult 0.45 / acc -25）。

## B7 · NPC 目睹玩家遇袭不反应

**现象**：玩家被山贼/毒蛇打，旁边的 NPC 不会来帮忙、不会惊呼、不会逃跑。

**根因（三层叠加，缺任何一层都表现为「没反应」）**：

1. `world.js` 的 `startCombat()` 里 `emit('combatstart', …)` **全仓零监听**，事件发出去就沉了。
2. 反应台词走 `emit('storyline')`，但该事件**全仓只有两个 smoke 脚本在监听**，产品侧零消费者 →
   即使反应发生了，**玩家屏幕上仍一个字看不到**。
3. （隐藏根因）`personality.js` 的 `PERSONALITIES` **九条原本都没有 `id` 字段**，
   而调用方写 `per.id === 'qienuo'` —— **恒 false**，所有性格分流**全是死代码**。

**修法（接线 + 复用现有反应树，不复制逻辑）**：`world.js:172` 注册 `combatstart` 钩子 →
`world.js:1053` 抽出 `witnessTree()` 与既有 `witnessReaction` **共用同一棵树**（官府分支按
`playerIsVictim` 镜像，玩家受害时改为「制止凶手」且不动 `wanted`）→
`world.js:1095` `combatStartWitnessReaction()` 筛目击者并让怯懦者真 `fleeNpc`、侠义者真进 `battle.attackers`
→ `startCombat`（`world.js:1711`）把台词放进返回值，`commands.js:1790` 的 `kill` handler 并入输出
→ `personality.js` 补 9 条 `id`。

**测试（走真实触发路径：真 `exec('kill ' + foe.name)`）**：`B7-2` 战斗真建立且目标正确 /
`B7-3` 怯懦目击者**真的离开房间**（实测从 `jiangnan_street` 移到 `jiangnan_market`）/
`B7-4` 侠义目击者**真进 `battle.attackers`** / `B7-6` 玩家受害时 `wanted` 不变 /
`B7-基线` NPC 挨打仍触发（老路径没改坏）/ `B7-性格` `PERSONALITIES` 每条带 `id`。

## B10 · 点 NPC / 野兽的菜单里没有「攻击」 ✅ 已修（批次 4）

**修法**：`hl.actions` 加「攻击」，`cmd: 'attack ' + k`（**真实攻击指令**，与手输同路；目标用裸名，

## B12 · 被毒蛇击败后再回去毒蛇「x2」 ✅ 已修（批次 4）

**现象**：主人被毒蛇击败后再回去，毒蛇名旁出现 `x2`。

**先复现（不凭推断改）**：真 `GameEngine.boot()` + 固定 seed + 「含毒蛇的遭遇房 + 无遭遇邻居」，
`encounter.chance=1`、`npcs=['mob_snake']`（内存态）→ 进屋刷蛇 → **被击败**（`p.hp=0`→`auto`→复活回客栈）
→ 再进屋。**修复前实测活体毒蛇 `1,2,3,4,5` 叠加**，房间描述出现 `毒蛇（山中猛兽） x4`。

**结论**：**重复 spawn**（不是「倒地实例没清」）。遭遇分支每次进屋独立掷骰、**从不查房里是否已有同种**；
打赢会 `onNpcKilled` 删掉毒蛇（所以平时无 x2），**打输**则毒蛇不死、留原地，再进屋又刷一条**活**蛇。
「倒地实例没清」**不成立**：倒地者 `dead=true` 被 `npcsIn` 过滤，**不参与 x2 计数**。

**修法**：`world.onRoomEnter` 遭遇分支 —— **同种活体复用（re-engage）**，不再叠实例：
```js
const existing = this.npcsIn(ch.room).find(n => n.defId === nid) || null;
const npc = existing || this.spawnNpc(nid, ch.room, 1);
```
**为什么是复用**：① 不叠同名；② 又不丢掉这次遭遇（拿原实例再 `startCombat`，不像「直接不刷」会让回屋毫无动静）；
③ **不删实例**：判据用 `npcsIn`（过滤 dead），地上躺一条时照常刷活的，**倒地实例原样保留**供补刀/搜身/装袋（铁律 32）。
只限「同种不叠加」，换物种照刷；`game/data/*.json` 零改动。

**测试**：`tools/smoke-batch4.js` B12-1~6（反复进出活体恒为 1 / 描述无「毒蛇… xN」/ 回房活体 1 /
倒地实例保留可搜身）。**变异自证**：去重关掉 → 复现 `perEntry=[1,2,3]`、`毒蛇 x4` → B12-1/2/3 红。

1. **地块名看不全** —— `ui.js·mapHtml()` 的 `MAP_NODE=26` 与 `.mn-name{font-size:8px}` 是给桌面定的；

  其余一字未动（`touch-action:none`、`{passive}` 用法、捕获期 click 拦截机制均不变）。

> 交付：`tools/npc-skills.js`（身份规则表）· `tools/gen-npc-skills.js`（生成器）· `game/data/10_skills.json`（+7 功法）· `game/data/40_npcs.json` · `tools/smoke-npc-skills.js`（47 项）

**根因**：`gen-social.js` 生成 `npcv_*` 时只按 tag 给最粗的 `basic_*`，**从没做身份→功法分配**；
且现有 53 门功法除 8 门 `basic_*` 外全是门派/传奇专属，**非门派武人无「江湖通用」功法可挂**。

**修法（数据侧）**：新增 7 门「江湖通用」功法（长拳/江湖剑法/江湖刀法/齐眉棍法/卸力招架/轻身术/吐纳功，数值贴近 basic、只换身份不抬输出）；
`tools/npc-skills.js` 定「id → sect → tag」三级**显式**规则表，`gen-npc-skills.js` 生成期落回 `40_npcs.json`
（**只加不夺**：非 basic 的既有真功夫一律保留；判不出身份就不动）。
**为什么数据侧而非 B3 式运行时注入**：`world.js` 正被并行修读档缺陷（不碰共线文件）＋ 避免 B3 的「三条加载路径」隐患。

**效果（实测）**：攻击槽 `basic_*` 占比 **219/265 → 25/320**；`内功 43→84`、`轻功 69→153`、`招架 26→188`；
僧/道 26 人 **26 配内功、26 配轻功**；A 层 15 名宿 + 15 名 A 层故事人物全部持有非基本招牌招式。

**误判防护（B3 之 BLK-2 教训）**：① 判据只用显式字段（id/sect/tag），**绝不扫 name/desc 关键词**；
② 只加不夺、**不删任何既有字段（深比对 fields removed=0）**；③ 判不出就不动；④ 反例钉死「僧人不使刀」「书生不配内功」。

**同类排查**：全库 **49 处「兵刃系招式没兵刃」**（山贼有刀法没刀、捕快拿枪使刀法…）→ 补/换普通兵刃 **49→5**（余 5 为暗器/音波，全库无对应兵器道具）。

**测试**：`smoke-npc-skills.js` **47/0**（含**真打真看**：从战斗日志数出「和尚→韦陀掌 / 镖师→狂风快刀 / 剑客→江湖剑法 / 老叫花→打狗棒法 / 东方不败→辟邪剑法」）。
**变异自证**：让 `planForNpc` 恒 null（＝B8 未做）→ 实测复现基本拳脚/基本刀法 + 24 条武器惩罚 → **36/11 红**；还原 47/0。

## B18 · 内侍 gender 与 tag 矛盾 ✅ 已修（批次 6）

**根因（查实）**：`gen-social.js:380-381` 性别规则只对 `['courtesan','singer','consort','palace','nun','madam']` 强制 female，
**`eunuch` 不在「强制男」的白名单里** → 10 个内侍随机出 5 个 female。

**判据（为什么改 gender、不改 tag）**：① 内侍/太监**定义上只有男性**（tag+title 都写「内侍」）；
② 女性化 desc（耳坠/辫子/帔子）与画像「她」**由 gender 派生**（循环证据）；③ tag 是结构性分配（`eunuch` 恰 9 席、与 C 层批次「内侍9」完全对上）→ **tag 对、gender 错**。
**修法**：**只改 gender**（5 席 →male），tag/title/room 一律不动；派生的 desc 与画像 now（「她」）对齐男内侍口径。**不许两边都改**已遵守。
**测试**：`smoke-npc-skills` §⑥。**变异自证**：gender 改回 female → **45/2 红**。
> ⚠️ **与设计稿 `26-npc-skill-map.md §7.1` 分歧**：设计稿建议改 **tag**（保留 female），本工程依**生成器根因而改 gender**。列详报 §10 待裁决。
> ⚠️ 同源残留：`monk` 也没被强制为男（另有 4 个女「和尚」），不属本批，登记备查。
