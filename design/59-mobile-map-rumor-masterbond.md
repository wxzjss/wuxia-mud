## 一、主人点单 ①：手机端「细看此人」底部按钮排划不动

**病症**：`.modal-foot` 是 `display:flex; justify-content:flex-end` + 不换行。
「细看此人」底部最多 8 个按钮（打量/交谈/秘技/结缘/人物故事/拜师或请教/传功/挑战/关闭），
窄屏排不下就往左溢出 —— 而 **`flex-end` 的溢出区在 CSS 里是滚不到的**
（只有右侧溢出可滚），于是左边几个按钮在手机上**直接消失**，还没法划出来。

**改法**（`main.css` 的 `.modal-foot`）：
- 容器改 `justify-content: flex-start` + `overflow-x: auto`（+ `overflow-y: hidden`、`-webkit-overflow-scrolling: touch`）
- 靠**首个子元素的 `margin-left: auto`** 撑出右对齐 —— 排得下时靠右（桌面观感零改动），
  排不下时 auto 归零、从左边第一个开始，一路划到底
- `.modal-foot > * { flex: 0 0 auto }`：按钮不许被压扁（压扁了照样看不清）

两份副本同改（`game/src/renderer/css/main.css` ↔ `server/public/css/main.css`）。

## 二、主人点单 ②：地图上标出「往这个方向继续走是哪个区域」

**后端** `maplayout.computeRegionNeighbors(regionBoxes)` —— 纯几何的「四向最近邻」：
1. 目标块在指定方向上完全错开
2. 两者在**垂直方向上有交叠**（否则是斜对面，说「往东走能到它」就是骗人）
3. 并列时取**交叠更长**的那个；仍并列按 id 定序
4. **只留互认的那一份**（A 的东邻是 B ⇒ B 的西邻也得是 A）

   ⚠️ 第 3、4 步是被实测逼出来的：只按「距离最近」选时，
   两块并列会**按遍历顺序**选出一个 —— 结果 A 说东边是 B、B 说西边是 C，
   实测 **19 条对不上**。牌子是给玩家指路的，指错方向比不指更糟。

**前端** `ui.js mapHtml`：
- 在区域块之间那道缝里贴一枚 `.map-edge-hint`（「→ 华山派」），
  **只画东 / 南两个方向**（反向是同一道缝上的同一件事，画两遍就是叠字）
- 画布**外**的区域模式不画（邻居不在图上，牌子会挂在墙外）
- 抬头处的出口列表里，**跨出本地区**的出口额外标 `→区域名`（`.map-out`）

   ⚠️ 跨区域出口必须由**后端按真出口**算（`engine.mapView` 新下发 `crossExits`）：
   区域装箱在区域之间留 2 格空当，**跨区域的房间在图上从来不相邻**，
   前端拿坐标反查隔壁是谁永远是「查无此人」（实测一条都命中不了）。

**图例**加了「出界方向」一项（虚线点），不然玩家不认识那排牌子。

## 三、自拟 🅔：传闻的**消费端**（`core/rumorfeed.js` + `92_rumor_extra.json`）

传闻引擎本身早就齐了（生根 / 扩散 / 走样 / 衰减 / 打听），可**玩家做的事很少变成传闻**，
更没有「回头听到」的那一刻 —— 对玩家而言这套东西等于不存在。

补三件事：
1. **接线** `note(world, seedId, data)`：统一出口 + **同一桩事一天只传一回**（防刷屏）。
   新增 4 个种子：`rs_master_take`（拜师）/ `rs_sect_promote`（升位）/ `rs_skill_fuse`（创功）/ `rs_take_disciple`（收徒）
2. **当面对质** `chatterIn()`：走进你的事迹正被议论的地方，屏幕上多一句
   「檐下两个闲汉在说嘴：「听人说某某把两门功夫揉成了一门新的……」」——
   三闸防吵：一屋一天一回 / 屋里得有活人 / 这条传闻在本地区得有热度
3. **问你自己**：新指令 **`风声`** —— 「江湖上现在怎么说你」，
   念原话 + 标传到哪儿 + 标走没走样。这是主人要的「成长的外部反馈」

另把 `npcMemory` 的「听说你的事」**从泛泛升级成具体**：新增 `rumorLine()`，
见面时会**引用具体那一条**（「外头有人传——『……』。你跟我说实话，到底有没有这回事。」），
口气按交情分三档；同一条对同一人只说一次、两天最多一回。

**接线点**：拜师个人（commands）、门派升位（sectlife.afterPromote，三条晋升路共用一处）、
自创武学（customskill.fuse）。`doMove` 里接闲话（与匪类/讨教/寻仇同一层，传送不惊动人）。

## 四、自拟 🅕：师门情谊（`core/masterbond.js`）

`拜师` 原来只做两件事：记一笔 + 让「请教」必定成功 —— 师父本质上是台发武学的机器。
现在给他**四张嘴**（一次只说一件）：
1. **你带伤来** → 先看伤（**真的**上药：气血 +25% + 好感）——最要紧，排第一
2. **你坏了名声**（恶名 ≥30）→ 训你：「别报我的名字。」
3. **你登门太少** → 隔 15 天「还知道回来」/ 隔 40 天「你还记得这地方怎么走」
4. **你刚做成了事** → 嘴上不夸，手上有表示（给钱 + 好感），同一桩事只夸一回

**「你最近做成了什么」直接问传闻系统**（`rumorfeed.aboutPlayer` 找 3 天内的升位/创功/夺魁），
不另开一本账 —— 一处数据两处用，不会出现「系统没记、师父就装作不知道」。

新指令 **`请安 [师父]`**：一天一次，+好感并把「多久没来」的账清掉。
没有它，师父念叨你「还知道回来」就成了玩家**永远无法应对**的指责。

### 本轮踩的坑（都记着）
1. **`String.match` 带 `g` 标志会丢掉分组** —— `x[1]` 取到的是 `"class"` 的第 2 个字母 `l`，
   测试自报「标注里的名字是 l」。要用 `matchAll`。
2. **`canFuse` 在调用时就查等级与内力** —— 先问后给会得到「你现在 1 级 / 内力不够」的拒绝。
3. **邻居并列时不能靠遍历顺序**（见 §二）。「不报错但指错方向」比报错更难发现。
4. **`.modal-foot` 那种 `flex-end` + `overflow` 是 CSS 的经典陷阱**：
   左侧溢出不可滚。要么换行，要么 `flex-start` + 首元素 `margin-left:auto`。
