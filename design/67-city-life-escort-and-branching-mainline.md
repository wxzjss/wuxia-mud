## 二、城市补人（第一优先，纯数据，风险最低）

**目标**：四大名城 + 姑苏 + 江口码头，每城补到 **25~32 人**（密度追到 0.9~1.2/房），
荒野/蛮荒这类野外区补到 **6~10 人**（猎户、采药人、路倒、游方僧、落草的山民）。

**每一城的人要"像有活干"**，按城的性格分配工种，不要一律"摊主+伙计"：

| 城 | 城格 | 该有的人 |
|---|---|---|
| 襄阳 | 兵家要冲、南北通衢 | 守城兵、牙将、镖局分局、饭铺、马市、脚夫、说书人、探子 |
| 洛阳 | 旧都、牡丹花会 | 花匠、绸缎庄、画师、书院学子、退休老吏、青楼上宾 |
| 成都 | 蜀中富庶、远离兵祸 | 茶商、漆器匠、盐贩、川剧伶人、武馆、药商 |
| 长安 | 都城、官气最重 | 禁军、六部书吏、大理寺仵作、驿丞、胡商、贡院考生 |
| 姑苏 | 水乡、文人 | 船娘、评弹艺人、绣娘、书院祭酒、园林管事 |
| 江口码头 | 漕运 | 船帮把头、纤夫、税吏、货栈掌柜、水鬼（打捞人） |

**每条 NPC 都要写画像**（`role/origin/now/want/fear/voice/routine/marks`），
并且**按身份 + 落点选模板**（复用 `gen-portraits-bc.js` 的 `sectRoleOf` / `FIELD_T` 机制，
上次的口吻错配就是这条没做对）。新加的市井身份（兵/脚夫/纤夫/驿丞/仵作…）
要在 `T` 里各加一池，**不能落到 `GENERIC` 街坊池**（那正是上次"守阁弟子说街面上的话"的病根）。

**支线**：每座城 **≥3 条**城市支线（该城的人的事，不带出城），
以及 **≥1 条触发式支线**（走进某间屋/某个时辰才发生）。这是"活人感"的主要来源 ——
人再多，不会找你说话，也还是个布景。

**守卫**：`tools/map-check.js` 加一条「每座 town/capital 区域密度 ≥ 0.8 人/房」，
免得以后又摊薄。

## 三、官府巡逻（第二优先，新系统）

**规格**：
- 每座 `town`/`capital` 区域配 **2~4 名巡街**（`constable`）+ 1 名捕头（`official`）。
- 他们**按路线走动**（`schedule` 已经是现成的按昼夜换房间的机制，扩成「几个时辰换一处」）。
- 玩家**通缉度 `p.wanted > 0`** 时，巡街的会**盘查**（不是一上来就打）：
  盘查 → 玩家可选「报上名号 / 给钱打点 / 动手 / 跑」。通缉度越高，盘查越凶。
- 巡街的人**目击凶案会制止**（这条已有：`witnessTree` 里 `constable`/`official`/`escort`
  会真的加通缉度，2026-10-11 修好过）。
- **正邪分野**：官府路线的人（下面第五节）与他们有专属互动（报信、领差事）。

## 四、镖局 · 送镖（第二优先，新系统）

**规格**（建议，待主人点头）：

```
镖局：每座大城一间（总号 1 + 分局 N），门面房间 + 掌柜 + 镖头 + 趟子手
接镖：镖局柜台接「镖单」
      · 镖单有：起城 → 讫城、镖物（货/银/人/密函）、镖银、路引要求
      · 三种档：普通货（低险低酬）／重镖（易被盯）／暗镖（不能走官道，绕路）
押镖：接单后进入「押镖态」，沿路走（**不能飞往** —— 飞往要拦）
      · 路上按区域危险度掷**劫镖**：山贼/水匪/黑店/同行抢单
      · 劫镖是**真战斗**；镖物被抢走 → 要按契约赔（可欠债，接上已有的 debt 系统）
交镖：到讫城镖局 → 结镖银 + 声望 + 镖局好感；声誉越高，好镖单越多
连环：押过 N 趟且零失镖 → 镖局邀你入伙（新身份线）；失手太多 → 上黑名单
```

**与已有系统的接点**（都不新造）：
- 劫镖用现成的 `outlaw.js`（匪类遭遇）+ `combat.js`；
- 镖银/赔付走现成的money与debt；
- 「不能飞往」复用 `飞往` 指令里那道闸（加一个 `p.onEscort` 判断）；
- 镖局好感走 `social.js`。

**守卫**：`smoke-escort.js`（接单 → 路上劫镖 → 交镖/失镖 → 赔付，全程真跑）。

## 五、主线分化（最大的一块，分阶段）

### 5.1 要解决的三个问题（主人点名的）
1. **主线要贯穿所有地区（含皇宫）+ 名人参与** —— 现在主线三~五幕的舞台偏江湖，皇宫/衙门戏薄。
2. **每阶段每节点要有前置支线** —— 用来"垫人物"：让玩家在推进主线前，先跟这条线上的人
   打过照面、帮过忙、知道他的难处。没有前置，主线里出现的人就是"突然冒出来的工具人"。
3. **按出身 / 性别 / Mod 分化** —— 现在完全不分。

### 5.2 设计骨架

```
出身 → 选边（正 / 反 / 中立）
  ├─ 官宦子弟(noble) / 山门弃婴(monastic) 等「有根」的出身 → 正派线：庙堂 + 门派
  ├─ 血仇遗孤(grudge_orphan) / 楼里新来的(brothel_sold) → 反派线：仇与债
  └─ 其余 → 江湖线（中立）：只看利害，不看正邪
性别 → 同一节点的**处境**不同（不是换一套任务，是同一件事的两种走法）
  · 例：进青楼查案 —— 男角要花钱打通，女角能被鸨母收作"姑娘"从里查
  · 例：考场/武举 —— 女扮男装、被人做局，走法不同
Mod 出身 → **中立主线**：玩家不再是"天选之人"，而是"一个来路不明的人"，
          谁都能合作、谁都能翻脸，结局不预设正邪
```

### 5.3 分期（每期都可独立验收，别一口吃成胖子）

| 期 | 内容 | 验收 |
|---|---|---|
| **P1** | 立「主线状态机」：`p.mainline = {line:'orthodox'\|'outlaw'\|'neutral', act, node, flags}`；出身/性别在开局定 `line`；主线的每一步都读它 | `smoke-mainline-branch.js`：三种出身开局 `line` 不同；同一节点三种 line 的可得动作不同 |
| **P2** | 给每一幕的每个节点配 **1~2 条前置支线**（先做第 1 幕：约 8 条），支线完成才解锁节点 | 前置没做完时节点**明确说不解锁**（不静默） |
| **P3** | 皇宫/衙门线：宫廷三节点（面圣／廷议／天牢），名人（皇帝/太后/大理寺卿）卷入 | 主线可走到皇宫且不改动既有幕次结构 |
| **P4** | 性别分化：同一节点两套解法（复用 `p.gender`，加 `require` 分支） | 同一节点男/女可得动作不同，且**都能通关** |
| **P5** | Mod 出身 → `line='neutral'` 的独立主线 | 中立线全程不锁正邪结局 |

**为什么这么排**：P1 是所有分化的地基（没有 `line` 字段，后面每写一条分支都要再改一遍世界文件）；
P2 是"归属感"的主要来源，优先级高于 P3/P4/P5 的花样。

### 8.6 按钮审计（`tools/button-audit.js`，主人点名要的）

三层：**静态映射**（按钮指向的指令/面板存在吗）+ **真渲染**（每个面板点开有没有东西）
+ **真执行**（按钮要发的指令在后端真跑一遍，判据是响应里不许出现「是什么指令？」这句兜底文案）。
带 **⓪ 守卫自证**（喂一条假指令必须被抓住）。

**它立刻抓出一个真崩溃**：`describeItem` 里一直在调 `typeCN()` / `statCN()` ——
而这两个函数**全仓从来没定义过**。「任何带 `type` 的物品，一点『细看』就 ReferenceError」，
被引擎 catch 兜住只在控制台留一行 —— 玩家看到的是「点了没反应」。全库带 `type` 的物品 190 件。
已补上**唯一一份**中文名表（`ITEM_TYPE_CN` / `EQUIP_STAT_CN`），并把 `engine.js` 里
抄的那一份字面量改成引用它（两份表就是漂移的开始）。

实测：19 个面板全部渲染出非空内容、17+ 条按钮指令全部真跑通、81 条指令无一条是死按钮。
