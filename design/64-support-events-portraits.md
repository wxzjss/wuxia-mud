## 1. 战斗辅助武技：内功 / 轻功 / 招架里那些「保命招」

**主人要的**：内功轻功招架也该有**能在战斗中用的辅助性武技**。

原先武技（`skill.moves[]`）只有一条通路 —— `oneAttack` 打人。
保命招没有伤害，塞进那条路等于白送对方一下。所以这里**单开一条通路**：

```jsonc
// 95_support_moves.json 里的一式
{ "id": "sup_huti_1", "name": "气墙", "mpCost": 24, "cooldown": 3,
  "support": { "kind": "def", "value": 26, "turns": 3,
               "text": "你把气沉到脚下，一层无形的东西绷在身外。…" } }
```

`world.js` 的武技分支里，`mv.support` **排在 `oneAttack` 之前**判断，支持六种：

| kind | 效果 | 谁 |
|---|---|---|
| `def` / `dodge` / `parry` | 挂 buff（走 `addBuff`，与装备/内功加成同一套） | 护体真气 / 掠影 / 铁桥功 |
| `guard` | 复用「防御」那条 `battle.guardTurns`（本回合伤害减半） | 卸力法 |
| `heal` / `mp` | 当场回气血 / 回内力（不越上限） | 混元一气功 / 归元诀 |
| `escape` | 不掷骰**必定脱战**，与「逃」走同一个 `finishCombat` | 踏雪无痕 |

三条纪律：

- **状态只在「这一局」算数**：`finishCombat` 里清掉所有 `sup:` 标记的状态。
  不清的话玩家打完还挂着「+26 防」，等于白拿一份属性进下一场。
- **状态要会过期**：玩家走「武技/防御/用物品」三条分支**不经过 `combat.step()`**，
  玩家侧 buff 的回合数从来没人减（这是既有的口径，不是本轮引入的 bug）。
  所以这里**只递减自己打的 `sup:` 标记**，不碰别人的 dot / 蓄势 —— 一刀切
  `tickBuffs` 会把 dot 的语义一起改掉，那是另一个口径的事。
- **不打人**：辅助招走自己的分支，不会顺手往对手身上招呼一下。

**给玩家一条真能学到的路**（否则就是死数据）：九门按门派气质分给**六城武馆教头**，
玩家在武馆「请教 `<教头> <招法名>`」花束脩即可学。

> ⚠️ 改教头的 `teach` 时踩了**数组 replace 语义**：`teach` 是数组，
> 新写必须把原来那 12 门基础武学**抄全**，否则教头会「只会教辅助招、连基本拳脚都不会教了」。
> 测试里专门有一条守它。

## 2. #109 · W5 世界事件库：12 → 68 条

按 `design/27 §2.3` 的清单补齐八类：

| 类 | 条数 | 例 |
|---|---|---|
| 江湖恩怨 | 12 | 仇家堵路 · 下战书 · 半夜放火 · 酒里下药 · 仇家求和 |
| 官府缉拿 | 8 | 官道盘查 · 悬赏告示 · 查夜 · 城门查验 · 缉捕 |
| 天灾饥荒 | 6 | 蝗灾 · 河堤决口 · 粮价上涨 · 大旱 · 时疫 |
| 秘境现世 | 6 | 思过崖后洞 · 古墓现世 · 剑冢出土 · 藏经阁失窃 |
| 门派纷争 | 10 | 两派械斗 · 掌门换人 · 镇派之宝失窃 · 联手追杀你 |
| 市井琐事 | 12 | 催债的上门 · 当街斗殴 · 说书人 · 出殡 · 赌坊开庄 |
| 商路货殖 | 8 | 镖银被劫 · 商队遇匪 · 走私被发现 · 山贼设卡 |
| 边关烽火 | 6 | 边军征丁 · 胡骑南下 · 烽火台举烟 · 雪封山 |

四条工程纪律（都是踩出来的）：

1. **不许写 `combat:`** —— 跨日没有战斗上下文，实测会抛 `reading 'inCombat'`。
   测试里有一条静态扫描守着。
2. **一天最多报两件**：68 条里三四十条带 `chance`，不限流的话运气不好一天连报四五件，
   世界会像跑马灯。实现是「打乱顺序后取前两件」—— 打乱是为了公平，不按数组顺序让前几条永远优先。
3. **条件必须用引擎认识的键**：`evalCond` 对未知键**不报错**（默认放行），
   写错一个条件名就是「永远成立 / 永远不成立」而且一声不吭。测试里有一份白名单逐条比。
4. **引用的房间 / 区域必须存在**：写错一个字母 = 这条事件永远不触发。测试逐条查。

### 2.1 顺带修好的一处「变量没人写」

事件条件读三个变量，而它们**全仓没有任何地方写过**：

| 变量 | 真身 | 症状 |
|---|---|---|
| `rumor_heat_max` | 活跃传闻的最高热度 | 「造你的谣」（≥30）永不触发 |
| `rumor_heat_bad_max` | 其中**对你不利**那一批的最高热度 | 「托人递话」「联手追杀你」永不触发 |
| `wanted` | `p.kidnap.wanted`（律罪档 0~100） | **「大赦」从上线起就没触发过**（这条事件早就在库里） |

修法：`dailyRumorTick()` 末尾统一归一（每跨日一次），另外同步 `has_debt`
（←`p.kidnap.debt`）与 `family_count`（←正妻+妾+结义），供「拿家眷做筏」那类事件读。

> 口径：`_max` 认全部传闻；`_bad_max` **只认 `seed.polarity < 0` 的**——
> 行善传得越广不该让你被追杀（与 `design/27 §5.5.4` 的分工一致）。

## 3. #112 · 众生画像三层补员

| 层 | 补员前 | 补员后 | 来源 |
|---|---|---|---|
| A | 49 | **57** | `96_portraits_a.json`（原著具名 8 席 + 江南七才子等 9 人的缺栏目补齐） |
| B | 3 | **60** | `97_portraits_bc.json`（生成器 `tools/gen-portraits-bc.js`） |
| C | 86 | **161（满）** | 同上 |

**为什么用生成器**：B/C 层多是「街面上的人」，他们需要的是**各有各的活计与心事**，
不是各有各的传奇。做法是每个身份写一把**具体的**句子，再按人物自身的真实字段
（姓名 / 身份 / 所在区域 / 性格 / 喜好 / 邻居 / 关系）拼装。两条纪律：

- **确定性**：选句只用 `id` 的哈希，不掷骰 —— 重跑必须一模一样，否则数据会漂。
- **只补空白**：只给没有 `portrait` 的人写，已有画像一个字不动。

**反面形象**（主人亲自点名的那一条）：26 席（V01–V26）全在册，且都答满了
「他最初为什么走到这一步 / 他现在自己怎么看 / 有没有一个自己也后悔的瞬间 / 还能不能被拉回来」，
没有一条是「我是坏人」。测试里有一条专门守这个。

## 4. 画像判定的剧情与功能：抓到三处**静默失效**

主人要求「看一下根据 npc 画像背景设定来判定的剧情以及功能是否存在问题」。查出三处，
**全是不报错、只是不发生的**那一类：

### 4.1 `portrait.hooks` 全仓没有消费点

51 个人写了「故事钩子」（`{id,title,type,trigger,seed,rewardHint}`），
**没有任何地方读它** —— 玩家一个也问不出来。已补：

- 话题进「询问」面板（`engine.askTopicsOf`），交情不够时标注「先替他办点事」；
- `ask <人> about <钩子标题>` 或泛问「有什么难处」→ 条件满足就说 `seed` + `rewardHint`
  并记进 `npc.pstate.hooks`；不满足则**不撒谎也不白给**，把话头留下。

### 4.2 hooks 的 `trigger` 读一个**没人写过**的变量

钩子条件一律写 `{ var: 'trust_<npcId>', op:'>=', value:N }`，
而 trust 真身是 `npc.pstate.trust` —— 名字对不上，`p.vars` 里那个键从来是空的，
**条件恒不成立**。新增 `world.syncTrustVar(npc)` 在读写交界处归一
（与 `faction_power_*` 是同一个坑、同一种处理）。

### 4.3 `taboo`（禁忌）与 `hooks`（托付）两栏打架 —— 45 处撞车

画像里 `voice.taboo` 是「外人提不得」，`hooks[].title` 是「他信得过你才托给你的事」，
写手把同一个心结写进了两栏（岳不群：taboo「弟子」/ 钩子「下山的那个弟子」）。
结果是：**玩家照他自己给的钩子标题去问，先被扣 15 点好感**。判定收两道口：

- **钩子标题不算踩雷**（以钩子为准）；
- **单字禁忌不算**：数据里有人把 taboo 写成「手」「脚」「塔」，
  一个字能盖住半部词典，那不叫禁忌，那叫碰瓷。

## 5. 性格 ↔ 画像语气：从「大面积对不上」到 23/0

`tools/persona-portrait-check.js` 原先两处红：

- **画像语气归不了类**（一大批新画像的 tone 词不在词表里 → 核对直接跳过，等于没核对）；
- **带画像的人性格与语气不一致**（岳不群画像「谦」而性格是阴鸷、洪七公画像「油」而性格是豪爽…）。

修法两条：

1. `personality.js` 的 `TONE_KW` **在末尾补**若干规则（豪爽/侠义/油滑/暴躁/阴沉/木讷/冷漠/温婉）——
   放末尾是为了前面五条优先级不变、老画像判定一个字不动；
2. **画像的 tone 从性格派生**（生成器里的 `PERSONA_TONE`）——
   tone 是「说话调子」，本来就该跟着性格走，不是跟着身份走。
   第一版把 tone 写死在身份模板上（掌柜一律「和气」），就出现「一个豪爽的铁匠被写成闷」这种自相矛盾。

> 两个词表必须对得上：生成器写什么、`TONE_KW` 就得认什么。改一边要改两边（已在两处都写了交叉注释）。

## 6. 据画像写的九条支线

挑的是画像写得最实的九位：**江南七才子（唐寅 / 祝允明 / 文徵明 / 周文宾 / 徐祯卿 / 张灵 / 都穆）
+ 花魁柳含烟 + 提学周学政**。一句话原则：**一个人想要的东西，就是他请你帮的忙。**

| 支线 | 从他画像的哪一条来 |
|---|---|
| 送给听雨轩的那幅画 | 唐寅 want「把一幅画送到该到的地方去」 |
| 念一遍那篇序 | 祝枝山 want「有个人肯听他念一遍新写的序」 |
| 退回去的那张贴子 | 文徵明「谁来求应酬画一律回绝」 |
| 唱完再掀冠 | 周文宾 want「找个人跟他合一出戏」 |
| 一句真话 | 徐祯卿 want「想听一句真话——不是恭维，是评语」 |
| 一坛不带目的的酒 | 张灵 want「想再跟唐寅喝一场——不带目的的那种」 |
| 缺掉的那一页 | 都穆 want「有一卷书的缺页，他找了七年」 |
| 攒了七年的东西 | 柳含烟 want「存够赎身的银子」 |
| 落卷上的那行批语 | 周学政 want「看看这一代还有没有人肯老老实实把书读下去」 |

三条纪律：**目标只用 `kind:'room'`**（全库只有 room 与 item 类目标有推进点）；
**房间 id 必须真实存在**（生成时逐个校验）；**抉择走 `menu` 且两边都有代价**。

## 7. 回归：103 套全绿，其中 6 套是「契约更新」

回归第一次跑出 7 套红，逐条判定后**只有 1 处是真 bug，6 处是测试的口径该跟着改**：

| 套 | 判定 | 处理 |
|---|---|---|
| `ai-flavor-check` | **真命中** | 一句「没抬头，只说了句」撞「观察腔（不X只Y）」→ 改写成两句 |
| `smoke-sidequest` | 口径 | 写死「61 的 52 + 67 的 10」→ 改成**把所有数据文件的 hk_ 一起数** |
| `smoke-wuguan` | 口径 | 「列表里全是基础武学」→ 教头现在**另授辅助武技**，改为「12 门基础一门不落 + 另授 sup_」 |
| `smoke-portrait-batch` | 口径 | taboo 断言 → 改为挑「长度≥2 且不撞钩子标题」的禁忌词来验 |
| `smoke-portrait` | 口径 | 「无画像 NPC 不多出 npcsact 行」→ 改按**这个人自己的名字**过滤（同屋别人有画像了） |
| `smoke-round3` M-5 | 环境 | 官方示例与站点不一致 → 跑 `seedOfficialMods()` 同步 |
| `smoke-mod-trace` | 环境 | 清理一次删 52 个文件触发运行环境的**批量删除保护** → 拆成两步删（先子目录再外壳） |

> 教训与前几轮一致：**测试报红先判「是不是口径该变」**。
> 这轮 6 套里有 5 套是我改了正当行为后测试仍在守旧契约 —— 不改测试就等于把新功能判成 bug。
