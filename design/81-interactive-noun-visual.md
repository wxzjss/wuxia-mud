## 一、记号语言：一句话说清

> **「点 = 能下手，线 = 能过去。」**

- **可交互名词**（碗）：**字下一颗朱点**——中文排版里原生的**着重号**，古人拿朱笔点读就是这个动作。
  它落在**字下面，一颗一颗**，说的是"这个词你能动它"。
- **出口**（北/南/江南城）：**字下一道虚线**——**垫在字底下的一条线**，说的是"这个词你能穿过去"。

一个是**点**，一个是**线**。玩家不用记规则：
**字下面有点的，点了会做事；字下面有线的，点了会走路。**

### 1.1 为什么是点，不是别的

按你我上一轮定下的通用判据——**连续量用可递增通道，离散量用可枚举通道**：

- 「这个词能点吗」是**离散**（能 / 不能）→ 走**可枚举通道**：形状。
- 「点了是做事还是走路」也是**离散**（两类）→ 形状要能枚举出**两档**。

**点 / 线**正好是两档可枚举的形状，且：
- 去色截图上照样可辨（形状不依赖颜色）→ 满足我的硬约束；
- 色觉差异下照样可辨；
- 不是网页链接（链接是**实线**），也不是网页按钮（按钮是**框+底**）；
- 是中文排版**本来就有**的记号，不往文字 MUD 里塞 UI 语汇。

### 1.2 明确不用的四种手法（各写理由，免得后来的人又捡回来）

| 手法 | 不用 | 理由 |
|------|------|------|
| 底色块 / 边框 / 圆角 | ❌ | 就是现在 `.hl` 的样子（`.log-line .hl` 整段 + `.log-line .hl:hover`）。**这就是"做成网页按钮"**。改成点之后整段删掉。<br>🔴 **2026-10-13 补（83 走查查出，是我自己漏的）**：`.log-line.action .hl` 是**独立选择器**，不在上面那一段里，它也带 `background` 且把 `border-bottom-style` 改成 **dashed**。<br>⇒ **删除清单必须单独加这一行**，否则落地后会留下一个虚线底的 `.hl`，正好撞出口的虚线（违反 `81/N-V-7`）。按选择器找，别按行号。 |
| 字号变化 | ❌ | 日志区是等宽文本流（`.log` 14px / 1.8），跳字号就跳行高，整块文本跟着抖。同 `79 §〇.1`。 |
| 字重（500/600） | ❌ | 无 webfont，500/600 在中文衬线上是**合成伪粗**，14px 下糊。同 `76 §4.1`。 |
| 斜体 | ❌ | 合成斜体，同上。 |

## 三、逐项规格

### 3.1 `.hl` —— 名词记号

```css
.log-line .hl {
  /* ① 按钮复位：不复位就是个按钮 */
  display: inline; font: inherit; line-height: inherit;
  margin: 0; padding: 0; border: 0; background: none; border-radius: 0;
  color: var(--noun-ink);
  cursor: pointer;
  /* ② 主判据：着重点（形状，不依赖颜色） */
  -webkit-text-emphasis: filled dot var(--noun-dot);
          text-emphasis: filled dot var(--noun-dot);
  -webkit-text-emphasis-position: under right;
          text-emphasis-position: under right;
  transition: color .14s, text-decoration-color .14s;
}
/* ③ 兜底：认不出 text-emphasis 的引擎 → 给一条实线（仍是朱色，与出口的虚线+灰不同族） */
@supports not (text-emphasis: filled dot) {
  .log-line .hl { border-bottom: 1px solid var(--noun-fb-line); }
}
```

**几何**

| 项 | 值 | 说明 |
|----|----|------|
| 字号 / 行高 / 字族 | **继承，不得覆写** | 日志等宽流，跳了就抖 |
| 字重 | **400** | 无真 bold |
| 斜体 | **normal** | 合成斜体糊 |
| 左右 padding | **0** | 有 padding 就撑开字距，中文排版里很难看 |
| 点大小 | `--noun-dot-size: .40em` | 由浏览器按字号算，不写 px |

**颜色（辅助通道，不是主判据）**

| 项 | 变量 | 暗色实测 | 浅色实测 |
|----|------|---------|---------|
| 词本身 | `--noun-ink: var(--ink-1)` | 对纸 15.72 / 14.52 ✅ | 对纸 15.03 / 16.71 ✅ |
| 词 vs 周围正文 | — | 对比 **1.147** / ΔL\* **5.2** | 对比 **1.144** / ΔL\* **5.4** |
| 着重点 | `--noun-dot: var(--red)` | 对纸 **4.60** / 4.24 ✅（图形 ≥3） | 对纸 **6.67** / 7.42 ✅ |

⚠️ **词色只准亮一档，不准再高。**
从 `78 §2.1-bis` 来的教训：对比 ≥1.35 就变成"另一个层级"，玩家会把它读成标题而不是正文里的一个词。
本方案的 1.14 / ΔL\* 5.2 是"墨稍微浓了一点"，不是"换了一种字"。

**状态清单（`.hl`）**

| 状态 | 视觉差异（只描述差异，不改交互逻辑） |
|------|--------------------------------|
| 默认 | 字下朱点；字色 `--noun-ink`；无下划线、无底、无框 |
| 悬停 `@media (hover:hover)` | 加一条 `text-decoration: underline` + `text-decoration-color: var(--noun-dot)` + `text-underline-offset: 3px`。**只加线，不改点、不改色、不动排版** |
| 按下 `:active` | 瞬时 `background: var(--tint-red)`（极淡朱底，.14s）。**仅存在于按下那一瞬**，不是常态底 |
| 聚焦 `:focus-visible` | 与悬停同式 **+** `outline: 1px dashed var(--noun-dot); outline-offset: 2px`。**键盘聚焦不能只靠颜色**，所以给虚线轮廓（形状） |
| 已展开 `aria-expanded="true"` | **词本身一个像素都不变。** 只用"下面多了一小行"这件事表达——**位置通道，不是样式通道** |
| 无动作 | **不渲染 `.hl`，当普通文字。** 后端没给 `actions` 的名词一律不高亮（`openInteractMenu` 已有 `if (!acts.length) return;`，保留） |

**🔴 L1 一个字都不说（与文案规则合流后的硬约束）**

游有方定了一条分界线，我完全接受，而且我的方案本来就是这个形状：

> **屏幕永不主动写出一条指令。屏幕能主动做的只有一件事：把那个词点亮。指令名只在玩家点了之后才出现。**

落到视觉上有两条：

- **默认态只有着重点，没有任何文字**——没有角标、没有小气泡、没有"可点击"字样。
  它只是"这个词长得不一样"。
- ⚠️ **必须删掉现有 `title="点击查看能做什么"`**（`ui.js:544`）。
  那是 hover 冒泡提示，**属于"屏幕主动说话"**，违背这条。
  无障碍信息改走 `aria-label`（读屏念，屏幕不显示）。见 `81/N-V-26`。

另：`cond` 不通过 / `once` 已用掉 ⇒ **那个词根本不亮**。
同一个词第一章辰时亮、第三十天路过不亮——它不是永久标记，是随剧情开关的。见 `81/N-V-24`。

### 3.2 `.hl-tip` —— 点了之后出现的提示行

**形式：行内展开，不是浮层，不是全屏遮罩。**

为什么：
- 浮层（tooltip）在手机上小、被手指挡、且离开就丢；
- 全屏遮罩（`choices`）把正文盖住，是"网页弹窗"，不是 MUD；
- **行内展开**贴着那句话、在主文本流里、窄屏照旧可见——三条全中。

```
  灶上蹲着只粗瓷碗，碗沿豁了个口。
  ··················●··············        ← 字下一颗朱点（着重点）
  └ 端碗                                    ← 提示行，紧贴这一行下面
```

**DOM（新增，挂在 `.log-line` 内作最后一个块级子元素）**

```html
<div class="log-line …">
  …灶上蹲着只粗瓷<button class="hl" data-hl="3"
     aria-expanded="false" aria-controls="hl-tip-3">碗</button>，碗沿豁了个口。
  <div class="hl-tip" id="hl-tip-3" hidden>
    <button class="hl-tip-cmd" data-cmd="端碗">端碗</button>
    <span class="hl-tip-note"><!-- 游有方填 --></span>
  </div>
</div>
```

| 项 | 值 | 说明 |
|----|----|------|
| 位置 | `.log-line` 的最后一个块级子元素 | 保证它**在主文本流内**，不在 `#scene` / `#sidebar` / 任何弹层 |
| 左缩进 | 首选 `padding-left: <该词相对本行的 offsetLeft>px`；量不到 → `--tip-indent-fb: 2em` | 视觉上挂在那颗点下面，关联明确 |
| 字号 | `--tip-font: 12.5px` | ⚠️ **这是 UI 旁白，不是叙事**。叙事行一律 14px 不许动（同 `79`）；旁白可以小，它不承担"文本流"语义 |
| 行高 | `--tip-line: 1.5` | |
| 上间距 | `--tip-gap: 3px` | 与 `.log-line` 的 `margin-bottom: 3px` 同值，不另起一套 |
| 正文色 | `--tip-ink: var(--ink-3)` | 暗 5.63–6.10 ✅ / 浅 4.94–5.49 ✅ |
| 指令色 | `--tip-cmd` | 暗 `#b98f34` 5.48–6.16 ✅ / 浅 `#7d6018` 4.74–5.81 ✅ |
| 底色 / 边框 / 圆角 | **一律不给** | 它是一行小字，不是卡片 |
| 宽度 | 不超出所在行；窄屏自动折行 | |

**提示行里放几个指令**

游有方扫过全库：**单房 `action` 最多 3 条**，229 间有 action 的房里 209 间只有 1 条
（见 `design/82-interactive-noun-hints.md` §1.2 / §3.3）。
⇒ **1–3 个全部并列在提示行里**，每个都是可点的 `.hl-tip-cmd`。
⇒ **没有 ">4 个走 `choices` 菜单" 这一档——那条路径永远不会触发，删掉，不留死代码。**
（顺带：现有 `choices` 菜单项只有 label + hint 没有 cmd，`ui.js:108-110`；既然不走它了，这条不必改。）

**⚠️ 与文案规则的对接（2026-10-13 合流，取代本条原来的写法）**

游有方定的是三层：L1 点亮（不说话）/ L2 点击单 / L3 回执教，且 **L2 在 209 间房里不出现**（单动作直接执行，教的事交给 L3）。
我原写的是"任何情况都先提示后执行"。**两边合流后按可逆性分流**：

| 动作性质 | 点那个词之后 | 谁教指令 |
|---|---|---|
| **可逆 / 无害**（端碗、挪缸、打水、交谈、请教、细看） | **直接执行**，不打断、不弹窗 | **L3**：回执末一句「下一次，心里默念『XX』就行」（游有方的文案） |
| **不可逆 / 有代价**（偷袭、攻击、绑架、偷窃、丢弃、叛门） | **先展开提示行**，提示行里那颗指令点了才执行 | **L2**：提示行内 |
| **多动作（2–3 条）** | 一律先展开提示行，并列几个指令 | **L2**：提示行内 |

理由：**点亮 = 邀请点击。** 一个词被点亮之后，玩家第一次点它多半是试探；
如果这一下直接打出「偷袭」，是不可撤销的。**至少要有一条看得见的刹车。**
可逆动作不需要这道刹车（端个碗错了没有代价），不可逆的需要。

⇒ `81/N-V-21` 已按这个口径改写：判据从"任何情况"收窄到"不可逆动作"。

**什么时候收起（四条，全由用户动作触发）**

1. 再点一次同一个 `.hl`
2. 点了别处的 `.hl`（旧的收、新的开）
3. 点了提示行里的 `.hl-tip-cmd`（执行 → 收）
4. 点日志空白处 / 按 Esc

🔴 **不设自动超时。**
自动消失 = 玩家还没读完就没了。这是 `78` 里 `.tb-bar span` 那一类"不报错、就是看不见"的病，
我不在同一个项目里开第二例。见 `81/N-V-19`。

**互斥**：同一时刻 `#log` 里只允许一张提示行展开。见 `81/N-V-11`。

**其它收起时机**：执行任意指令后（日志重绘，旧的上下文已经不成立了）。见 `81/N-V-20`。

### 3.3 `.hl-tip-cmd` —— 提示行里那颗可点的指令

| 项 | 值 |
|----|----|
| 元素 | `<button>`，带 `data-cmd`（**非空**，就是玩家该敲的那串字） |
| 字号 | 13px（比提示正文 12.5px 大半档，为的是"这串字是能敲的"） |
| 字族 | `--font-ui`（与指令输入框同族，暗示"这是指令"） |
| 颜色 | `--tip-cmd` |
| 触屏高度 | `min-height: --tip-cmd-min-h: 40px`（≤820px 生效，与 `.qb-btn` 一致） |
| 状态 | 默认（朱金色字，无底无框）／ 悬停（`text-decoration: underline`）／ 按下（`--tint-red` 极淡底）／ 聚焦（虚线轮廓） |

⚠️ **`data-cmd` 绝不能命中 `PANEL_CMDS`。**
`panelForCmd()`（ui.js:3858-3861）是**整串精确匹配**，命中了就被前端拦成"开面板"，后端根本收不到。
「端碗」安全；但「装备」「地图」「任务」「飞往」「麻袋」这些都在表里（ui.js:3806-3855）。
⇒ 见 `81/N-V-14`：这张表是**可直接跑的判据**。

### 3.4 与 `.exit-inline`（出口）的区分

| | 可交互名词 `.hl` | 出口 `.exit-inline` |
|---|---|---|
| 记号族 | **点**（着重点，逐字一颗） | **线**（虚线下划，垫在词下） |
| 兜底族 | 实线（朱） | 虚线（灰 `--ink-4`） |
| 底 / 框 / 圆角 | 无 | 无（九宫格里那份是白字深底胶囊，属另一处语境，不动） |
| 点了做什么 | 做一件事 | 走一段路 |
| 提示行引导词 | 由游有方定 | 由游有方定 |

**区分的硬判据**：两者**不能同族**。`.hl` 的点/实线 与 `.exit-inline` 的虚线，
在 `border-bottom-style` + `text-emphasis-style` 两个属性上**不允许全等**。见 `81/N-V-7`。

⚠️ **出口行不挂名词**：`.log-line.exits` 是 `display:flex; justify-content:center`，
在里面插提示行会把九宫格顶歪。见 `81/N-V-8`。

### 3.5 密度与重复（噪音上限，视觉侧的）

- **同一行 `.hl` ≤ 4 个。** 一行里五个词都在闪点，等于没有点。见 `81/N-V-22`。
- **同一动作不许在两处高亮。** 描写里的「碗」和「此地可做」那一行里的「碗」

  见 `81/N-V-23`。
  （保留哪一处归游有方/主程序；我要求的是**不许两处都亮**。）

### 3.6 触屏（≤820px）与热区

- **触屏没有 hover**，所以默认态的朱点**必须**自己说清楚——这也是它不能是 hover-only 下划线的原因。
- 热区外扩**不改排版**：`.hl { position: relative }` + `.hl::before { content:''; position:absolute; inset: calc(-1 * var(--hl-hit-pad)) -3px; }`，

- 提示行里的 `.hl-tip-cmd` 在 ≤820px 下 `min-height: 40px`。

⚠️ 一条老规矩：改 class 一律**追加**（`cls +=` / `setAttribute`），不许 `node.className =`。

## 九、一句话

> **点 = 能下手，线 = 能过去。**
> 词下一颗朱点（中文原生的着重号），点开是紧贴那一行的一小行提示，
> 提示里那串指令**自己就能点**——
> **"提醒玩家该敲什么"和"直接替他敲了"是同一条路，不是两步。**

这一条正好接住主人那句"第一章剧情就是天然的新手教程"：
玩家每点开一次提示就学一个指令，看三次就学会自己敲了。
**提示本身即教程，不需要第二套 UI。**
