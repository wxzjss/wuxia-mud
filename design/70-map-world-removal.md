## 二、删掉了什么（逐条对账）

### 前端渲染（`game/src/renderer/js/ui.js`）

| 删掉的 | 原用途 | 谁替它 |
|---|---|---|
| `let mapScope` | 'region' / 'world' 视野开关 | —（只剩 region） |
| `let mapLevel` | 分层档（数字，原始 z 值） | —（层信息改由 ▲/▼ 角标承担） |
| `let pendingPanRegion` | 跨渲染的「换区平移」目标 | —（没有别区可平移） |
| `.map-scope` 里的切换器 | 「当前区域 / 天下全图」两颗按钮 | 改成一句「只显示你脚下这一片：XX」 |
| `.map-level` 整条 | 层按钮（响应式，数据有几个 z 就几颗） | `.mn-lv` 角标（▲/▼）保留 |
| `[data-scope]` / `[data-level]` / `[data-pan-region]` 三处 onclick | 切视野 / 切层 / 平移 | — |
| `centerMapOnRegion()` 及其导出 | 点区域名把视角平移过去 | — |
| `edgeHintHtml` + 边界路牌生成整段 | 本区 ↔ 邻居区那道缝上的「→ XX」 | 抬头 `.map-out` 的「出口 → 区域名」 |
| `data-cx` / `data-cy` | 平移锚点（从 DOM 反读坐标） | —（元素本体保留，当语义容器） |

**取景框**：`b` 恒为「本区房间的紧包围盒」——那一刀「裁掉别的区域」不能省，
省了就变成一个大画布里缩着一个小区域。

**区域底色块**：从「34 个区域的定位锚」退化成「本区一块的语义容器」，
`data-region-box` 只剩 1 个（测试靠它断言「图上只有本区」）。

### 样式（`game/src/renderer/css/main.css`）

* 删 `.ms-btn` / `.ms-btn.on` / `.ms-btn:hover`（视野胶囊）
* 删 `.map-level` / `.ml-title` / `.ml-btn` / `.ml-btn.on` / `.ml-num` / `.ml-warn`
* 删 `.map-edge-hint` / `.map-edge-hint .meh-arrow`
* **保留** `.map-scope`（容器还在，装那句说明）、`.mn-lv`（▲/▼ 角标）

### 保留（**故意的**，别下次顺手删）

* **`.mn-lv` 角标**：「这屋有楼梯」是走路的关键信息。地图只画平面那一层，
  没了角标玩家会以为楼上楼下那些房间凭空消失。
* **房间 tooltip 里的层名**（`lvName` → 「三层」「地下2层」）：层信息的第二条通道。
* **`maplayout.computeRegionNeighbors` / `regionBoxes[].neighbors`**：
  纯数据，留着不碍事，将来若想开回「出界提示」随时能用。
  对应 `map-edge-check` 第 2 节**保留**了后端 neighbors 的断言。

## 三、守卫怎么跟着改（关键：**反转口径**，不是删掉）

砍功能最容易犯两个错：① 留着旧断言 → 天天报红；② 干脆删掉守卫 →
下次谁把它接回来都没人拦。这一批一律走**第三条**：把断言反转成
「**它真的不在了**」，并补上「**没白丢的信息还在**」。

| 脚本 | 原口径 | 新口径 |
|---|---|---|
| `smoke-map-level` | 分层响应式、切层换内容、`mapLevel` 状态 | **整体重写**：分层/视野切换器真的没了 ＋ ▲▼角标与 tooltip 层名还在 |
| `smoke-map-link` | 路牌不遮挡地块名 | D 节反转成「路牌真的没了」；C-1 口径同步 |
| `map-edge-check` | 世界地图 ≥20 块路牌、箭头不叠字 | 3/4 节反转成「路牌/箭头/源码/CSS 四处都清」 |
| `mapguide-check` | 「有视野切换栏」 | 反转成「切换器没了 ＋ 那句说明还在」 |
| `map-redesign-check` | 「`data-cx/cy` 还在（平移靠它）」 | 反转成「只剩一个区域框 ＋ 锚点与函数都删了」 |

### 顺手挖出的一个**假红**（值得记）

`smoke-map-link` 的 C-1 原本自己重算像素坐标：`(r.x - m.bounds.minX) * 30 + 34 + 15`。
实测算出 `(1039,169)`，而真渲染出的格心是 `1249` —— **偏 210px**。

根因：`mapHtml` 前面还有一道「裁到本区紧包围盒」，
所以渲染用的 `b` 是**本区**的 `minX/minY`，而 `m.bounds` 是**全图** bounds。
区域装箱在区域之间留了空当（`minX` 会到 -3 这种值），两份 bounds 差着那一截。

⇒ 12 条边全判「漏画」。修法：判据**与 ui.js 同源** ——
从渲染出的 SVG 里反读每条 link 的点集，不再自己复现一遍算法。
（老铁律：守卫要核对后端真下发的数据，不要复现一遍算法。）
