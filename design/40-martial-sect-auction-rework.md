## §0 一句话结论 + 本次动的范围

### 0.1 一句话

**武学从「一堆平行技能」改成「一棵有根的树」**：每门武学都挂在一门**基础武学**底下（前置 + 上限都受它管），战斗里不再是「装备到武器槽就自动打」，而是**先把已激活武学的「武技」摆进快捷栏、临战点用**；门派按**一流（考核严）/ 二流（考核千奇百怪）/ 三流（几乎无考核）**分三层重新编队，层间靠**门派好感度**与**大比**串联；武学的主要新出海口是**拍卖行**（可买可寄拍，有概率出高品）。

## §1 前置与上限机制

### 1.1 前置链（需求①②）

**结构**：武学组成**树**，每门武学有且只有**一个直接前置**（`base`）。根的集合 = 八门基础武学。三档深度：

```
基础武学(九品) ──→ 门派入门(七/八/九品) ──→ 门派中阶(四/五/六品) ──→ 门派绝学(一/二/三品)
   basic_sword        huashan_sword            huashan_sword_art          huashan_jianyi
```

**数据形态**（新增字段，写在 `10_skills.json` 每门武学上）：

```jsonc
"huashan_jianyi": {
  "id": "huashan_jianyi",
  "grade": 1,                       // 新增：品级（05 §2.2）
  "base": "huashan_sword_art",      // 新增：直接前置（有根→必须写）
  "require": { "sect": "huashan", "skill": "huashan_sword_art", ">=": 300 }  // 既有字段，门槛取 05 §2.2
}
```

**引擎现状**：`learnSkill()` 已会读 `sd.require` 走 `evalCond`（`character.js:341-345`）；`evalCond` 支持 `{skill, '>='}`（`modapi.js:184-194`）。**所以「前置学不会就学不了」现在就能用**——但**前提是数据里补了 `require`**。现有只有 4 门带 `require`（`huashan_jianyi` `10_skills.json:168-172`、`damo_sword` `:335-339`、`xianglong_zhang` `:600-604`、`dugu_jiujian`/`xuantie_jianfa` 无门派前置），**绝大多数武学没有前置**。

> ✅ **结论**：需求①「必须先学基础武学」= **纯数据补 `require`**，引擎无需改。
> ⚠️ 唯一要学的：`baseSkill` 是「直接前置」而不是「都必须指向 basic_*」——因为一条链太长（基本剑法→华山剑法→养吾剑法→华山剑意），逐级前置才防得住「一步登天」。

### 1.2 上限机制（需求②）—— **这是本次最核心的引擎改动**

**公式**（写进 `05-balance-spec.md` §2.4，此处复述）：

```
effectiveMax(skill) = min(
      skill.maxLevel                        // ① 门内硬顶（05 §2.2）
    , maxSkillLevelFor(skill)               // ② 资质/悟性/内功/经脉上限（05 §2.5）
    , (skill.base ? levelOf(skill.base) : +∞) // ③ 【新】基础武学练到几级，就最多到几级
)
```

**为什么必须有 ③**：主人原话「基础武学练到什么级别，其他武学最多只能学到那个级别」。现在引擎**没有这一项**，`maxSkillLevelFor()` 只算 ①②（`character.js:420-441`，`limit = floor(wis*6+apt*9+ngLv*0.8)`）。

**引擎现状 / 缺口**：

| 环节 | 现状 | 出处 | 结论 |
|---|---|---|---|
| ② 的上限函数 | 存在但公式偏弱（到不了 1000，见 05 §7-④） | `character.js:439` | 重标定（05 §2.5） |
| ③ 基础武学上限 | **不存在** | — | **缺口 P0-1** |
| `learnLimit` 逃生口 | 存在（`evalTemplate` 可写 `{skill:xxx}`） | `character.js:423-429` | ❌ 不能当③用：它 `return v` **直接绕过 `maxLevel`**（`character.js:426`），且 `evalTemplate` 只会做字符串替换（`modapi.js:654-675`），**没有 `min()`**，写不出「取小值」 |
| 熟练度档位归一化 | 用 `sd.maxLevel` | `character.js:39` `profTierOf` | ⚠️ 必须改成 `effectiveMax`，否则被③压低后**永远停在未入门**（见 05 §4） |

> **落地建议**：给 `Character.maxSkillLevelFor()` 增加第三项 `base` 查询；同时把 `profTierOf/profTierIndex` 的分母换成 `effectiveMax`。**这两处不改，需求②就是空话。**

### 1.3 与「熟练度六级 / 去等级化伤害」怎么共存

**共存原则：品级管「倍率基准」，熟练度档位管「倍率系数」，两者相乘，各封顶一次。**

| 机制 | 出处 | 在本体系里的角色 |
|---|---|---|
| 去等级化伤害 | `combat.js:399-401`：`base = u.atk`，不再叠 `level` | ✅ **地基，不动**。伤害只由 `atk × damageMult(品) × profTierMult(档)` 决定 |
| 熟练度六级 `PROF_TIERS` | `character.js:19-26`（0.6→2.0） | ✅ 保留。练得越熟越强（需求⑩后半） |
| 品级 `grade` | 本文件新增 | ✅ 决定 `damageMult` 基准（05 §2.2）+ `maxLevel` + 学习门槛 |
| 倍率天花板 | — | **`damageMult × 2.0 ≤ 4.8`**（05 §4）。任何特效不许再乘品级，防「二次爆炸」（`06` §0 记的同款 bug） |

**冲突点（必列）**：`profTierIndex` 现在的档位阈值是 `0.2/0.4/0.6/0.85`（`character.js:30-34`）。当③把上限压到「基础武学等级」这种**动态值**后，同一门技能在不同玩家手里档位会不同——这是**设计意图**（基础武学越高，同门技能能练到的档位越高），不是 bug。但**前端显示必须改用 `effectiveMax` 算进度**（`engine.js:636` 现在返回 `maxLevel: p.maxSkillLevelFor(sd)`，够用；`engine.js:642` 的 `profTier` 要跟着改）。

## §2 激活绑定（需求③④）

> 🔴 **【口径更正 · 2026-10-10 主人亲口纠正，本节以此为准】**
> 本文初稿把「免绑、最多 3 本」当成了 **`category === '旁门'` 这一个类别的特权**——**错了**。
> 主人原话：
> > 「可以直接激活的三本是属于**没有基本功法类型的**，像毒术之类的应该有**基本毒术**，
> > 医疗类应该有**基本医术**可绑定激活，那种**没有基本武学的只能单独激活三本**」
>
> **正确判据 = 「这一门武学有没有对应的基础武学」，不是「它属于哪个 category」**：
> - **有毒术就该有《基本毒术》、有医术就该有《基本医术》** —— 这类照样**绑定激活**（与内功绑《基本内功》同理）；
> - **只有真的没有对应基础武学的那些**，才走「无需绑定 · 单独激活 · **合计最多 3 本**」；
> - 那 3 本名额是**跨门类共用一个池子**（不是每类 3 本）。
>
> ⇒ §2.2 的「唯一基础武学」表要扩成一张**基础武学总表**（见 §2.4），§2.4 整节已按新口径重写。

### 2.5 与 `equipment` / `equippedSkills` 的关系（复用优先）

- **`equipment`**（`character.js:115`：头/身/武器/副手…）＝**兵刃甲胄**，管 `weaponPenalty`（`combat.js:40-48`：无对应兵刃伤害 ×0.45）。
- **`equippedSkills`**（`character.js:107`）＝**武学激活**，管 `pickSkill`（`combat.js:315-359`：从 `['剑','刀','棍','鞭','暗器','拳']` 里挑已装备的用）。
- **两者正交**，本设计**不动 `equipment`**，只给 `equippedSkills` 加**校验**（§2.3）+ **新增旁门数组**（§2.4）。
- ⚠️ 一个现存小坑：`pickSkill` 的挑选顺序是**硬编码** `['剑','刀','棍','鞭','暗器','拳']`（`combat.js:348`）——**不含 `音波`/`枪`**。若 §2.2 采纳 `音波` 槽，`pickSkill` 必须同步加（§9 P0-2 附带）。

### 2.6 前端「武学」页面要显示什么

现有面板：`skillsHtml()`（`ui.js:1559-1575`，表格列：武学/门类/类型/等级/熟练度/威力）+ 数据源 `skillList()`（`engine.js:630-648`，已带 `category/profTier/weaponType/damageMult`）。

## §4 武技（战斗招式）

### 4.1 现状实测：现在「武技」是什么

**当前引擎里没有独立的「武技」概念**——一门武学 `skill` 就是一个招：`perform <武学名>`（`commands.js:2180-2189`）→ `combatStep({type:'skill',skill})`（`world.js:2175-2192`）→ `combat.oneAttack()`（`combat.js:361`）。所谓「招式效果」= `skill.effects[]`，在**命中后**由 `applySkillEffect` 逐条结算（`combat.js:411-418`）。

**所以主人要的「每个武学都有武技」，现实是「每个武学都有『一坨 effects』，没有名字、没有独立消耗、没有冷却」。**

### 4.2 武技数据结构（建议新增字段 `moves`）

```jsonc
"huashan_jianyi": {
  "id": "huashan_jianyi",
  "effects": [ /* 既有：等价于「被动/命中武技」，保留不删（向后兼容） */ ],
  "moves": [                                   // 新增：显式武技列表
    {
      "id": "hs_jianyi_po",                    // 武技唯一 id（全局唯一）
      "name": "剑意·破",                        // 中文名（战斗日志用）
      "trigger": "active",                     // active(手动) / onHit / onCrit / onDamaged / onTurnStart / passive
      "mpCost": 25,                            // 额外内力（叠加 skill.mpCost）
      "staminaCost": 10,                       // 额外体力
      "cooldown": 3,                           // 回合冷却（新引擎能力，见 §9 P0-3）
      "require": { "skill": "huashan_jianyi", ">=": 300 },  // 可选：练到一定档才解锁这招
      "effects": [ { "type": "ignoreDef" },
                   { "type": "cond", "if": { "chance": 0.4 },
                     "then": [ { "type": "extraHit", "value": 2 } ] } ]
    }
  ]
}
```

**兼容规则**：`moves` 缺省时，`skill.effects` 视为**一条隐式 `onHit` 被动武技**（现有 60 门武学一律走这条，**不改数据也能跑**）。这样「武技是可选增强，不是强制重写」。

### 4.3 特殊效果清单（需求⑫；每条给**引擎实现要点**）

**图例**：🟢 现有引擎直接支持（`applySkillEffect`，`combat.js:465-530`）｜🟡 现有部分支持（要拼）｜🔴 需新代码（缺口）。

| 效果 | 引擎现状 | 实现要点 / 缺口 |
|---|---|---|
| **眩晕** | 🟢 `case 'stun'`（`combat.js:474-476`） | 直接写 `{type:'stun',chance,turns}`。已有 `shaolin_changquan`/`wudang_taiji` 用 |
| **定身/减速** | 🟢 `case 'slow'`（`:477-479`） | `{type:'slow',value,turns}` |
| **用毒（持续掉血）** | 🟢 `case 'dot'`（`:469-473`） | 结算在 `tickBuffs`（`combat.js:532-549`）。`tangmen_du` 已用 |
| **连击** | 🟢 `case 'extraHit'`（`:495-503`） | `{type:'extraHit',value:N}` 递归调 `oneAttack`。⚠️ 注意递归里 `slot` 传 1，**不会再触发一层 effects**（防无限） |
| **吸血** | 🟢 `lifesteal`（`combat.js:436-440`，走 `u.lifesteal`）+ 可 `{type:'drain',ratio}` 吸内力（`:486-489`） | buff `mods:{lifesteal:0.2}` 或 `{type:'drain'}`。`weituo_zhang`/`xuedao` 已用 |
| **破防** | 🟢 `{type:'ignoreDef'}`（`:491-492` 空实现，真效果在 `ctx.mult` + `armorPen`） | ⚠️ `ignoreDef` **本身不改数值**，只出日志；真正破防靠 `armorPen`（`combat.js:60-67`）。写武技时**两个都要写** |
| **反伤** | 🟢 `reflect`（`combat.js:441-445`） | 只能通过 buff `mods:{reflect:0.3}`（基线 0，走绝对值，见 `combat.js:259` 的 ZERO_BASE） |
| **自我增益/减益** | 🟢 `case 'buff'`（`:480-482`）/`case 'debuff'`（`:483-485`） | `mods` 键支持 `atk/def/dodge/parry/speed/critRate/critDmg/armorPen/lifesteal/reflect`（`character.js:273-293`） |
| **治疗/回内力** | 🟢 `case 'heal'`（`:493-494`） | ⚠️ 只有 `heal`，**没有回内力**——需用 `{type:'custom'}`（`:504-510`，走 `world.effectFns[fn]`） |
| **迷幻/混乱**（敌人随机打自己人） | 🔴 **无** | 需新 effect：命中后给 `confuse` buff，`pickTarget`（`combat.js:295-307`）读它 → 目标从 enemies 改成包括友军。**缺口 P1** |
| **封穴/沉默**（禁敌用招） | 🔴 **无** | 需新 effect：给 `silence` buff，`pickSkill`（`combat.js:315-359`）读它 → 返回 null（只能普攻）。**缺口 P1** |
| **缴械**（打落敌兵器） | 🔴 **无** | 需 `disarm` buff + `oneAttack` 读 `u.equipment['武器']`。**缺口 P2** |
| **位移/击退** | 🔴 **无** | 战斗无「位置」概念（`battle.attackers/defenders` 是数组，无坐标）。**做不了**——除非改战斗模型。**缺口 P2 / 建议不做** |
| **群攻/溅射** | 🔴 **无** | `oneAttack` 只打单目标 `t`（`combat.js:361`）；`battle` 虽支持多方（`combat.js:107-115`）但无 AOE 入口。**缺口 P1** |
| **封印门派武学**（正派专破邪功） | 🟡 可拼 | 现在是**数据注释**（`weituo_zhang` desc 写「专破邪功」`10_skills.json:303`，但无机制）。要做须 `cond` 读 `target.sect` 的 `align`——`evalCond` 支持 `{sect}`，但**判的是玩家自己**（`modapi.js:252`），**判不了目标** → 需扩 `evalCond` 或写 `custom`。**缺口 P1** |
| **毒/蛊叠加层数** | 🟡 可拼 | `dot` 用 `tag: 'dot_<name>'` 会**覆盖同类**（`character.js:604`），要做「叠毒」须改 buff 叠加规则。**缺口 P2** |
| **连招（A招后接B招加成）** | 🔴 无 | 无「上一招」记忆。需在战斗对象上记 `lastMoveId`。**缺口 P2** |

> **给二流门派的「眼前一亮」特效落点**（需求⑫的正面回答）：引擎**现在就能做**的是 —— **眩晕 + 连击 + 用毒 + 吸血 + 减益(封速度/封招架) + 破防** 的组合。**「迷幻」要靠 P1 的 confuse，「封穴」要靠 P1 的 silence**。所以二流门派的招牌特效应**优先选能落地的**（毒+连击+眩晕+减速），把「迷幻」留给一两个「概念门派」并显式挂 P1 依赖。

### 4.4 一流门派武学效果（需求⑬，我给判断 + 理由）

**判断原则（三条）**：

1. **一流门派的强，强在「稳」不「诡」**——给**高倍率 + 高命中 + 自我增益**（buff），不做花哨控制。理由：一流是「天下正宗」，其武技该是「硬碰硬打得过」，与二流的「阴招」形成对照。
2. **必给一条「本源特效」**——即门派武学母题：少林=疗/卸力、武当=反震/借力、华山=破防、峨眉=连击、丐帮=刚猛蓄力、大理=点穴(眩晕)、魔教=吸血。
3. **每个一流门派给 1 门「越品」绝学**（一品），作为大比/主线的顶点奖励。

| 一流门派 | 母题特效 | 武技风格（理由） |
|---|---|---|
| 少林 | `heal` + `debuff(def−)` | 「罗汉伏魔」，硬桥硬马，能边打边疗（`yijinjing` 已带高 maxHp） |
| 武当 | `reflect` + `buff(dodge/parry)` | 「以柔克刚」——反弹与拆招是太极拳的题眼（`wudang_taiji` 已带 debuff speed） |
| 华山 | `ignoreDef` + `armorPen` | 「剑走轻灵，后发先至」（`huashan_sword` `ignoreDef` 已用，`10_skills.json:145-147`） |
| 峨眉 | `extraHit`(连击) | 「剑刺并重」，女子近身连击（`emei_sword` 已带 `extraHit`，`:490-503`） |
| 丐帮 | `buff(atk)` + `stun` | 「降龙至刚」——蓄力后一掌定身（`xianglong_zhang` 已带 `stun`+`debuff`，`:608-641`） |
| 大理段氏 | `stun`(点穴) + `debuff(speed/parry)` | 「一阳指封穴」（`yiyang_zhi` 已带「封穴」，`:984-1006`） |
| 日月神教 | `drain`(吸内力) + `lifesteal` | 「吸星大法」（`xixing_dafa` 已带 `lifesteal:0.15`，`:1219-1222`） |

### 4.5 快捷栏：前端怎么放、战斗里怎么用（需求⑪）

**现状实测**：

| 环节 | 现状 | 出处 |
|---|---|---|
| 快捷栏数据 | `DEFAULT_QUICKBAR` 10 个默认（查看四周/背包/武学/状态/打坐/运功疗伤/地图/任务/帮助/教程） | `ui.js:2910-2921` |
| 存哪 | `localStorage['wx_quickbar']` | `ui.js:2923-2935` |
| **战斗态** | ⚠️ **被硬编码替换**成 `[普通攻击/全力一击/防御/逃跑]` 4 键 | `ui.js:2944-2950` |
| 点键后 | `doCmd('attack')` 等 → 后端 `kill`/无参 `attack`/`defend`/`flee` | `ui.js:2967`；`commands.js:2201-2211` |
| 后端「用某招」 | `perform <武学名>` → `combatStep({type:'skill'})` | `commands.js:2180-2189`；`world.js:2175` |

**设计**：

```
战斗态快捷栏 = [普通攻击] [武技·A] [武技·B] [武技·C] [防御] [逃跑] [+ 背包]

点一下 → doCmd('perform <武技名>')
```

**落地拆法（两档）**：

| 档 | 内容 | 依赖 |
|---|---|---|
| **v1（快，先能玩）** | 战斗快捷栏把「已激活武学」渲染成按钮（点一下 `perform <武学名>`） | 只需改 `ui.js`（`renderQuickbar` 战斗分支）。**零后端改动**——`perform` 早就能用 |

> **强烈建议先落 v1**：主人需求⑪的核心诉求是「把已激活武学的武技放进快捷栏临战点用」，v1 已满足 80%；v2 的「同门多武技」是锦上添花。

**与现有战斗流程怎么接**：`world.combatStep(userAction)`（`world.js:2159`）已有 `type:'skill'` 分支，**v1 直接复用**；只有 v2 的 `cooldown` 要在 `battle` 对象上挂 `cooldowns: {}`（仿 `battle.guardTurns`，`world.js:2199` 的先例）。

### 5.3 每个门派的武学清单（需求⑭：核心/中阶/入门 × 内功/招架/轻功/攻击/旁门）

**规格**：每个门派在其**三个品级**上，各要覆盖 **5 类**（内功/招架/轻功/攻击/旁门）**至少各一本**。即每门派下限 `3 品 × 5 类 = 15 门`（**≥** 是硬指标）。

**先看现状缺口（实测，别粉饰）**：现有 60 门武学里，`type` 分布为 `拳12/剑12/刀6/棍4/鞭1/轻功7/招架2/内功12/暗器4`（本文实测）。即：
- **招架只有 2 门**（`basic_parry` + `jh_parry`），**14 个门派一个招架武学都没有**；
- **音波 0、枪 0**；`暗器` 4 门都是门派专属、无基础；
- 所以需求⑭在现状下**几乎全门派不达标** → 主要工作量在**补 `招架`/`内功`/`旁门`/`轻功` 四类**。

```jsonc
//    `flag`/`randomitem` 走 args → 下方写法经 evalEffect 实测可通。

    "then":[
      { "type":"narrate", "raw":"洞壁苔痕斑驳，你借着天光，见石壁上刻着半篇拳经……" },
      { "type":"flag", "args":["met_cave_1"] },              // → p.setFlag('met_cave_1', true)（modapi.js:519）
      { "type":"randomitem", "args":["book_jiu_yang","book_xuantie","book_lingbo"] }  // 等概率（modapi.js:442-446）
    ] } ]
```

**缺口**：`giveRandom` **是等概率**（`modapi.js:443` 用 `rng.pick`）→ 想要「低品 60% / 中品 30% / 高品 10%」的**加权随机**，需新 effect（**P1**，或退化为「写多份不同 `chance` 的 cond 分支」纯数据实现，见 §9 P1-10 的替代方案）。主人要「品级不确定」——**等概率也满足「不确定」**，加权是增强项。

### 6.3 拍卖行（**需求⑰，全新系统**）

**现状**：**完全没有**。最接近的是商铺买/卖（`commands.js:2622-2668`）与寄卖无。

**设计（完整）**：

#### 6.3.0 形态与地点
- **独立场所**：各大城设「拍卖行」房间（建议挂 `market` 东市 / `jiangnan` 主城），由专门 NPC 主持。
- **周期**：每 **3 游戏日** 开一场（对齐 05 §5.3）；未开场时可「看预展」。

#### 6.3.1 拍品生成
- 每期上架 **12 件**：`10 件固定池（药材/兵器/丹药/特殊物）+ 2 件高价值位`。
- **高价值位**按 05 §5.2 的概率抽品级：`一品 2% / 二品 4% / 三品 6% … 九品 18%`；抽到武学则生成对应品的「秘籍书」（`type:'book'` + `teach`）。
- 起拍价 = 05 §5.2 表值；每期价格带 ±15% 浮动（`rng`）。

#### 6.3.2 出价流程（玩家参与）
- **英式增价**（明拍）：每件拍品列「当前价 / 领先者 / 剩余轮次」。
- 玩家 `bid <价>` 出价，须 ≥ 当前价 + 最小加价（建议 5%）。NPC 竞价者按预算随机跟价。
- 一回合 = 游戏内 30 分钟；**连续 2 回合无人加价 → 落槌**。

#### 6.3.3 寄拍（玩家卖高价值物）
- 指令 `consign <物品>`：校验门槛（05 §5.3：`value>=500` 或 `grade<=6`），自定保底价。
- 落槌后扣 **8% 手续费**，余款入袋；流拍收 **2% 上架费**。
- 寄拍期间物品从背包移除，挂 `p.consignments[]`。

#### 6.3.4 前端页面
- 新增「拍卖」面板：**预展区**（只读）/ **竞价区**（当前价 + 我的出价 + 剩余）/ **寄拍区**（我的寄拍 + 状态）。
- 快捷栏加「拍卖」按钮（非战斗态）。

#### 6.3.5 引擎缺口
**整块新增**：`auction.js`（模块）+ `bid`/`consign`/`auction` 指令（`commands.js`）+ `data.auction`（拍品池）+ 前端面板。**P0-5**。**这是主人点名要的功能，不做就没落地。**
