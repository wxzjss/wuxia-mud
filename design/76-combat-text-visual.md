## 〇、先说四件已经查实的硬事实（决定后面所有取值）

1. **日志区是等宽流，字号不许跳** —— `.log { line-height: 1.8; font-size: 14px; max-width: var(--col-w) }`，`.log-line { margin-bottom: 3px }`。行高由容器给，任何一档改字号都会让那一行在流里"鼓"出来。**⇒ 字号、行高、margin 一律不参与分档。**
2. **项目没有加载任何 webfont** —— `--font: "Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", "STSong", Georgia, serif` 是**纯系统字体栈**（`index.html` 内无 `@font-face`、无 Google Fonts 链接）。
   ⇒ **字重不能当主要手段**：系统衬线中文没有真 bold，500/600 会被浏览器**合成伪粗**，14px 下笔画糊成一团。字重只保留给第 5 档一次，且标注可砍。
3. **`.log-line.combat` 现在是硬编码 `#8a3a2a`**（main.css:604），不是变量。
   ⇒ 违反「颜色一律 CSS 变量」，本次必须一并收掉。同类硬编码还有 `.log-line.faint`（`#4a4a58`）、`.log-line.favor`（`#c0392b`）、`.log-line.like`（`#cf9163`）—— 见 §5.2，我只报不修。
4. **句库的 `severity` 表已经 `return` 出来了**（`design/75` §1.5 末尾 `return { version, severity, parts, … }`）。
   ⇒ 渲染层**可以自己按同一张表算出 tier**，不必改 `COMBAT_LINES.render()` 的返回值。**游有方那份句库一个字都不用动**（见 §5.2 方案 B）。

## 一、风格定义

### 1.1 一句话

> **战斗不是新的材质，是写在同一张纸上的、颜色更深的那几行字。**
> 分轻重**不靠字号、不靠框、不靠底色块** —— 靠**左侧那道批注竖线有多粗、有多长、是什么颜色**。

### 1.2 为什么主手段是「左侧竖条」

| 候选 | 判定 | 理由 |
|---|---|---|
| **字号大小** | ✗ | 硬约束排除：等宽流，跳字号就跳行高 |
| **底色块** | ✗ | 制作人已判"长日志里会很吵"，我同意 —— 一场 20 手的架就是 20 个色块，日志区会变成色带，正文反而不显。**且底色块在窄屏换行时会断成两截** |
| **前缀符号（※ ▲ ●）** | ✗ | 那是在**文本流里插 UI**。游有方花了大力气让句子读起来像小说（「六句话里没有一个数字、没有一个招式名、没有一个成语」），往句首塞一个符号，等于把读者从故事里拽出来。**这是在拆他的台** |
| **整行字色** | 部分 | 有效，但单靠它不够：① 要满足"不靠读字"，色差必须拉得很大，五档拉开就会有两档难看；② 色觉差异下 5 档相邻色相很难分辨。**色是次手段，不是主手段** |
| **字重** | 部分 | 见 §〇.2：系统衬线无真 bold，合成伪粗在 14px 下糊。**只给第 5 档用一次** |
| **左侧竖条（宽 + 长 + 色）** | ✅ | ① **零排版影响** —— 用 `::before` 绝对定位，`padding-left` 恒定，不占行盒、不跳行高；② **天然是"可读的重量"** —— 杠越粗越长＝这一下越重，不需要读字也不需要辨色；③ **去色仍可辨** —— 2px 短杠 vs 6.5px 通栏，灰度下一眼分得出；④ **气质对** —— 竖线是**批注本/眉批**的记号，跟地图那张"私人笔记"是同一套东西，不是地图符号也不是 UI 控件 |

### 1.3 一道杠的三个维度（这是全部的分档语言）

| 维度 | 1 档 | 2 档 | 3 档 | 4 档 | 5 档 |
|---|---|---|---|---|---|
| **宽**（`--combat-bar-w-N`） | 2px | 3px | 4px | 5px | **6.5px** |
| **长**（上下内缩 `--combat-bar-in-N`） | 32%（短杠，居中） | 24% | 15% | 7% | **0%（通栏）** |
| **色**（`--combat-sN`） | 淡赭灰 | 土黄褐 | 赭红 | 朱 | 亮朱 |

**「长」这个维度是补「宽」的不足的**：2px 与 3px 的差在 14px 字旁边很微妙，但「一道只占三分之一行高的短杠」与「一道顶天立地的通栏」是任何人都能分辨的。**两个维度相乘，五档的可辨度不是 5 级，是 15 级。**

### 1.4 主客：实心 vs 虚线（不是"我挨的/我打出的"，是"血是谁的"）

制作人把这条交给我判。我的结论：

> **实心杠 = 血是我的。虚线杠 = 血是别人的。**

三点理由：

1. **比"我挨的/我打出的"更准**。战斗里有 NPC 打 NPC（你看热闹），那时既不是你挨也不是你打 —— 按"主客"分就无处安放，按"血是谁的"分则天然归到虚线。**规则从两条变一条，零例外。**
2. **语义自洽**。实打实落在你身上 → 实心；你送出去的一下，成不成还在两可 → 虚线。这跟句子本身的意思是一致的，不是外加的标签。
3. **不引入新形状、新颜色**。虚线是同一道杠的另一种"填法"，去色、缩放到 2 倍都还在。

配一条字色规则：**血是别人的，字色降一档**（`--combat-deal-N` = `--combat-s(N-1)`，1 档降到 `--ink-3`）。所以别人挨的"站不住"，字色只到我挨的"伤到骨"那么红 —— **我的血总是比别人的血更红一点**，这一条不需要玩家意识到，他只要觉得"打我的那几行更扎眼"就对了。

### 1.5 总纲修订（与 `design/73` 的关系）

`design/73` 定的总纲是：**界面元件，只有「我」配朱与金，其余一律墨阶。**

战斗文本不是界面元件，是**叙事内容**。所以补一句，不是推翻：

> **界面元件：只有「我」配朱与金。**
> **叙事内容：只有「血」配朱 —— 而且只按血的多少配，不按好看配。**

朱红在本方案里**只有一个来源**：`--red` / `--red-2` 那一族（s4 ≈ `--red`，s5 = `--red-2`）。我没有为战斗新造一种红 —— **跟全项目是同一瓶朱砂**。

## 三、逐元件规格

### 3.1 ① 五档怎么一眼分出轻重（结论表）

| 档 | 名称 | 竖条宽 | 竖条长（内缩） | 竖条色 | 我挨的·字色 | 我打出的·字色 | 字重 | 额外 |
|---|---|---|---|---|---|---|---|---|
| **1** | 蹭了一下不算伤 | 2px | 32% | `--combat-s1` | `--combat-s1` | `--ink-3` | 400 | — |
| **2** | 挂脏了 | 3px | 24% | `--combat-s2` | `--combat-s2` | `--combat-s1` | 400 | — |
| **3** | 见了血 | 4px | 15% | `--combat-s3` | `--combat-s3` | `--combat-s2` | 400 | — |
| **4** | 伤到骨 | 5px | 7% | `--combat-s4` | `--combat-s4` | `--combat-s3` | **500** | — |
| **5** | 站不住 | **6.5px** | **0%** | `--combat-s5` | `--combat-s5` | `--combat-s4` | **600** | 极淡底 `--combat-s5-bg` |
| — | **落空** | **无杠** | — | — | `--combat-miss`（`--ink-4`） | 同 | 400 | 没打着就不该有血色 |
| — | **被挡开** | 2px（虚线更密） | 30% | `--combat-s1` | `--combat-block`（`--ink-3`） | 同 | 400 | — |
| — | **暴击** | 同档位 | 同档位 | 同档位 | 同档位（**tier 已被句库强制抬到 ≥3**） | 同 | +100（封顶 600） | 竖条加外柔光 `--combat-crit-glow` |

**三条硬规矩**：

1. **字号一律 14px，与日志正文完全相同。** 任何档位、任何状态，不改 `font-size`、不改 `line-height`、不改 `margin-bottom`。
2. **`padding-left` 恒为 `--combat-pad: 15px`**，不随档位变。档位的差异**全部**由 `::before` 那道杠承载 —— 杠是绝对定位的，占不到行盒。
3. **不给圆角、不给边框、不给阴影（暴击的柔光除外）、不给背景图**。它还是一行字，不是卡片。

**字重的可砍声明**：500/600 在系统衬线中文上是**合成伪粗**。落地后请主人在真机上看一眼 4/5 档：若伪粗难看，**第一个砍字重**（`--combat-w-4` / `--combat-w-5` 全改 400），分档由「杠宽 + 杠长 + 色 + 第 5 档的极淡底」承担 —— 这四样已经够了，字重只是加成。**不要为了保住字重去换字体或加载 webfont**（项目有"不引入外部资源"的规矩，且 webfont 会拖慢首屏）。

### 3.2 竖条的画法（写死，别自由发挥）

```css
.log-line.combat { position: relative; padding-left: var(--combat-pad); }
.log-line.combat::before {
  content: ''; position: absolute; left: 0;
  top: var(--combat-bar-in, 32%); bottom: var(--combat-bar-in, 32%);
  width: var(--combat-bar-w, 2px);
  background: var(--combat-bar, var(--combat-s1));
  border-radius: 1px; pointer-events: none;
}
/* 血是别人的 → 同一道杠改成竖向虚线 */
.log-line.combat.cb-out::before {
  background: repeating-linear-gradient(
    180deg, var(--combat-bar, var(--combat-s1)) 0 3px, transparent 3px 6px);
}
/* 落空：不画杠 */
.log-line.combat.cb-miss::before { content: none; }
```

> ⚠️ **为什么用 `::before` 而不是 `border-left`**：`border-left` 参与布局。杠宽从 2px 到 6.5px，用 border 就必须让每档的 `padding-left` 跟着减（否则正文起始位置会按档位左右跳 4.5px），那是一条"两处各写一份、必然漂移"的坑 —— 我在地图方案里已经为同类问题记过两次了。**绝对定位的 `::before` 从结构上消灭了这个可能。**

### 3.3 ② 数值模式开关

**产品判断（制作人采纳游有方的原判，我按它设计）**：默认关，**不主动提示这个开关的存在** —— 不弹窗、不引导、不在新手流程里提、不开 toast、不加"推荐关闭"徽标。**想算的人自己会找到。**

| 项 | 规格 |
|---|---|
| **位置** | 设置面板，**「界面配色」之后、「Mod 网站地址」之前**。理由：Mod 地址是开发者项，必须垫底；这一项与上面那批玩法开关同族，排在它们之后、开发者项之前 |
| **控件** | **完全复用** `.set-row` + `.switch`（与「自动存档」「紧凑模式」「地图显示未探索地名」同款）。**不新造控件、不新造图标、不新造 class** |
| **标签文案** | `战斗显示气血数字` |
| | ⚠️ 不用「拟真模式 / 数值模式 / 伤害数字」—— 前两个是设计术语不是玩家语言，后一个里"伤害"这个词在游有方的文本里根本不出现。「气血数字」是本游戏自己的词（`.tb-bar.hp` 的 `title` 就是"气血"） |
| **默认** | `off`。`.switch` 无 `.on`，文字「关」 |
| **设置键名** | `S.settings.combatnum`（加入 `['anim','auto','narrow','mapnames']` 那个 toggle 数组，变成 `['anim','auto','narrow','mapnames','combatnum']`，DOM id `set-combatnum`） |
| **生效时机** | 下次渲染即生效（不像地图那个要重开面板） |
| **零引导的机械定义** | 见验收 V-14 |

**打开后，句尾那个 `（-37）` 长什么样**：

```css
.cb-num {
  color: var(--combat-num);           /* 比正文弱一档：它是附录，不是叙述 */
  font-family: var(--font-ui);        /* 衬线 → 无衬线：这是"数据"不是"句子" */
  letter-spacing: var(--combat-num-ls);
  font-weight: 400;                   /* 不加粗 */
  /* ⚠️ font-size 不写 = 继承 14px */
}
```

| 项 | 值 | 理由 |
|---|---|---|
| 色 | `--combat-num` `#8a8271`（暗）/ `#6f675a`（浅） | 比档位色都弱。数字是给"想算的人"看的，不该跟句子抢眼 |
| 字体 | `--font-ui`（无衬线） | 衬线 = 叙事，无衬线 = 数据。同一行里一眼分得开"哪句是故事、哪个是数" |
| 字号 | **不写**，继承 14px | 硬约束 |
| 括号 | 中文全角 `（-37）` | 游有方 §1.6 已定，不动 |
| 位置 | **只在句尾**，由句库 `render()` 追加 | 游有方 §1.6 已定："正文一字不改" |

**"正文一字不改"的机械定义**：开启前后，把 `.cb-num` 从行内摘掉后剩下的 `textContent` 必须**逐字相同**。这是验收 V-12。

### 3.4 ③ 战斗文本在日志区的排版

| 项 | 规格 |
|---|---|
| 字体 | `var(--font)`（衬线）—— **与日志正文同一栈**。战斗是叙事，不是数据 |
| 字号 | **14px，与正文完全一致** |
| 行高 | 继承 `.log` 的 1.8，不写 |
| 行间距 | 继承 `.log-line` 的 `margin-bottom: 3px`，不写 |
| 左留白 | `padding-left: var(--combat-pad)` = 15px（给杠让位，恒定） |
| 首行缩进 | **0**。战斗行不缩进 —— 它是一句完整的话，不是段落 |
| 块间距 | 连续战斗行之间不额外加距。**一场架看起来是一块，靠的是杠的连续，不是空格** |
| 形状 | 无边框、无圆角、无背景（第 5 档的极淡底除外）、无阴影 |
| 换行 | `word-break: break-word` 已由 `.log-line` 给，窄屏换行时**杠不跟着断**（它是绝对定位，永远一条） |

**气质统一（与 `design/73` 的接缝）**：

| 接缝点 | 做法 |
|---|---|
| 材质 | **不引入新材质**。日志区就是那张纸（= 地图的 `--map-void` 那一档），战斗是**写在纸上的字**，不是贴上去的卡片 |
| 朱色 | 只有一个来源：`--red` / `--red-2` 那一瓶。s4 ≈ `--red`，s5 = `--red-2` |
| 金色 | **战斗一行都不给金**。暴击用朱色柔光，不用金 —— 金留给地图的 L1 与面板的"我" |
| 竖条 | 与地图未探索羽化、任务卡片的左侧朱条是**同一套"左侧一道"**的语言 |
| .roomname 左边线 | 已在 `design/73` §3.8 改为 `var(--map-boundary)`；战斗行改用 `::before` 后两者不冲突（`.log-line.combat` 与 `.log-line.story` / `.log-line.quest` 互斥） |

**"我打出去"和"我挨的"的最终裁定**（制作人交我判的那条）：

> **要区别，但区别不在"我打/我挨"，在"血是谁的"。**
> 血是我的 → 实心杠 + 全档字色；血是别人的 → 虚线杠 + 字色降一档。
> **我的血永远比别人的血红一档。** 玩家不需要知道这条规则，他只要觉得"打在我身上的那几行更扎眼"就够了。

## 四、规格总表

### 4.1 CSS 变量清单（暗色 `:root`，新增）


## 六、给主理人的一句话

> 游有方把"造成 37 点伤害"翻译成「他这一剁落下来，你抬手一架，骨头先响，血随后就出来了」—— 那我该做的不是给这句话加装饰，是**让它在屏幕上有它应有的重量**。
> 所以我一行字都没加大、一个符号都没往句首塞：只在左边加了一道批注竖线，**这道杠有多粗、有多长、有多红，就是这一下有多重**。
> 血是我的，杠是实的；血是别人的，杠是虚的，字色还降一档 —— **我的血永远比别人的血红一点**，这条玩家不需要知道，他只要觉得打在自己身上的那几行更扎眼就够了。
