## 卷首 · 一页纸核心设计

**三句话**

- **是什么品类**：浏览器里的武侠 MUD —— 一个**已经谢幕的江湖**的最后二十年，玩家来晚了，只能在传说的灰里翻找还值钱的东西。
- **玩家做什么**：在一处具体的地里**看明白发生了什么**（看风），找到那个知道内情的人**把话问出来**（问事），遇到卡住的事**亲手用肢体去解决**（动手：挪、撬、爬、摸、守、挑），最后**承担这个结果、被人记住**（落名）。
- **爽点在哪**：不是数字变大，是**你做的每一件事都有具体回响** —— 你挪过那口缸，墙根的水渍五年不干；你撬开过那口匣子，三年后有人上门问你匣子里少了什么。

**一句话卖点**

> **众人都已谢幕，而你刚到。**

**目标体验**：北大侠客行那样的"读字像看片子" —— 玩家靠环境描写和对话辨认"这是什么地方、这些人什么关系、我现在该干什么"，而不是靠任务面板。

**核心循环（单次 30–90 秒，可无尽串联）**

| 节拍 | 动词族 | 做什么 | 回报 |
|---|---|---|---|
| ① 看风 | 看 / 听 / 闻 / 摸 | 读房间的具体细节与时令变化，抓到一条"不对劲" | 一条线索、一个可点的物件 |
| ② 问事 | 问 / 打听 / 请安 / 请托 | 找一个认得这件事的人，把内情问出来 | 一个具体差事 + 一个代价（人情 / 银钱 / 立场） |
| ③ 动手 | 挪 / 撬 / 爬 / 摸 / 守 / 挑 / 出刀 | 亲手做成一件需要操作的事（见 D.3） | 手感 + 后果（东西动了、人记住了、封条破了） |
| ④ 落名 | 报 / 还 / 认 | 把结果交还给某人，或藏起来 | 名声与因果账变动，下一件难事自动浮出来 |

**贯穿的东西**：**因果账** —— 你欠谁的、谁欠你的、谁在找你。它是唯一的长期进度条，也是"我为什么要继续"的答案。

### A.2 数值与模板克隆体检（"设定很怪"的量化答案）

- **165 名弟子塌缩成 3 个数值签名**：60 人共用一组、另 60 人共用另一组、36 人共用第三组。遇到"唐门弟子"和"苗疆弟子"是同一个人数值。
- **43 名守卫共用同一句台词**「本门不是客栈。要进，得有个说法。」，且被放在**渡口（桃花岛·渡口）、破庙（丐帮·破庙）**等非客栈语境。
- **43 门派 × 5 族（force/guard/fly/atk/qimen）× 3 级** ≈ 600 门武学，描述为同一句模板换前缀：
  - `XX的护身手法。架势摆得正，才谈得上卸力。`
  - `XX的提纵法门，走山路、翻墙头都用得上。`
  - `XX不轻易示人的一手。门里也只教个大概，剩下的靠自己悟。`
- **maxLevel 分布 400–1200**：没有可感知刻度的深度通胀。
- **性别与史实冲突**：`disciple_huashan_5` 名为**梁发**（原著华山男性弟子）却 `gender=female`。
- **地图层级的模板粘贴**（v1.1 新增，详见 M.2）：11 座山共享同一套六段山路（石阶/松林/半山亭/林间道/山泉/崖边路），4 座山村共享同一套四间（村口/打谷场/茶棚/山神庙），另有 22 座藏经阁、42 座藏宝阁。**合计约 146 间房（占世界 27%）是同一批模板粘贴的产物。**

### A.3 工具失灵（解释了"写了这么多稿还是 AI 味"）

跑仓内守卫 `tools/ai-flavor-check.js`：**AI 腔调 0 条 · 出戏词 0 条 · 全绿**。但它自己同时列出 **274 条样板复用**，最高**同一句出现 149 次**（`偶尔会多说两句，说完自己也觉得多余。`），并在源码注释里写着「不必逐条改」。

> **结论一：不是写得太差，是量具坏了。** 中文里最刺眼的 AI 味不是修辞套话，而是**同一副骨架被套了一百多次**。现有守卫把这件事标为"不判红"，于是无论重写多少稿都不会变好。

**两次交叉验证**

| 工具 | 对象 | 结果 |
|---|---|---|
| 朱雀启发式检测器 | 我刻意写的**坏样例**（升华腔＋拟人＋二分对照＋网文套词） | 疑似度 **24/100** |
| 朱雀启发式检测器 | 我写的**好样例** | **2/100** |
| story-engine `audit_text(diff_only=True)` | **现有主线检查表** | `all_passed = True` |
| story-engine `audit_text(diff_only=True)` | **我重写的一场戏** | `all_passed = True` |

> **结论二：统计类检测器与因果类检测器都判不出"剧情不好"。** 真正能判的只有**结构门槛**（有没有对手、有没有代价、有没有不可逆选择）—— 这是 §C、§D 要建的墙。

## B. 世界观与设定重建

### B.1 为什么"现在的设定很怪"

不是某一处错，是**四个不一致同时存在**：

| 病症 | 证据 | 后果 |
|---|---|---|
| **时间错位** | 同库共存`东厂`（1420 才设立）、`大理段氏`称"皇亲"（大理 1253 已亡）、`襄阳城`守城叙事（1273 已破）、`锦国旧陵`（非真实朝代名） | 玩家说不出"这是哪个朝代" |
| **空间失重** | 长安/洛阳/成都/襄阳/江南/大理/西域/侠客岛同处一张东西跨三千里的图，但移动只是"敲一下 n"；没有里数、没有耗时、没有干粮 | 世界像 536 个互不相关的小房间，不像一块地 |
| **尺度混层** | `region` 表里同时有宏观州域（江南、洛阳）与微观坊巷 POI（衙门府、东市、皇城、醉春楼、青溪村、田野） | 地图与归属感双双错乱 |
| **能力通胀** | 武学 maxLevel 400–1200，而伤害走 `atk × mult`，中间没有可感知刻度 | 玩家看不出 100 级和 300 级差在哪 |

### B.2 时代裁定（一句话定锚）

> **「景定之后二十一年」 —— 襄阳城破的第二十一个冬天，群侠已殁或已隐，忽必烈新丧，朝局未稳。**

**为什么选它**

1. 把全部金庸时间线折叠成"已经发生过的传说"，任何两部书的人物都不再互相矛盾 —— **这一条就治好了时间错位**。
2. 天然给玩家让位：上一代人已经把事情做完了，好东西留在没人敢去的地方。
3. 元初汉人江湖是最有武侠味的一段：禁兵刃、户籍严、遗民心结、官府与江湖互不信任。NPC 的沉默、提防、不与陌生人深谈，全都有了理由。

**三处最小修订**（不做全库推倒，只补三条硬规则）

| 处理 | 做法 | 影响面 |
|---|---|---|
| **改** | `东厂` → `肃政缉访司`（虚构但与元制相容的缉访机构）；39 处字符串 | 主线 act2–5 文本顺一遍，`q_main_sect` 铜牌改为司印 |
| **改** | `大理段氏`不再是"当朝皇亲"，改为**前朝王裔、今受监视的豪族**；43 处 | 反而变成剧情素材（见 D 第二幕） |
| **明** | 在楔子末尾、凡进城第一眼、官府首次出场**写死年号**：「景定之后二十一年，腊月」 | 3 处文案 |

**硬规则**：此后所有新写文本不得出现真实朝代年号；已存在的 `明朝`（1 处）优先清掉。

### B.3 地理与距离（地图不空的地基）

引入 **`路程表`**：州域之间的每一条边都写实数据与耗时。

```
向西 → 洛阳　四百八十里（步行九日 / 骑马四日 / 走漕船六日）
向北 → 长安　八百二十里（步行十六日 / 骑马七日）
```

- **每个出口必须能回答"多远、多久、要什么"**（这是 §M 地图 UI 的核心信息诉求，也是 B.3 与 M 节的连接点）。
- **出门成本**：跨州移动消耗时间 + 干粮 + 水；不足则在路上出问题（"第三天你在路边吐了，吐完继续走"）。让"路"成为有质感的内容，而不是两间房之间的一条线。
- 轻功飞行（`flight.js` 的 BFS）不再是免费传送，改为**用内力换时间**；内力不够会中途落地，进退不得。

**区域分层**（只加字段，不改结构）

| 层级 | 成员 | 玩家用法 |
|---|---|---|
| **州域**（宏观，有距离） | 江南、洛阳、长安、成都、襄阳、姑苏、华山、少林、武当、峨眉、大理、苗疆、西域、关外、海上 | 跨州需路程，逐渐解锁 |
| **坊巷**（微观，无距离） | 衙门府、东市、皇城、醉春楼、白鹿书院、青溪村、田野、江口码头、地下黑市 | 州域内的 POI，几步就到 |

### B.4 武力体系（为什么现在的武学怪）

**病**：一门武功 = 一个可刷的数值 + 一句模板描述。43 家 × 15 门 = 645 个换皮条目。

**新规则：一门武功必须同时回答三件事，答不上来就不许存在。**

1. **它解决什么问题** —— 要么打得更远、要么更挨打、要么走得更快、要么让人认不出你的路数。**四选一，不许什么都占。**
2. **它的代价是什么** —— 耗内 / 伤身 / 费时 / 露底 / 名声变差。**每门真功夫都要付出一样东西**；这是"看起来像真的"的来源。
3. **别人怎么认出它** —— 打完地上留什么痕、对手怎么分辨。**给出一条专属特征词**，供 §F 的战斗演出取用。

**合并方案（761 → 约 180）**

| 现在 | 变成 |
|---|---|
| `huashan_force_1 / _2 / _3` | 一门 `huashan_force`，六重熟练度；**每突破一重给一段专属短文本**（这是加回来的东西） |
| `<43 门派> × guard/fly/atk/qimen × 3` | **删**。13 家深门各留 1 门过门通识功，写在 `30_sects.json` |
| 30 家门面留下约 60 门 | 每家门面留 2 门：**一门立派功夫 + 一门只有这门才有的怪招** |

**数值区间重定**（原 400–1200 → 六重）

| 重 | 名称 | 区间 | 突破门槛（示例） |
|---|---|---|---|
| 一 | 入门 | 1–50 | 学会即可 |
| 二 | 熟练 | 51–120 | 实战命中 80 次 |
| 三 | 纯熟 | 121–220 | 赢一场同阶，或成功一次手动场景 |
| 四 | 登堂 | 221–350 | 需师父点拨（好感 ≥ 40） |
| 五 | 贯通 | 351–500 | 需门内层位 |
| 六 | 化境 | 501–650 | 需残页 / 敌手 / 一次不可逆事件 |

> **调参依据**：原表上限 1200 与 `damageMult` 天花板 2.4 相乘，导致同职等之间的差距可达 10 倍。收窄到 650 后，六重之间的伤害倍率带宽落在 **1.0 / 1.35 / 1.7 / 2.05 / 2.4 / 2.75**，能被玩家用一句"差了一重"说清。

## C. 江湖味文风规范

> 来源：`deai-promax`（五层爆破 / 网文四层流水线 / 禁用词表）、`humanizer`、`de-ai-flavor`、`write` 四份材料合成的**可执行**版本，并用朱雀启发式校准（好样例 2/100 vs 坏样例 24/100，见 A.3）。

### C.1 单一性法则（总纲，压倒一切）

> **玩家在任意时刻看到的每一句话，都必须只能属于这个地方 / 这个人。**
> **凡是能从别处原样抄来的句子，一律不许存在。**

这一条压倒所有"写得好不好"的判断：一句通顺但能套给 40 个人的话，比一句笨拙但只属于他一人的话更糟。

### C.2 三条硬门槛（不达标不进包）

| # | 门槛 | 判据（可机械执行） |
|---|---|---|
| **T1 唯一性** | 同一句 ≥8 字的玩家可见文本，全库最多出现 **2 次** | 守卫「重复度守卫」，阈值 2（现在实测 149 次） |
| **T2 归属** | 每个 NPC 的台词必须引用**他自己的三件已知事实**（出身 / 此刻所在地 / 他手上那件事）至少一件 | 守卫「归属守卫」（见 E.3），逐 ID 校验 |
| **T3 具体** | 任何场景描写必须包含**至少 2 个不可替换的物理细节**（材质、气味、声音、温度、形状、旧痕） | 抽样检查器，每批抽 10% |

### C.3 禁用清单（在既有 `tools/ai-flavor-check.js` 基础上增补）

**① 修辞层**（现有守卫已覆盖，保留）

升华腔（彰显 / 承载着 / 见证着 / 诉说着 / 昭示）、空洞过渡（值得一提 / 由此可见 / 在这个…的时代）、伪深度（别有一番滋味 / 淋漓尽致 / 栩栩如生）、公文腔（旨在 / 致力于 / 赋能 / 助力）、翻译腔（使得 / 从而 / 对于…而言 / 某种程度上）、空赞词（完美 / 极致 / 非凡 / 震撼 / 惊艳）、模板收尾（一段…的旅程 / 谱写…篇章）。

## D. 剧情架构

### D.0 为什么"现在的剧情写得不好"

`q_main_jianghu` 六步：加入门派 → 任意武学 100 级 → 完成 5 桩支线 → 战胜一位成名高手 → 习得绝顶内功 → 名动天下。

**这是一份能力提升清单，不是剧。** 它缺三样东西：

| 缺 | 后果 |
|---|---|
| **对手** | 没有一个人因玩家的进展而受损，也就没有人对抗玩家 |
| **代价** | 每一步都是"再加"，从不要求放弃任何东西，选择就没有意义 |
| **不可逆** | 玩家可以反悔一切，于是没有决策，只有搬运 |

**新增硬性设计验收（纳入 §L 每期验收点）**

> **主线每一幕必须至少有一次不可逆选择** —— 玩家选了以后，世界永久改变，且至少有一位具体的人因此处境变差。**做不到，这一幕不许立项。**

（我自己的样例段落已跑过 `audit_text(diff_only=True)`，`all_passed=True`；但同一份校验对现有检查表也是 `all_passed=True` —— 再次证明要靠结构门槛，不靠工具，见 A.3。）

### D.1 主结构：五幕 + 三条线

三条线保留（`mainline.js` 的 orthodox / outlaw / neutral），但**不再是"同一件事的三种说法"，而是同一件事的三种责任**：

| 线 | 核心质问 | 第二幕的不可逆选择 |
|---|---|---|
| **正派**（有根者） | 你愿不愿意为了规矩，认下发不出去的一笔账？ | 公开认错并交出一个人 / 沉默保住门楣 |
| **反派**（背债者） | 你愿不愿意为了这笔账，伤一个没欠你的人？ | 分利 / 独吞并被追 |
| **中立**（无根者） | 你愿不愿意在所有人都押了注的事里，谁的注都不接？ | 两边都通知（各得一半的恨）/ 两边都不通知（自己得两个仇家） |

| 幕 | 名称 | 目标体验 | 时长（估） | 结局效果 |
|---|---|---|---|---|
| 一 | **最后一班差事** | 你才知道这江湖已经没人了 | 60–90 分钟 | 入 13 深门之一；拿到一张"没人敢去的地方"的名单 |
| 二 | **无人认领的一笔账** | 你开始替别人担事 | 3–5 小时 | 声名明显变动，至少一个人处境变差 |
| 三 | **上一个时代的人开始失踪** | 传说开始真的变成尸体 | 6–10 小时 | 一名具名 NPC 永久死亡或失踪（写死存档） |
| 四 | **众目之下的那一刀** | 铺垫一次性兑现 | 4–6 小时 | 江湖格局一变，玩家必须选边或出走 |
| 五 | **该收的都收了** | 你终于成了那个"已经谢幕的人" | 收尾 | 二十年后别人谈论你（终局信件） |

### D.2 第一幕完整脚本（本幕是重做的验收样张）

**【第一幕】最后一班差事**

**场景 1 · 茶摊（0–8 分钟）**
玩家按楔子落脚。此处逐字执行 §I 的卯时至辰时。

**场景 3 · 江南城·城东当铺（20–35 分钟）**

> 当铺柜台比人高，柜上有道包了铜皮的边，磨得发亮。掌柜接过那封信，只看封皮，不看里面的字。
>
> 「这个印，」他把信往柜台上一放，指腹在封皮上蹭了一下，「三年前的腊月按的。按的时候人还在。」
>
> 你问现在人呢。
>
> 「牢里没了。」他说得很平，「你想看单子我把单子找给你 —— 不过那单子七个月前就卖了。」

**他已经把记录卖了。** 这就是这个时代的质地：信息是商品，而且早就流失了。

**场景 4 · 第一次不可逆选择（35–45 分钟）**

玩家回茶摊复命，此时必须做一件事：**告诉老汉 —— 或者不告诉。**

- **告诉**：老汉沉默很久，说「知道了」，再不提。**第二天玩家的地图上多出一条新路（死亡率高的山道）—— 有人悄悄替他探了路。**
- **不告诉**：三天后玩家再回茶摊，老汉不见了，灶是凉的，**粗布上留着那封信（同一个道具，同一个 ID）。玩家可以捡起来，但从此没有任何人替他作证。**

> 两者都不扣数值，只改变世界。这是全篇的基调：**代价永远是具体的人和具体的路，不是 −10 点。** 茶摊还在（可以反复回来），但人不一定。

**场景 6 · 山门（55–80 分钟，第一幕收尾）**

按 `BIRTH_SECT` 映射落在 13 家之一，执行 §I 第六步。

### D.3「手动操作的互动场景」设计范式

> 这是主人点名要的东西：**「有真正需要玩家手动操作进行互动的场景，给人实感」**。
> 现状：全库 `room.actions` 是一次性按钮（触发一次命令就完），且**新手路径沿途为 0**。

**范式定义（手动件 Handpiece）**

一个手动件 = **一组带状态的手势**，必须同时满足五条：

| # | 要求 | 说明 |
|---|---|---|
| **H1 多步** | ≥3 个具体操作，且**顺序有意义** | 不是"点一下成功" |
| **H2 身体成本** | 每步消耗气力 / 时间 / 道具 / 承担一点风险 | "手上有重量" |
| **H3 环境参与** | 天气、时辰、地面湿度、负重会影响结果 | 让世界插手 |
| **H4 可失败可恢复** | 失败有具体后果，但不致命，可以重来 | 不惩罚到不敢试 |
| **H5 永久痕迹** | 成功后**房间描述永久改变**，且至少一个人会记得 | 实感的来源 |

**三个模板（任选其一复用）**

| 模板 | 骨架 | 用于 |
|---|---|---|
| **T-A 体力件** | 松 → 抬 → 垫 → 挪 | 挪缸、抬梁、推车、搬石 |
| **T-B 手感件** | 摸 → 辨 → 下手 → 复位 | 开锁、摸黑抽匣、挑断封绳而不破封条 |
| **T-C 身法件** | 探 → 稳 → 过 → 落地 | 独木桥、跃涧、翻墙、踩瓦 |

**具体示例 · T-A「挪缸」**（新手第一件，**替代现在"点一下交谈就拿信"**）

> 灶离不了水。缸在墙根，半缸水，缸身一道旧裂纹，裂纹上抹过灰。
>
> **①【伸手】** — 你试着把手插进缸沿底下。缸太沉，手指嵌进去一截，拔不出来，只能先放手。（失败：指尖勒出一道白印，**气力 −1**）
> **②【倒水】**（需容器）— 倒出半缸水，地上一片湿。缸轻了一半。（副作用：**缸变滑了**）
> **③【撬】**（需力器）— 你把扁担插进缸底与地的缝里。压下去，缸歪了 —— **你听见裂纹张开的声音。**
> **④【垫】**（需找得到东西）— 你垫了块木板，再压。这次缸没裂。
> **⑤【挪】** — 缸离墙三尺。墙根留下一片永远干不了的湿印。

**结果**：第 ⑤ 步完成后，房间描述永久追加一句「墙根有一片水渍，怎么也干不了。」老汉看了你一眼，这才从怀里摸信。

> **为什么比"点一下拿信"好**：玩家知道那封信是用"手上有泥、肩上有缸"换来的。**人只会记住自己出力换来的东西。**

**具体示例 · T-B「夜入签押房」**（主线事件，示范 H3 与不可逆）

> 三更，签押房。桌上一匣，匣上一道封条，封条**干了但未完全干**（早到会湿、晚到会脆 → H3）。
> **①【听】** — 每 30 秒给一次脚步远近反馈。错判则重来并 +30 秒。
> **②【挑】** — 挑封条。若匣屉顺序错 → **封条破损，本次永久失败**（且这笔账记在少数知道此案的人头上 → H5）。
> **③【抽】** — 抽屉有涩感，里面有东西会滚：必须在抽屉完全出来之前按住。
> **④【复位】** — 一切放回原样。复位不干净 → 三天后衙门会顺着线索找到最近的访客。

### D.4 强剧情如何驱动流程（不要让检查表驱动）

现在：完成任务 → 系统打开下一个 stage。
改成：**世界里的某个人，因为你做过的某件事，主动来找你。**

| 机制 | 实现要点（承接已有系统） |
|---|---|
| **上门** | 扩展 `npclife` / `patrol`：带条件的 NPC 会走到玩家房间，**说出与那件事相关的第一句话**，然后离开 |
| **扣住** | `storybeat.hold/takeHeld` 已有机制；扩展为：被扣住的剧情由 NPC 触发释放，不再等玩家点"追踪" |
| **说不的机会** | 每个重要剧情给玩家一个明确的"不"。拒绝不是死路，而是**换一条更窄的路**（配合三条线） |

## F. 战斗重设计

### F.1 为什么"现在的战斗很怪"（实测）

对 `GameEngine` 做了一次实测：满状态玩家在茶摊动手打人。

```
[combat] 你向老周发起了攻击！
[plain]  范清面色一沉，手按兵刃，警惕地盯着你。
[warn]   游侠断喝一声，横身拦住：「住手！光天化日，动手伤人算甚么本事！」
[plain]  卖茶的老汉面色一沉，手按兵刃，警惕地盯着你。
── 第一次执行「自动战斗」──
[combat] 游侠使出一招「长拳」，击中你，造成 93 点伤害。
[combat] 游侠使出一招「长拳」，正中要害（暴击），造成 160 点伤害。你倒地不起！
[faint]  你眼前一黑，什么都不知道了……
[faint]  不知过了多久，你在一阵草药味里醒转 —— 是江南城·悦来客栈的伙计把你从路边背了回来。
```

**四条病灶**

| # | 病 | 根因 | 后果 |
|---|---|---|---|
| **C1** | **玩家没出手就结束** | `step()` 一次调用结算**所有单位**，排序靠"身速+随机"；`auto` 循环最多 60 回合 | 打一次等于打六十次，玩家没有任何回合内输入 |
| **C2** | **761 门武学共享一句句子** | `oneAttack()` 结尾固定为：`使出一招「X」，击中Y，造成 N 点伤害。` | 所有武学打起来一模一样 —— **这是"战斗很怪"的主因** |
| **C3** | **数字代替了描述** | 伤害直接暴露数值 | 数字主导了阅读，沉浸被摧毁 |
| **C4** | **围观者全变成参战者** | 目击反应把旁观者拉进战斗 | 攻击任何人 → 三打一 → 秒败，玩家不敢动手 |

### F.2 新规则

**① 回合驱动：一指令 = 一手，每回合玩家先决策**

```
不再有一键打完。每一回合玩家必须选一个动词：
  出（抢攻） / 变（变招） / 守（凝神） / 撤（拉开距离） / 擒（只在近身可用）
```
- `auto` 保留，改名 **「挂机」**，明确标识"你在这儿看戏"，不作为默认玩法入口。
- **先手规则**：第一回合永远先问玩家。若是被伏击，则对方先出一手后立刻把处置权交回玩家。

**② 身位 + 架势 —— 两层可读信息**

| 身位 | 可用动词 | 说明 |
|---|---|---|
| **远**（两步以上） | 撤、出（暗器 / 音波 / 长兵） | 距离是资源 |
| **中** | 出（多数武学）、守、变、撤 | 默认交手位 |
| **近** | 擒、出（短兵 / 拳）、守 | 抢得先机，也更容易被反打 |

三者互相克制：**抢攻克防守消耗，变招克抢攻预判，防守克抢攻反震**。让"打赢"变成读数与选择，而不是把血条打到 0。

**③ 演出从"数值句"改为"身体句"（核心改造）**

不再输出单一模板。改为 **动词 × 部位 × 程度** 三层组合，每层手写。

```
动词层（按武学类型分池，每池 ≥12 条，无重复）
  剑：抹、挑、点、削、挑开、压住……
  刀：劈、剁、斜斩、撩、砸、背砍……
  拳：捣、掖、摔、肘击……
  暗器：甩手、反手抖袖、指弹……
部位层（≥10 处）
  面门 / 咽喉 / 左肩 / 右肋 / 手背 / 前膝 / 脚踝 / 后颈 / 指节 / 腰带
程度层（替代"造成 N 点伤害"，5 档）
  蹭了一下不算伤 / 挂脏了 / 见了血 / 伤到骨 / 站不住
```

样例输出：

> 他一刀斜劈下来，你抬左臂架住，刀刃在皮袄上滑过去，贴着小臂划了道白印。前臂麻到肘。
>
> 你反手一个掖捶打在他右肋，他身子一歪，鞋底在青石上蹭出一声。你听见他吸了半口气，那口气没吸完。

> **数值去哪了**：默认**拟真模式**（只出现伤势程度词），设置里可开「数值模式」。新号默认拟真（主人明确要沉浸式）。

**④ 围观者不再自动参战**（修 C4）

| 现在 | 改成 |
|---|---|
| 三名旁观者全部加入战斗 | 只有被攻击者本人与官差会动手；其余人**指认、跑去报官、拦架**。三件事都产生后续（报官 → 通缉；拦架 → 该 NPC 对玩家好感 −30 并被记载） |

**⑤ 濒死保护（兼作演出）**

任何一次"从 50% 以上掉到 0"改为：**留 1 血 + 强制播放一段倒地演出**（不是直接昏到客栈）。给玩家一个"撑着站起来 / 认输 / 被拖走"的处理机会。**既保住危险感，又去掉"莫名其妙就回客栈了"的断裂。**

### F.3 战斗密度与节奏

| 参数 | 建议区间 | 依据 |
|---|---|---|
| 普通战斗回合数 | **4–9 回合** | 改为每回合一个按键后，>12 回合会疲劳 |
| 同级敌人的解决回合 | **3–6 回合** | 与上一致 |
| 成名高手 / 首领 | **8–15 回合**，保留 `bossPhases` 三阶段（现有机制可用） | — |
| 同级之间命中率 | **0.62–0.82**（现公式下限 0.25 太低） | 连续打空是"战斗很怪"的亚型 |
| 暴击率 | **0.05–0.18** | — |
| 逃跑成功率 | 首次 **0.55–0.75**，连续逃跑递减到 0.25 | 玩家必须有活路，但不许无限逃 |

### F.4 战斗反馈层级

| 层 | 载体 | 例 |
|---|---|---|
| L1 手感 | 战斗文本（见 F.2 ③） | 「刀刃在皮袄上滑过去」 |
| L2 状态 | 面板 / 血条色相 | 见红 / 见黑 |
| L3 声音 | 音效（可由 `ambience` 派生） | 骨响 / 衣裂 / 闷哼 |
| L4 世界 | **战斗后房间留下永久痕迹** | 翻倒的凳子、墙上的血掌印、被人踢开的碗 |

> L4 是**最便宜也最有效**的一层：打完一架留下一个具体的印迹，玩家就信了。

## G. 门派玩法循环

### G.0 病

43 家门派在数据上看起来一样（`72_sects_tier` 里 29 家缺 `name/desc/ranks/require`）；165 名弟子共用 3 个数值。玩家进了任何一家，遇到的是同一套。

### G.1 分层（最省力的解法）

| 层 | 数量 | 内容 | 能不能入 |
|---|---|---|---|
| **深门** | **13** | 完整循环（G.2）、独立职级、真功夫、独立门务 | ✅ |
| **门面** | **30** | 3–6 间房、1 位当家、2 门立派功夫、1 条支线、在地图上出现、会被传闻提到 | ⚠️ 只能投靠 / 挂名，不入师门 |

> **为什么不全删**：这 30 家的房间与 NPC 是地图密度的一部分；全删会让 200 余间房瞬间空掉。**降级比删除划算。**

### G.2 门派循环（四环，缺一环这一家就不算"有玩法"）

```
  入门（仪式）──► 日常（习艺 / 当值 / 门差 / 人情）
       ▲                                  │
       │                                  ▼
   立户（有自己的份位与名下账）  ◄────  出头（位次挑战 / 大典夺魁）
```

| 环 | 做什么 | 产出 | 手感 |
|---|---|---|---|
| **① 入门** | 手动件（不一定是打架 —— 也可以是"背下门规并在廊下认出三位师兄的名字"） | 一个名分 + 一件信物 | 你用手 / 用嘴换来的 |
| **② 日常** | **四选一**：习艺（练功 / 请教）、当值（扫除 / 巡山 / 看库房）、门差（替门里办事）、人情（同门之间送酒 / 代班） | 贡献 + 好感 + 少量银钱 | 可选 = 活的；全都要 = 上班 |
| **③ 出头** | 排位挑战 / 大典夺魁 / 接下别人不敢接的差事 | 位阶上来一次 | 需要具体的对手（人格化的同门） |
| **④ 立户** | 有自己的屋子 / 收徒 / 在门里留下名下的一笔账 | 长期关系锚 | 你在门里有了"自己人" |

**睡前必须留下的东西**：每天玩完，玩家应该能说出一个**具体的、有名字的同门**今天发生了什么变化。做不到，这一天的门派内容就失败了。

### G.3 样张：华山（其余 12 家照此结构展开）

| 环节 | 内容 | 手动件 |
|---|---|---|
| 入门 | 需在思过崖石壁前待一夜，认出壁上二十七道剑痕里哪一道是本门前辈的 | ✅ T-B（摸 → 辨 → 认） |
| 日常·当值 | 巡山道，检查三处界石（雪天会有脚印） | ✅ T-C（部分路段） |
| 日常·门差 | 替掌门送一封信去另一家，路上可能被截 | 路程 + 遭遇 |
| 出头 | 门内大比：连胜三位具名师兄（各有自己的套路与口头禅） | 战斗（F.2） |
| 立户 | 有资格要一间屋子；屋子会在痕迹系统里被标记 | 家宅系统已存在 |

> 关键：**每一家必须有一件"只有这家才有的手动件"**。13 家 = 13 件，这是写得出来的工作量。

## H. 地图内容密度方案（"不空"）

> 本节只谈**内容密度**（房间里有什么）。界面的信息架构与视觉层级见新增的 **§M**。

### H.0 病：不是地方少，是地方里没有东西

- 房间平均 38 字；536 房只有 388 条不同描述。
- 96% 的房间没有 NPC 常驻（834 人分布在 368 间房，中位数 2 人）。
- **0 间房有地面物品** —— 世界从不掉东西。
- 新手沿途前几间房：`actions = []`。

### H.1 五项改造（按性价比排序）

| # | 改造 | 目标 | 数据量 |
|---|---|---|---|
| **H-a** | **房间三段式**：① 固定描写（地形/材质/气味，30–60 字）② **动态句**（时辰 / 节气 / 天气 / 玩家带来的东西，1 句）③ **痕迹句**（人留下的旧痕 / 近期发生过的事，1 句） | 每段都能单独成立，组合后不可预测 | 重写 200 间 + 生成器改造 336 间 |
| **H-b** | **痕迹系统**：玩家 / NPC 做过的事会在房间留下 `marks[]`，**追加在描述之后** | 同一间房每次来都不一样 | 引擎增加 `room.marks` |
| **H-c** | **地面物品**：所有房间按类型给一份掉落规则 | 地面不再永远空 | 数据表增加 `groundSpawn` |
| **H-d** | **密度底线**：每间房 ≥1 个不可替换细节；每间有人住的房 ≥1 个可交互物；每个州域 ≥1 个手动件 | 消灭空白房 | 守卫 + 补写 |
| **H-e** | **遭遇与路上小事**：道路型房间按时辰 + 天气出事件 | 走在路上会碰上事 | `encounter.js` 已存在，缺的是内容 |

> H-b 是"实感"最便宜的来源：你挪过缸的地方永远有水渍。
> H-c 是目前数值为 0 的一项，一个最小改动就能让世界"会掉东西"。

### H.2 动线（现在平均出口数 2.05，地图基本是线性走廊）

| 指标 | 现在 | 目标 |
|---|---|---|
| 平均出口数 | 2.05 | **2.6–3.0** |
| ≥3 出口的房间 | 110 / 536（21%） | **≥45%** |
| 州域内部环路 | 少 | **每个州域至少 1 条环路** |

> 为什么重要：走廊型地图让"迷路"变成"走轴"，玩家没法对空间形成心智图。有环路后，"绕近路"才成为一种知识。

### H.3 环境演出（框架已有，缺内容）

`ambience.js` 的 16 类场所 + 三类移动播报系统写得很干净。缺的是**每句都值得读**。

| 现状 | 改法 |
|---|---|
| 每类场所一套句库，全城共用 | 保留共用池用于"常见音"，**每个具体地点补 2–3 条只有这儿能听见的声音** |
| 一次 tick 最多 3 条 | 保留（节流是对的） |
| 播报「某某往北去了」 | 加入**为什么**：「某某往北去了，手里提着个空壶」—— 尾缀从他的随身物件里抽，NPC 立刻有了故事 |

## I. 新手引导剧本：「腊月廿八，从卯时到亥时」

> **设计原则**：主人曾亲自下线过一个"教程"（因为它是"教"，不是"发生"）。所以**不再有教程** —— 改为"你到达的这一天"。
> 所有"该做什么"以**在场的人正在做什么**的形式出现，而不是提示条。

### I.0 结构（目标：第一个动作在 3 分钟内自然发生，60 分钟内到山门）

| 时刻 | 场景 | 用户行为驱动力 | 应承担的教学 |
|---|---|---|---|
| 卯时 06:00 | 楔子卡（保留现有 13 版，写得很好） | 关心"我是谁" | 出身 / 世界观锚点 |
| 卯时 | 老槐树·茶摊 | **看四周**（自有欲望：这是哪儿） | `look` |
| 辰时 | 茶摊·挪缸（**T-A 手动件**） | 缸挡了路，不管就走不了 | 亲手操作 + 界面熟悉 |
| 辰时末 | 拿到引荐信 | 老汉指了一个具体的山名 | "接下来去哪"第一次明确 |
| 巳时 | 出江南城·南门 | 有人拦路要钱 —— 给了钱会显示银钱变少 | 路上的开销与时间是真的 |
| 午时 | 青溪村接下一个差事 | 村民请他带一句口信，只需一个方向 | 支线的标准形态：小、具体、当天可完成 |
| 未时 | 回城完成差事 → 得一件旧物 + 老汉的一句话 | 第二次操作回忆 | 完成 → 回报 |
| 申时 | **出门北上（第一幕路线启动）** | 引荐信在手，山那边有去处 | — |
| 酉时 | 荒野·独木桥（**T-C 手动件**） | 天暗了，过不去就要在野外过夜 | 身法 / 负重的物理体验 |
| 戌时 | 山脚下小店歇一晚 | 累了、饿了 | 住宿 / 餐饮 / 存档 |
| 亥时 | **第一天结束**；屏幕上仅一句「给今天留句话」 | 用户为自己做了一件有温度的事 | 存档 + 一条属于这局的记录 |

### I.1 不可出现的四件事

| 不要 | 替代 |
|---|---|
| 数字进度条（3/8） | 由"天色"与在场人的催促承担 |
| 「按 look」这类键盘提示 | 让房间第一句就给出吸引点（水缸在挡路） |
| 弹窗教学卡 | 全部内容由房间文本与 NPC 台词承载 |
| "先打一只狼"这类机制验收 | 首个"动手"是搬缸（身体），不是打架 |

### I.2 必要的扶手（藏在世界里）

- **看** —— 每个房间至少留一条让人想跟进的细节（守 C.4）。
- **问** —— 老汉 / 村人都可以问；`askTopics` 的三档优先级是对的，保留。
- **地图** —— 只显示当前州域 + 在出口上标注距离（见 §M）。
- **迷路时** —— 在路口留脚印 / 车辙（**是字面上的人为痕迹，不是任务标记**），让玩家学着自己看地方。

## J. 数值与进度框架意见

### J.1 总体判定

| 派生 | 建议公式 | 区间 |

## L. 分期实施路线（已按技术架构总监结论重排）

> 技术架构总监的结论（v1.1 采纳）：
> - **数据层静默杀手**：833 个 NPC 里有 **473 个被多个数据文件重复定义**；房间 **118/531 重复**；**43 个门派全部重复**；而 `mergeData` 的数组默认是 **replace 语义**（`world.js:269`）。改 NPC 的 `teach / quests / talk` 时只要写成"增量补丁"，整段会被**静默替换** —— 不报错、不崩、游戏照常能跑，内容就是不见了。
> - **数据规模**：53 个数据文件 3.41 MB，其中地图数据 276 KB（约 8%）。
> - **性能修复 P0 已派给主程序**（单步下行 355.8 KB → 目标 27.6 KB）。

**因此 L 节的节奏原则是：**

> **数据的批量增删改，最早也要等 P1 的三道闸落地之后。在那之前，设计侧只出方案与文案，不动数据文件。**

三道闸：① 加载 fail-fast；② 补丁区强制声明 `arrayMode`；③ 重复 id 与出口形状守卫。

| 「地图只剩当前区域单视野」 | **只有 UI 是单视野，后端回包仍是全量**：`map.rooms` = **512 间房，覆盖全部 35 个州域**（长安 35、江南 32、洛阳 27、襄阳 27、华山 23…）。过滤发生在前端 `mapHtml()` | 回包体积 285 KB；**且新角色 `explore: {visited:1, total:512}` —— 一级玩家在回包里能读到全世界 512 个房间的名字与坐标** |
| 「bridges 234 条」 | ✅ 确认 234 条，其中 **43 条跨州** | 数字对得上（CSS 注释里那句"实测 154 条"是过期文字） |

**回包体积拆解（实测）**

| 字段 | 体积 | 说明 |
|---|---|---|
| `regions[].rooms` | **100.1 KB** | 35 个区，每个区内嵌完整房间数组 |
| `rooms[]` | **90.8 KB** | 同一批房间的**第二份副本** |
| `terrain` | **44.4 KB** | 34 个区的地形，一次全发 |
| `cells` | 27.9 KB | — |
| `bridges` | 16.4 KB | — |
| 其余 | 约 5.6 KB | — |
| **合计** | **285.2 KB** | 而 `view` 不带地图时只有 **22.3 KB** |

> **结论：地图回包里有 90.8 KB 是纯粹的重复数据（`rooms[]` 与 `regions[].rooms[]` 内容同一批）。** 光是去掉这一份，就能从 285 KB 降到约 194 KB；再按州域分批取，可降到 30 KB 以内。

### M.2 地图为什么让人觉得"大但是空"

不是因为格子少，是因为**它给的是名字，不是地方**。

| 层次 | 现在给的 | 玩家真正想知道的 |
|---|---|---|
| 一眼看到 | 512 个 4 字短名排成的网格 | 我在哪、这是什么地界、往哪能走 |
| 格子本身 | 一个方块 + 一个被砍短的名字 | 这地方是什么（庙？铺子？人家？野地？） |
| 格子之间 | 一条线（表示有出口） | 多远、多久、路上有没有事 |
| 没去过的地方 | 与去过的地方同样是白格 | 那里是黑的，我不知道 |

**更根本的一条**：地图现在**替文本说话**（把房间名摆出来），而它本该做的是**补文本说不清的三件事：方位、远近、区域关系**。房间长什么样、有什么人，那是文本的事。地图把名字摆满，等于把文本已经讲过的东西又讲了一遍，而且讲得更差。

**还有一个内容侧的根因（与 A.2 同源）**：27% 的房间是模板粘贴的产物 ——

- **11 座山共享同一套六段山路**：`石阶 / 松林 / 半山亭 / 林间道 / 山泉 / 崖边路`（华山、少林、武当、峨眉、大理、唐门…）= 66 间房
- **4 座山村共享同一套四间**：`村口 / 打谷场 / 茶棚 / 山神庙` = 16 间房
- **22 座藏经阁 + 42 座藏宝阁** = 64 间房

**这些模板房在地图上还是以坐标直线出现的**（华山 path1–6 落在 x=27…35 的一条直线上）。所以玩家在图上看到的是：一条由六个雷同小格组成的直线，后面接一座雷同的山。**"大但是空"的第一现场就在地图上。**

### M.3 地图的角色定位（定方向）

> **地图是"你去过的地方的私人笔记"，不是"世界的完整图纸"。**

三条定位：

1. **它是世界感的载体，也是导航工具，但顺序不能反** —— 先让人觉得"世界很大、我去过的地方很少"，再帮他在去过的地方里找路。
2. **地图只补文本说不清的**：方位（我在哪、朝哪走）、远近（多少里、多少日）、区域关系（这边属哪一州、出去是哪）。**长什么样、有什么人、发生了什么，一律交给房间文本。**
3. **未去过的地方必须是未知的。** 知道全世界 512 个房间的名字，就已经没有江湖了。

### M.4 数据侧：地图属于「按需取」，不常驻

| 决策 | 结论 | 理由 |
|---|---|---|
| 常驻还是按需 | **按需取**：打开地图面板才请求，且**只请求当前州域** | 与"单步下行 27.6 KB"的目标同一条战线；一份 285 KB 的常驻数据会直接吃掉性能修复的收益 |
| 取数粒度 | **按州域分批**：`/api/map?region=jiangnan` | 单州最大约 35 房，估算 <8 KB |
| 服务端过滤 | **过滤上移到后端**，不再下发全量让前端筛 | 同时解决体积与剧透两个问题 |
| 迷雾 | **只下发"已探索"的房间的完整信息**；未探索的房间下发**占位坐标 + `known:false`**，不含名字 | 新玩家看到的图应该是"一小片亮 + 一大片黑" |
| 地形 `terrain` | 只取当前州域一份 | 省 43 KB |
| `regions[].rooms` 与 `rooms[]` | **去一份** | 省 90.8 KB |
| 缓存 | 前端缓存已取过的州域，跨州回来不重取 | 减少往返 |

**目标：地图回包从 285.2 KB → 单州 <8 KB；即便全州都取过也不超过 30 KB。**

### M.5 界面侧：信息架构与交互

#### M.5.1 该显示什么、不该显示什么（信息架构）

**四层视觉层级（由强到弱）**

| 层 | 内容 | 视觉权重 | 说明 |
|---|---|---|---|
| **L1 我在这里** | 当前房间 | 最强（唯一的高亮 + 光标形） | 一眼必须找到自己 |
| **L2 我从哪来** | 已走过的格子 + 走过的连线 | 中（实色、连线为实线） | "我的足迹"是地图的情感核心 |
| **L3 我附近有什么** | 当前房间的直接邻居（哪怕没去过） | 中偏弱（轮廓可见、名字不显示） | 让玩家知道"往哪能走"，但不剧透内容 |
| **L4 远处与边界** | 州域名、州域边界、出口方向 | 弱（大字 + 淡色） | 区域关系与"出去是哪" |

**该显示的**

- 当前房间（L1）
- 走过的格子与走过的路（L2）
- 相邻但未去过的格子，显示为**空白格 + 一个可走的箭头**（L3）
- **当前州域的名字与一句地点气质**（例如「江南 · 烟雨江南，繁华地」）—— 一行，不是图例
- 州域出口：在边界上标「向西 → 洛阳，四百八十里」（**距离与耗时，见 B.3**）
- 上下层的 ▲/▼ 角标（现有，保留）
- **「回到我」按钮**（2026-10-12 被删，建议回来 —— 平移后找不回自己是硬伤）
- 一行内嵌说明（替代独立图例块）：「亮的是走过的，暗的是没去过的」

**不该显示的**

| 不要 | 原因 |
|---|---|
| 未去过的房间的**名字** | 剧透，且"知道名字"不等于"知道地方" |
| 512 个格子全画出来 | 现在 UI 只画本州，但**观感上仍是"一堆白格"**；应改为"一小片亮 + 一圈邻格 + 大片未知" |
| 全世界的州域名列表 | 未去过的州只显示**方位与里数**，不显示名字以外的信息 |
| 与房间文本重复的内容 | 地图不要再复述"这间房叫什么"以外的信息 |
| 坐标 / 网格线 / 缩尺 | 破坏"笔记"感，那是工程图不是江湖图 |

#### M.5.2 玩家怎么看、怎么点、怎么走（交互方式）

| 动作 | 行为 | 说明 |
|---|---|---|
| **看** | 打开面板 → 自动居中到"我"，只渲染本州 | 不需要先点任何东西 |
| **悬停** | 已走过的格子显示**全名 + 一句你在这儿做过的事**（来自 `marks`） | 这是地图与痕迹系统的结合点，也是"实感"的来源 |
| **悬停（未走过）** | 只显示「未去过」，或若相邻则显示「往北，未走过」 | 不给内容 |
| **拖动 / 缩放** | 保留（现有 ± 与拖拽是对的） | — |
| **「回到我」** | 一键居中回当前房 | 建议恢复 |
| **点击（有条件恢复）** | **只允许点击"已走过且相邻"的格子** → 走真实寻路与耗时，不是瞬移 | 这解决了 2026-10-12 删除它的顾虑（防剧透 + 防跨州瞬移），同时找回"在图上走"的爽感 |
| **点击州域出口** | 弹出「向西 → 洛阳，四百八十里，步行九日 / 骑马四日」，可确认出发 | 距离信息（B.3）的落点 |
| **点击未去过的格子** | **不响应**，只给一句「你还没去过那儿」 | 不剧透 |

#### M.5.3 与房间文本的分工（明确边界）

| 信息 | 归谁 |
|---|---|
| 这地方长什么样、有什么气味声音 | **房间文本** |
| 这里有谁、他们在做什么 | **房间文本** |
| 这间房发生过什么（痕迹） | **房间文本**（地图悬停时引用一句） |
| 我在哪、朝哪走 | **地图** |
| 多远、多久、路上要什么 | **地图 + 出口标签** |
| 这地方属哪一州、出去是哪 | **地图** |
| 我去过哪、没去过哪 | **地图** |

> **一句话**：地图负责**关系**，文本负责**质地**。任何一方越界，另一方就会显得多余。

### M.6 内容侧：让地图本身不再"雷同"

界面改好了，格子里的名字还是得不一样。三条：

| # | 做法 | 说明 |
|---|---|---|
| **M-c1** | **拆掉 11 座山的通用六段山路**：每座山按自己的气质重命名并改写（华山是"千尺幢/苍龙岭"，武当是"上下十八盘"，峨眉是"钻天坡/九十九道拐"） | 66 间房不再同名 |
| **M-c2** | **拆掉 4 座山村的通用四间**：每村按营生重命名（采药村 / 烧炭村 / 采石村 / 猎户村），各有自己的物产与烦心事 | 16 间房不再同名 |
| **M-c3** | **22 座藏经阁与 42 座藏宝阁收编**：藏经阁只在 13 家深门保留（其余改为"某某的书房/账房/香堂"），藏宝阁同理收缩 | 腾出 40 余间房的名额给有内容的房间 |

> 这三条与 §H 的房间重写是同一批工作，不额外开工，但要**在地图的命名规则里单独立一条底线**：**同一个州域内，任意两间房不得只差一个前缀。**

## 一句话总结给主理人

> 这个游戏的病**不是缺内容，是缺"只属于此处的那一句话"**。536 间房只有 388 条不同的描述，834 人共用 453 行台词，761 门武学里 600 门是同一个生成模板，11 座山共享同一套六段山路，而地图把全世界 512 个房间的名字一次性塞进了回包。**修复的杠杆不在写更多，在删掉重复的、给留下来的每一处写一个别人抄不走的细节。**
>
> 建议从 P0 的两件「修量具」开始：**翻转 AI 味守卫阈值** + **上线归属守卫**。这两件总共不超过两天，但它们决定了后面所有稿子能不能变好。
>
> 地图那一块，请在 P1 把**回包瘦身**与**性能修复**合并做 —— 它们是同一件事的两半；顺带能修掉"一级玩家能读到全世界房间名"这个剧透问题。
