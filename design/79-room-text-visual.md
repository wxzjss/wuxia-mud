## 〇、四条实测事实（决定后面所有取舍）

### 事实 1：三段**不在同一处渲染**，不是我想象的"三行日志"

| 段 | 面板（上方大框 `#room-desc`） | 日志区 |
|---|---|---|
| ① 固定描写 `room.desc` | ✅ **常驻**（ui.js:236，每次进房重画） | ✅ `look` 时推 `kind:'desc'`（commands.js:658） |
| ② 动态句 `room.ambient` | ❌ 无 | ✅ `kind:'ambient'`（ambience.js:82） |
| ③ 痕迹句 `p.roomNotes[roomId]` | ❌ 无 | ❌ **尚未实现**（全仓 grep `roomNotes` 为空） |

⇒ 视觉分层**只需要治日志区那一份**；面板里那份①是常驻底噪，另论（§2.4）。

### 事实 2：`kind:'desc'` 目前**没有样式**，掉回默认

`ui.js:364` `const type = l.type || l.kind || 'plain'`，而 CSS 里**没有 `.log-line.desc`**（grep 为空）。
所以①现在吃的是 `.log-line.plain { color: var(--ink-2) }` —— **比它应有的淡了一档**。
本来该是"这地方长什么样"的正字，现在看起来像旁枝末节。

### 事实 3：现有 `.log-line.ambient` 三处全踩约束

```css
/* main.css:893 —— 现状 */
.log-line.ambient { color: var(--ink-4); font-size: 12.5px; font-style: italic; opacity: .88; padding-left: 2px; }
```

| 写法 | 问题 |
|---|---|
| `font-size: 12.5px` | 日志正文 14px。跳字号就跳行高，整块日志跟着抖（76 §3.2 同款理由） |
| `font-style: italic` | 全库无 webfont，`--font` 是纯系统栈 ⇒ italic 是**合成倾斜**，14px 中文下笔画糊（76 §1.2 已判定过同样的字重问题） |
| `opacity: .88` | 再砍一档对比度。实测：亮色 `--ink-3 #6f675a` 本已只有 4.94，叠 .88 后掉到 **3.87** ✗ |
| `color: var(--ink-4)` | `--ink-4` 现值暗 3.58 / 亮 2.76，**两套都不达标**（78 §2.1） |

四条都要改。

### 事实 4：日志区**已经有两根左竖条了**，战斗是第三根

| 竖条 | 选择器 | 形态 |
|---|---|---|
| 剧情行 | `.log-line.story`（main.css:777） | `border-left: 3px solid var(--line)` + `padding-left: 10px` |
| 任务行 | `.log-line.quest`（main.css:875） | `border-left: 3px solid var(--jade)` + `padding-left: 8px` |
| 战斗行 | `.log-line.combat::before`（main.css:807） | 绝对定位，宽 2→6.5px、长 32%→100%、朱色阶 |

**再加房间三段，就是第四根。** 这是本篇最关键的判断依据，见 §一。

## 一、结论先行：**不沿用 76 的竖条**

主理人倾向沿用竖条，并要我判断、给区分说法。**我的判断是不沿用。** 三条理由：

### 1. 它们量的是两种不同的东西

| | 战斗五档 | 房间三段 |
|---|---|---|
| 量的是 | **程度**（连续量：蹭了一下 → 站不住） | **类别**（离散量：地方 / 此刻 / 你） |
| 需要的通道 | **可递增**的通道（宽 / 长 / 色阶能单调变化） | **可枚举**的通道（位置 / 形状能一一对上） |

拿量"程度"的工具去量"类别"，玩家会误读成"房间的杠也有轻重之分"——
他会以为动态句比固定描写"轻"，而实际那只是**另一种东西**。

### 2. 房间三段用竖条会直接撞车

日志里 story / quest 已经是两根 border-left，战斗是第三根 `::before`。
房间三段若再来，屏幕上一屏内最多同时挂着**四根差不多的竖杠**——
这正好是主理人担心的那个结果："别让玩家看见两根差不多的杠"，而实际会变成四根。

### 3. 竖条是"**程度**"的专用记号，已经定了性

`design/76` 里竖条被赋予了明确语义：**宽 = 伤多重、长 = 伤多深、朱 = 血是谁的**。
它在玩家眼里已经是"打架的记号"。把它挪用到房间描写上，是**把一个刚建立的语义稀释掉**。

### ⇒ 那房间三段用什么

**用"起笔位置（缩进）+ 墨色深浅 + 一枚朱点"。** 三个理由：

- **缩进本来就是这条日志的类型通道**：`.log-line.plain`(0) / `.log-line.quest`(8px) / `.log-line.story`(10px) 已经在用它区分类型。
  房间三段属于**同一族**（类型），不是程度族。
- **缩进不影响行高**。`padding-left` 只动水平位置，完全满足"日志区是等宽流"这条硬约束。
- **缩进的语义天然对**：由外而内、由物及我，一级比一级往里——正是①→②→③的关系。

### 区分说法（主理人要的那句）

> **竖杠 = 多重，缩进 = 是什么。**
> 战斗行左侧那根朱杠，宽窄长短在说"这一下有多重"；
> 房间三段左侧的空白，深浅进退在说"这句话是谁说的"。
> 一个是**尺子**（量程度），一个是**座位**（分主客）。
> 玩家分辨它们不需要记两套规则——**他只要看左边有没有竖着的东西**：有杠的是打架，没杠的是看地方。

## 二、三段视觉规格

### 2.1 总表

| 段 | 类名 | `padding-left` | 字色 | 记号 | 灰度（去色）下的判据 |
|---|---|---|---|---|---|
| **① 固定描写** | `.log-line.desc` | **0**（齐头） | `var(--room-ink-1)` = `var(--ink)` | **无** | 最黑、齐头 |
| **② 动态句** | `.log-line.ambient` | **14px** | `var(--room-ink-2)` = `var(--ink-3)` | **无** | 淡一档、退一格 |
| **③ 痕迹句** | `.log-line.trace` | **22px** | `var(--room-trace)` = `var(--red)` | **行首一枚实心朱点** | 退两格、**有个点** |

**字号一律 14px、行高一律 1.8、不用斜体、不加 opacity、不加框、不加底色块。**

### 2.2 为什么是这个顺序和这个方向

由外而内：`0 → 14 → 22`，逐级往里退。
语义上就是游有方 §2.0 那句：**"先有地方，再有此刻，最后才有你"**。
地方铺在最外面（齐头、最黑、最实），"你"收在最里面（退两格、朱色、带个自己的点）。

### 2.3 ③ 为什么是朱 + 朱点（两条硬理由）

1. **朱是"我"的专用色。** `design/76` 定的总纲是「只有『我』配朱与金」。
   痕迹句说的正是"**你**在这间房留下过什么" —— 它是整段文本里唯一属于玩家的东西，用朱是规矩之内。
   （对照：战斗 4/5 档的朱是"我的血"，此处是"我的痕迹"，同一瓶朱砂，不冲突。）
2. **② 和 ③ 光靠亮度分不开，必须有形状。** 实测两色间对比：暗 **1.33** / 亮 **1.35** ——
   去色后几乎一样。所以 ③ 的朱点**不是装饰，是它的主判据**。
   和主理人对地图 M-2 拍的那一板是同一条道理：**单靠亮度的 ③ 不算实现完成。**

> ⚠️ **不要用金。** 亮色 `--gold #a8842c` 在纸上只有 **3.10** ✗（暗色 8.05 ✅），两套主题过不去。
> 朱 `--red` 暗 **4.60** / 亮 **6.67**，两套都过。

> 🔴 **墨阶变体甲落地后的连带（2026-10-13 预计算，取值一个字都不用改）**
>
> 甲会动 `--ink`（① 用）与 `--ink-3`（② 用），`--red`（③）不动。
> 我把 ②③ 那组互色对比按甲的新值重算了一遍：
>
> | | 现在 | 墨阶甲后 |
> |---|---|---|
> | ②↔③ 暗侧 | 1.33 | **1.637** ✅（更好） |
> | ②↔③ 亮侧 | 1.35 | **1.126** 🔴 |
>
> **亮色侧从 1.35 掉到 1.126** —— ② 和 ③ 几乎同色。
> 上面那句"朱点不是装饰，是它的主判据"，在甲落地后要升级成：
> **亮色主题下，那颗朱点是②③之间唯一还剩的判据。**
>
> ⇒ 对本份文档的结论没有任何影响（三段式的取值、顺序、朱点规格全都不动），
> 但**给 `design/81` 追加了一条硬约束**：
> `81/N-V-1`（可交互名词的形状主判据）在亮色主题下**不允许退化到 `@supports` 兜底的实线下划**——
> 兜底那条是线，会跟 `.exit-inline` 的虚线撞族，而此时②③已经几乎没有亮度差可退。
> 详见 `design/81` §4.2。

### 2.4 面板里那一份①怎么办（不放在日志里的那个）

面板 `#room-desc`（main.css:680）**保持 `--ink-2` 不动**，不改。

理由：日志里的①是"**你刚 look 到的**"，是一次事件，所以给最重的 `--ink`；
面板里的①是**常驻底噪**，一直在那儿，给 `--ink-2` 才不会跟日志抢注意力。
**同一个①、两种重量，是刻意的**——不是遗漏。

### 2.5 朱点规格

```
┌──────────────────────────────────────────┐
│  ●                                       │  ← 9px 处一枚 4px 实心朱点
│        这里是你上次歇脚的地方。          │  ← 正文起于 22px
└──────────────────────────────────────────┘
  0        9  13              22px
```

| 项 | 值 | 说明 |
|---|---|---|
| 形状 | 实心圆（`border-radius: 50%`） | 对应"你在纸上按了个指印"，与地图 L1 的朱印同族 |
| 尺寸 | `--room-dot: 4px` | 再小（2–3px）在 14px 行里看不出是圆的；再大（6px+）压过文字 |
| 位置 | `left: 9px`，`top: .9em`，`translateY(-50%)` | 落在 13–22px 那段空白正中，不碰正文 |
| 颜色 | `var(--room-trace)` = `var(--red)` | 装饰件，阈值 3.0：暗 **4.60** ✅ / 亮 **6.67** ✅ |
| 实现 | `::before` **绝对定位** | 与 76 同款理由：不参与布局，正文起始位置不受影响 |

⚠️ 用 `::before` 而不是 `list-style` / `background-image`：`list-style` 会引入列表语义（`ul/li`），
改动 DOM 结构；`background-image` 要额外一个资源或 inline SVG，而本项目**零外部资源**（只在 CSS 里画）。

## 三、CSS 落地

### 3.1 新增变量（`:root` + `html.theme-light` **成对**）

```css
/* ================= 三段式房间文本（design/79 §3.1）=================
   ⚠️ 字色三个全部 var() 到已有变量，不另起炉灶：
      改墨阶（78 §2.1-bis）时这三处自动跟随，不用回来改第二遍。
   ⚠️ 缩进是**类型通道**，不是程度通道 —— 战斗的 --combat-pad(15px) 恒定不变，
      房间的三段缩进故意不等。两者互不干涉。 */
  --room-indent-1: 0;        /* ① 齐头 */
  --room-indent-2: 14px;     /* ② 退一格 */
  --room-indent-3: 22px;     /* ③ 退两格 */
  --room-dot:      4px;      /* ③ 朱点直径 */
  --room-dot-left: 9px;      /* ③ 朱点圆心距左边缘 */
  --room-ink-1: var(--ink);      /* ① 正字，最重 */
  --room-ink-2: var(--ink-3);    /* ② 浮墨，淡一档 */
  --room-trace: var(--red);      /* ③ 朱 —— 「只有『我』配朱与金」 */
```

**全部不需要浅色覆写** —— `--ink` / `--ink-3` / `--red` 三者在 `html.theme-light` 里都已成对定义，
`--room-*` 只是转一手。缩进与尺寸是几何量，按 76 的规矩不覆写。

### 3.2 规则

```css
/* —— ① 固定描写：齐头、最重、无记号 ——
   ⚠️ 原来 kind:'desc' 没有样式，掉回 .log-line.plain(--ink-2)，
      比它应有的淡一档。这一条是**补上**，不是改。 */
.log-line.desc {
  padding-left: var(--room-indent-1);
  color: var(--room-ink-1);
}

/* —— ② 动态句：退一格、淡一档、无记号 ——
   ⚠️ 删掉原来的 font-size:12.5px / font-style:italic / opacity:.88：
      · 字号跳 → 行高跳，整块日志抖（76 §3.2 同款）
      · 无 webfont，italic 是合成倾斜，14px 中文糊（76 §1.2 同款）
      · opacity .88 把亮色 --ink-3 从 4.94 砍到 3.87 ✗ */
.log-line.ambient {
  padding-left: var(--room-indent-2);
  color: var(--room-ink-2);
}

/* —— ③ 痕迹句：退两格、朱色、行首一枚实心朱点 ——
   ⚠️ 朱点是**主判据**不是装饰：②↔③ 两色间对比只有 1.33/1.35，
      去色后亮度几乎一样，没有这个点就分不开。 */
.log-line.trace {
  position: relative;
  padding-left: var(--room-indent-3);
  color: var(--room-trace);
}
.log-line.trace::before {
  content: '';
  position: absolute;
  left: var(--room-dot-left);
  top: .9em;
  width: var(--room-dot);
  height: var(--room-dot);
  margin-top: calc(var(--room-dot) / -2);
  border-radius: 50%;
  background: var(--room-trace);
  pointer-events: none;

```

### 3.3 类名变更表

| # | 类名 | 状态 | 说明 |
|---|---|---|---|
| 1 | `.log-line.desc` | **新增样式** | 后端 `kind:'desc'` 已存在（commands.js:658），只是前端没样式 |

### 3.4 后端需配合的两件（不是我的活，但要说清）

1. **`p.roomNotes[roomId]` 目前全仓为空** —— ③ 要出来，后端得先按 77 §2.0.1 的口径落字段（单值、覆盖时不提示）。

   顺序由后端保证，**前端不排序**（排序放前端就是"两处各写一份"）。

## 四、与战斗文本的关系（区分说法，接 §一）

| | 战斗行 | 房间三段 |
|---|---|---|
| 左边缘 | **有竖杠**（`::before`，2–6.5px，朱色阶） | **没有竖杠**，只有空白 |
| 左内缩 | `--combat-pad: 15px`，**五档恒定** | 0 / 14 / 22px，**三段不等** |
| 变的是什么 | 杠的**宽、长、色**（连续递增） | 起笔的**位置**（离散三级）+ 有无朱点 |
| 量的是 | 这一下**多重** | 这句话**是谁说的** |
| 玩家的读法 | 看杠 | 看有没有杠 |

**两根通道互不占用**：战斗用"竖着的实体"，房间用"横着的空白"。
即使同一屏里同时出现战斗行和房间三段，左边一根实、一根虚，**不会看混**。

> 补充一条给 QA 的边界情况：`.log-line.quest`（3px 翠条）与 `.log-line.story`（3px 线）**保留原样**，
> 本方案不动它们。它们是既有类型通道，跟房间三段同属"缩进族"，但用的是 border 不是 ::before ——
> 视觉上仍是"一根竖线"，与房间的"纯空白"不冲突。

## 五、验收断言（可 grep、可脚本判）

| # | 断言 | 判据 |
|---|---|---|
| **R-V-1** | **三段字号一律 14px** | 三种 `.log-line.desc` / `.ambient` / `.trace` 的 `getComputedStyle().fontSize === '14px'`，且等于 `.log-line.plain` |
| **R-V-2** | **行高不跳** | 三者 `getBoundingClientRect().height` 与同字数 `.log-line.plain` 差值 ≤ 1px |
| **R-V-3** | **不用斜体 / 不加 opacity** | 三者 `fontStyle === 'normal'`；且 `fadeIn` 动画结束后 `opacity === '1'`（⚠️ `.log-line` 基类带 `animation: fadeIn .22s`，须等动画结束再量，别抓到中间态） |
| **R-V-4** | **缩进三级且单调** | `paddingLeft` 解析值：① 0 < ② 14 < ③ 22，三者互不相等 |
| **R-V-5** | **① 是最重的一档** | ① 字色 === `var(--ink)`，且其相对亮度严格高于 ② |
| **R-V-6** | **③ 是朱** | `.log-line.trace` 字色 === `var(--red)`，且**不是** `--gold` |
| **R-V-7** | **③ 有朱点且是实心圆** | `.log-line.trace::before` 的 `borderRadius` ≥ 50%、`width === height === 4px`、`background` 为纯色（非渐变） |
| **R-V-8** | **朱点不碰正文** | 朱点右边缘（`--room-dot-left + --room-dot` = 13px）< 正文起始（22px） |
| **R-V-9** | **房间三段没有竖杠** | 三者 `:before` 无 `width > 1px 且 height > 8px` 的竖条形态；且三者 `border-left-width === 0` |
| **R-V-10** | **去色可辨**（V-7 同口径） | 日志区加 `filter: grayscale(1)` 截图，①③② 三档**可逐一数出**：齐头最黑 / 退一格淡 / 退两格带点 |
| **R-V-11** | **②↔③ 不能只靠亮度** | 单独把两者的字色调成同一亮度后，仍能靠"有没有朱点"区分 —— 若不能，说明朱点没实现 |
| **R-V-12** | **顺序固定 ①→②→③** | 同一次 `look` 输出的三行，DOM 顺序为 `desc` → `ambient` → `trace` |
| **R-V-13** | **痕迹句 0 或 1 句、永远最后** | 单次 `look` 中 `.log-line.trace` 数量 ∈ {0, 1}；若存在，其 `data-li` 严格大于同批 `desc` 与 `ambient` |
| **R-V-14** | **动态句缺则不显示** | `room.ambient` 无对应天气/夜句时，**不出现** `.log-line.ambient`（不兜底、不复用别的天气的句） |
| **R-V-15** | **面板①不被误改** | `#room-desc` 的 `color` 仍为 `var(--ink-2)`（常驻底噪，与日志①刻意不同） |

## 六、命名与交付

| 类别 | 格式 | 实例 |
|---|---|---|
