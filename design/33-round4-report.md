## B43 · 为什么点「看看」不弹面板（先答这一条，因为主人问得最直接）

项目里**有两个 NPC 菜单入口**：

| 入口 | 怎么触发 | 动作表在哪 | 我上一轮改了吗 |
|---|---|---|---|
| 右侧**场景栏卡片** | 点场景栏里那个人 | 前端 `openNpcMenu()`（ui.js） | ✅ 改了（第一项 →「细看此人」） |
| **日志里的 NPC 名** | 点日志「这里有：范清、游侠。」里高亮的名字 | 后端 hl 动作表（commands.js） | ❌ **漏了** |

玩家习惯的是**后者**（日志里点名字）。那份表的第一项是：

```js
const actions = [
  { label: '看看', cmd: 'look ' + k },   // ← 只是打一段文字
  …
];
```

所以「点『看看』却不弹面板」——**它本来就不是开面板的按钮**。上一轮我只改了半边入口。

**修法**：
- 后端 hl 第一项 → `{ label: '细看此人', act: 'profile', uid: 真实例id, cmd: 'look ' + k }`
  （`cmd` 留作兜底：老客户端 / 不认 `act` 时退回 look）
- 前端 `openInteractMenu` 支持 `act`（并把 `act/uid` 原样透传给回调，`choices()` 本来就会透传整个 item）
- 抽出 `runInteractAct()` 并挂到 `WXUI` 导出 —— 日志里的 `.hl` 按钮是 `innerHTML` 造的，
  假 DOM 里拿不到 `paintLog` 绑的 onclick，不挂出来就只能测「后端给了什么」而测不到「前端认不认」
- 文本流另给一项「**打量**」，两样都在，谁也不会丢

**为什么 uid 必须是实例 id 而不是名字**：主人撞到的「没有这个人」正是这个坑的另一面 ——
日志里那条路只会给**一段文本**（「老郎中」），而后端按名字找。所以：

```js
{ label: '细看此人', act: 'profile', uid: one && one.id, … }   // 一对一
```
并加了**端到端断言**（P-6）：拿 hl 给的 uid 去 `npcProfileOf`，必须查到**同一个人**——
uid 错一位立刻暴露，不用等到玩家点了才知道。

## B41 · 送礼面板（物品 + 金钱 + 已经送多少）

主人要三件事，逐条落地：

1. **「弹出玩家身上有什么物品（包括金钱）」** —— 面板分两区：行囊物品 / 银钱档位（50/100/300/800 + 自填）。
   原来「送东西」和「给银钱」是**两个入口**、要来回点。
2. **「点击选择赠送」** —— 点物品即送（原有），点金额即给（新增在同一下面板里）。
3. **「已经送多少」** —— 面板顶部一行：`此前已送 3 次，其中银钱共 200 文（馒头×2）`；
   每件物品行内标 `已送 N 次`；详情面板的「往来」行、`view().npcs[].gifts` 都用**同一份数据**。

**顺带修好一个半坏的按钮**：前端「给 他 银钱」发的是

```js
doCmd('give_money ' + v + ' to ' + n.name)   // ← 钱数在前
```
而后端签名是 `give_money <人名> <钱数>`（`args[0]` 当人名去 fuzzyFind）→
实发 `give_money 100 to 范清`，后端拿「100」当人名 → **「这里没有「100」。」**
（实测确认过。）修两处：前端按签名发；后端**两种顺序都认**（老档/教程文本/mod 里都还有老写法）：

```js
const toks = args.filter(t => !/^(to|给|送给?)$/i.test(t));
for (const t of toks) { /* 哪个 token 能解析成数字，哪个就是钱数 */ }
```

**记账**（`noteGift()`，唯一入口）：`npc.pstate.gifts = { count, money, items:{名称:件数} }`。
`pstate` 本来就随档走（deserialize 是**补齐式**恢复，不会把 gifts 冲掉），并加了随档断言（G-4）。

**还改掉一处「面板直接挡掉功能」**：原 `giveNpc` 在背包为空时 `return toast('行囊空空')` ——
连「给点银子」都做不到（钱在钱袋里，不在背包）。现在背包空也开面板，物品区显示「行囊空空」。

## B44 · 顺手挖出的引擎崩溃：`ask` 一碰「映射写法」就炸

补回春堂 NPC 时，我给陈济仁写了 `ask`：

```json
"ask": { "医术": "医术没什么玄的…", "药材": "要好的药材往北边山里找…" }
```

一执行 `ask 陈济仁 about 医术` → **抛异常**：

```
TypeError: Cannot read properties of undefined (reading 'includes')
  at … if (topic.includes(a.topic) || a.topic.includes(topic) …
```

**根因**：引擎里那份归一化只处理了两种写法 ——

```js
const askList = Array.isArray(def.ask) ? def.ask : [def.ask];
```

- `[{topic, answer}]`（数组）✔
- `{topic, answer}`（单条对象）✔
- **`{ "话题": "答案" }`（映射对象）✘** ← **数据里的主流写法**（示例 mod 的太虚居士等）

映射对象被塞进 `[rawAsk]` 后，`a.topic` 是 `undefined` → `a.topic.includes()` 直接抛异常，
**整条 ask 指令挂掉**（玩家看到的不是「他答不上来」）。

**为什么一直没人报**：基础数据里那 18 个带 `ask` 的 NPC 用的都是**数组**写法；
用映射写法的都在 mod / 后来补的数据里。而 `exec` 原来**不兜异常**，
服务端 `handleApi` 的 try/catch 把它兜成 500 —— 玩家看到的是「网络错误」，
排查的人拿到的是「没线索」。

**修法两条**：
1. `ask` 的 askList **三种写法全归一化**（映射对象展开成 `[{topic, answer|…}]`，值允许是对象）
2. **`engine.exec` 加通用防线**：一条指令抛异常 → 记 `console.error` 栈 +
   给玩家一行明确的「（「X」这道指令出了岔子，已经记下来了。）」。
   ⚠️ 刻意**不静默** —— 静默正是本项目最忌的「不报错就不生效」。

**断言**（`smoke-round4` §Q）：数组写法（岳不群/紫霞神功）与映射写法（徐半仙/算命）
**各挑一个真 NPC、真 exec、断言答的是那句答案**（不是走兜底编一句）。
另外 Q-4 造一条必然抛异常的指令，断言玩家拿到的是**明确回执**而不是脚本/请求炸掉。
